# 퀴즈나라 작업 안내

이 폴더는 큐플레이 느낌의 일러스트형 SD 아바타 퀴즈 게임이다. 사용자 요청은 퀴즈 게임에만 적용한다. 저장소의 좀비 게임 원본과 배포본은 수정하지 않는다. 원격 저장소에서 좀비 게임은 `클로드/`에 있으며, 학교의 이전 체크아웃에서는 저장소 루트 `index.html`과 `배포용/index.html`에 있다.

먼저 `개발환경.md`와 변경할 부분의 `디자인기준.md`를 확인한다. 사용자가 보낸 아바타 스크린샷을 최소 미술 품질로 유지한다. 머리·피부·눈의 겹침, 감은 눈, 상의·하의의 분리와 여러 색, 남녀 아바타, 항상 살아 있는 움직임을 실제 화면에서 확인한다. 그램·크롬북 노트북 화면을 우선한다.

## 상시 최우선 지침: 아이들이 좋아하는 맵·디자인·아바타

사용자 고정 요청(2026-10-01): **“아이들이 좋아하는 맵과 디자인, 아바타 디자인에 공을 제일 많이 들여야돼. 고정지침에 추가해서 항상 기억해줘.”** 이후 모든 퀴즈나라 작업에서 어린이가 탐험하고 꾸미고 싶어 하는 맵, 화면 디자인, 아바타의 미술 완성도에 가장 많은 공을 들인다. 기능만 연결된 임시 화면·단색 공간·기호를 늘어놓은 맵을 완성품으로 취급하지 않는다. 직접 사용할 수 있는 사용자 제공 에셋을 먼저 검토·재사용하고, 부족한 부분과 참고 화면에서 분리되지 않은 부분을 제작한다.

## 최신 작업 우선순위: 학생 PC 화면과 제공 에셋

사용자 최우선 요청(2026-10-01): **“아바타 자연스럽게 연결하고, 아바타가 진짜 살아있는 듯한 모션으로 만드는 것이 제일 우선.”** 몸·목·어깨·소매·허리·신발의 연결을 실제 착용과 연속 모션에서 먼저 완성한다. 민소매 팔 전체를 손 움직임으로 회전시키거나 옷의 회색 목 구멍을 피부로 오인하지 않는다. 남자 머리는 작은 썸네일에서도 실루엣이 구분되어야 한다. 작은 버튼·상품명·가격·안내에는 진한 읽기 글꼴을 사용하고 두꺼운 윤곽선·겹친 그림자를 적용하지 않는다. 큰 로고·놀이 간판의 장식 글자는 유지할 수 있다.

사용자 착용 검수 정정(2026-10-01): 어두운 피부 남자·꽃 민소매·청바지·운동화의 걷기 시안을 **신발 분리와 팔 가림 때문에 거부했다.** 알파 접촉 검사 통과를 자연스러움의 증거로 사용하지 않는다. 겹쳐진 신발 한 쌍을 중앙 직선으로 잘라 움직이지 않는다. 각 신발의 온전한 윤곽과 발목·바짓단의 공통 축을 확인하고, 어깨는 옷 뒤·드러난 팔과 손은 적절한 앞 레이어로 구성한다. 실제 상점 크기 및 연속 걷기·점프·착지에서 직접 검수한 후 완료를 보고한다.

사용자 배포 요청(2026-10-01): Netlify 수동 배포는 **이 폴더 안의 `배포용/` 전체**로 한다. `index.html`만 올리지 않는다. 런타임 수정 후 필요한 원화 변경을 `node tools/build-avatar-file-data.cjs`로 반영하고, `node tools/build-deployment.cjs`로 전체 배포본을 다시 만든다. 완료 전 `node tools/build-deployment.cjs --check`와 실제 배포 폴더 경로의 브라우저 검사를 수행한다. 저장소 루트·좀비 게임의 `배포용`과 혼동하지 않는다.

사용자 교사 운영 요청(2026-10-01): 상단은 **내 퀴즈·수업 관리·학생 관리**와 **새 퀴즈 만들기**로 운영한다. 내 퀴즈는 문제 보관·수정·새 수업/혼자 풀기 열기, 수업 관리는 이미 배포한 활동의 입장·진행·공유·결과, 학생 관리는 계정·비밀번호·골드다. 별도 퀴즈룸·기존 OX·패션왕을 일상 교사 탭에 다시 추가하지 않는다. 기존 저장 데이터를 삭제하지 않으며 OX 문항은 공통 문제 작성기에 포함한다.

사용자 최종 지시(2026-10-01): **“모바일은 신경 안 써도 돼.” “선생님 화면은 사실 신경 안 써도 되긴 하는데, 애들한테 보일 때는 내가 보내준 에셋들을 많이 활용해서 풍성하게 보여야 돼. 가독성은 떨어지지 않되.”** PC·노트북의 실제 학생 화면을 디자인·검수의 기준으로 한다. 모바일 대응·추가 모바일 검수에 시간을 쓰지 않는다. 교사 화면은 문제 작성·수업 진행의 편리함과 읽기·입력 기능을 우선하고, 장식 확장에 미술 작업을 집중하지 않는다. 이전 문서의 모바일 작업 지침보다 이 지시를 우선한다.

학생의 로비·상점·아바타·탐험 맵·문제창·결과 화면에는 제공 자료를 적극 활용한다. 제작 전에 [전체 소재 보관함](assets/library/index.html)에서 실제 쓸 자료를 고르고 선택한 파일·사용 부위를 기록한다. 화풍·시점·광원·크기를 맞춰 숲속 마을의 장소를 구성한다. 자료를 저장하거나 녹색 버튼으로 바꾼 사실만으로 에셋 활용·풍성한 디자인을 완료했다고 보고하지 않는다. 배경·건물·식생·생활 소품·장식이 연결된 풍경을 만들고, 현재 예쁜 SD 뼈대와 비율·자연스러운 의상 착용을 유지한다. 질문·답안·학생 이름·점수·버튼에는 밝고 차분한 읽기 공간을 확보한다. 구체적인 제작 순서와 완료 기준은 [디자인기준.md](디자인기준.md#제공-에셋으로-학생-화면을-만드는-순서)를 따른다.

- 기존 세밀한 얼굴·헤어·상의·하의·신발·펫·천사 이펙트와 숨쉬기·눈 깜박임·날갯짓을 보존한다. 걷기·점프·앉기를 추가해도 세밀한 원화와 의상 조합을 임시 아바타로 바꾸지 않는다.
- 사용자 제공 숲·마을·계곡·Kingshot·도시·숲속 정원 참고 이미지(2026-10-01)를 맵의 최소 미술 목표로 삼는다. 건물의 원근과 지붕·벽·창문·재질, 나무의 잎 덩어리와 수종 차이, 지형의 높낮이·물·빛·그림자를 함께 다듬는다. 단순 도형이나 반복 장식을 늘린 상태를 이 기준에 도달했다고 보고하지 않는다. 목표와 실제 화면의 달성 수준은 구분하고, 사용자에게 보여 줄 기본 플레이 화면으로 판단한다.
- 메인 로비는 숲과 색칠한 나무 간판, 퀴즈나라 로고와 **3학년 3반**을 유지한다. 게임 방식별 세계와 장식은 구분하고 문제·입력·이름·팀 색을 읽기 쉽게 배치한다.
- 최신 공통 UI 기준(2026-10-01)은 사용자 최종 선택인 **숲속 마을**이다. `interface.zip`의 나무·양피지 UI와 햇살 든 마법 숲을 기본 자료로 삼으며 [기본 인터페이스 보관함](assets/interface-library/README.md)에 원본을 보관한다. 학생의 로그인·로비·상점·옷장·모든 게임·결과 화면에 따뜻한 나무·크림색 종이·이끼 녹색·금색 테두리와 옥빛 포인트를 적용한다. 교사 화면은 같은 기본 재질·색상을 사용하되 추가 장식보다 입력·저장·수업 진행을 우선한다. 학생 화면의 나무 간판·진열대·잎·꽃은 풍성하게 다듬고 문제·본문·입력란은 읽기 쉽게 유지한다. 기존 Royal Match 참고의 입체감과 버튼 두께는 품질 참고로 유지하되 밝은 파란 플라스틱이 전체 화면을 지배하지 않게 한다. 중요한 제목은 둥글고 굵은 한글과 윤곽선, 수치는 크림색 판, 진행은 읽기 쉬운 캡슐로 표현한다. 현재 SD 아바타 뼈대·비율과 방식별 맵 세계는 유지한다.
- 맵 변경은 각 방식의 실제 학생 시작 위치와 기본 플레이 시점에서 확인한다. 출발·진행·사물 접근·문제 열기·정답 뒤 이동·종료 화면을 저장하고 직접 열어 미술을 확인한다. 별도 조망 화면은 이 검수를 대체하지 못한다.
- 화면에 그린 울타리·닫힌 관문·장애물의 실제 충돌, 길 찾기와 모든 문제의 접근 가능성을 확인한다. 점프·대각 이동으로 닫힌 순서 관문이나 맵 경계를 우회하지 못해야 한다. 실제 키보드와 화면 조작 버튼도 사용한다.
- 자동 검사 통과나 코드에 이름이 있다는 사실만으로 미술·플레이 완료를 보고하지 않는다. 구현 위치, 실행 검사, 직접 확인한 화면을 구분하고 필수 미확인 항목은 남은 작업으로 보고한다.

## 풍성한 화면을 만드는 미술 완료 기준

사용자 메타버스 방향 확정(2026-10-01): **로그인하면 숲속 마을에 모이고, 건물로 들어가 교실·퀴즈·상점을 이용한다. 로그인하면 언제든 우리 반 친구와 만난다. 교실 행동은 친구에게 다가가 손 흔들기·인사·감정 표현을 먼저 만든다.** 이는 향후 공간 제작의 기본 사용자 흐름이다. 현재 메뉴·퀴즈 맵이 이미 상시 다중 접속 마을로 바뀌었다고 보고하지 않는다. 향후 공유 공간에서는 위치·방향·행동을 서로 보이게 동기화하되 퀴즈 답·점수·진도는 학생별로 유지한다. 손 흔들기에는 소매·팔·손이 연결된 포즈를 별도로 마련한다.

사용자 향후 방향(2026-10-01): 학생들이 자기 아바타로 이동하고 책상에 앉는 메타버스 교실도 만들 예정이다. 현재는 아바타·의상·모션의 공통 구조를 먼저 완성하며, 메타버스 교실 자체를 현재 구현한 것으로 보고하지 않는다. 모션은 위치 이동과 분리하여 로비·상점·맵·라운드·향후 의자에도 재사용한다. 정지→걷기→정지, 점프→착지, 앉기→일어서기가 연결되고 옷·피부·장식이 부위에서 떨어지지 않아야 한다. 뒷모습·방향 전환 전용 원화나 여러 사용자 동기화는 향후 해당 공간 제작 시 별도로 준비한다.

사용자 다음 공간 요청(2026-10-01): **“아바타가 너무 클 필요는 없어”**, **“접속하면 거기서 애들이 모이는 … 2d 공간이지만 다양하게 오르거나 내리거나 할 수 있는 호기심을 자극하는 상상의 나라”**. 로그인 후 우리 반 친구가 언제든 모이는 숲속 마을을 다음 단계로 만든다. 마을 아바타는 전체 풍경·다른 친구·탐험 동선을 읽을 수 있는 작은 크기로 배치한다. 높낮이가 있는 숲길, 나무 위 집, 계단·다리, 폭포와 동굴, 비밀길 등 이동하고 발견할 수 있는 지형을 설계한다. 교실·퀴즈·상점은 들어갈 수 있는 건물로 연결한다. 장식뿐 아니라 실제 이동·오르내리기·발견으로 반응하게 하며, 처음 친구에게 다가가 인사·손 흔들기·감정 표현부터 구현한다. 현재 수정본을 마무리하면서 이 방향을 보존하며, 숲속 마을 공간이나 실시간 친구 동기화를 이미 구현한 것으로 보고하지 않는다.

사용자 추가 요청(2026-10-01): Barcelona Match-3 해변 마을·입체 정글 기지·여러 지형이 모인 섬 참고처럼 **풍성한 장면 구성**을 기본으로 한다. 자세한 제작·검수 기준은 [디자인기준.md의 풍경 구성 기준](./디자인기준.md#풍경-구성-기준)에 있다.

- 제작 전에 그 화면의 주인공 장소, 빛 방향, 앞·중간·뒤 풍경, 큰 볼거리와 주변 소품을 정한다. 색만 바꾸거나 장식 수만 늘리는 방식으로 미술 요구를 처리하지 않는다.
- 전경의 나무·풀·바위, 중경의 길·건물·체험 사물, 후경의 숲·절벽·물·하늘이 겹쳐 깊이를 만든다. 나무는 둥근 잎 덩어리의 명암, 가지와 뿌리, 주변 바닥에 닿는 그림자를 갖춘다.
- 각 구역은 고유한 큰 볼거리와 의미 있는 소품 무리를 갖춘다. 건물 옆의 간판·도구·화단, 개울 옆의 돌·수초·다리처럼 장소의 이야기가 보이게 배치한다. 넓은 단색 바닥과 같은 나무 복제가 지배하는 장면은 미술 미완성이다.
- 단순 도형은 경로·충돌·배치 초안으로만 사용한다. 최종 화면에는 세밀한 직접 제작 원화 또는 충분히 다듬은 재질·입체 자산을 쓰고, 기존 고품질 아바타와 소품을 보존한다.
- **대표 화면 한 장을 먼저 완성하고 실제 기본 시점으로 참고 이미지와 비교한다.** 입체감·깊이·소재 표현·장면 밀도·색감이 부족하면 해당 화면을 다시 다듬은 뒤 다른 화면으로 확장한다. 조망 캡처나 파일에 자산이 있다는 사실로 통과시키지 않는다.
- 메뉴·문제·이동 공간은 읽고 사용할 수 있게 확보한다. 모든 빈 공간에 소품을 채우지 않으며, UI 뒤 풍경은 시선을 분산시키지 않게 한다. 화면 가장자리·구석·경로 밖도 완성된 풍경으로 연결한다.
- 미술 검수 기록에는 같은 크기의 변경 전·후 기본 화면, 참고와 대조한 입체감·깊이·재질·밀도 항목, 남은 부족함을 적는다. 사용자 참고 최소 수준을 달성하지 못했으면 달성했다고 보고하지 않는다. 기능 검사 통과는 미술 완료 근거가 아니다.

## 귀엽고 풍성한 아바타의 고정 미술 기준

사용자 최종 정정(2026-10-01): **“방금 보낸 이미지랑 똑같이하고, 도트디자인 버리고, 저 캐릭터가 입을 옷을 잘 디자인해봐.”** 부드러운 일러스트형 SD 캐릭터를 최종 스타일로 사용한다. 이전의 도트·계단식 외곽·픽셀 고정 렌더 지침을 폐기하고, 매끄러운 곡선·반투명 가장자리·연속적인 명암과 자연스러운 모션을 유지한다. 얼굴·헤어·의상의 풍성함과 원래 꾸미기·구매 기능은 보존한다.

사용자 추가 요청(2026-10-01): 꽃·리본·모자·레이스와 여러 헤어가 있는 SD 캐릭터 의상 시트처럼 귀엽고 풍성한 느낌을 기본으로 한다. 세부 기준은 [디자인기준.md의 SD 아바타 기준](./디자인기준.md#귀엽고-풍성한-sd-아바타-기준)에 있다.

- 큰 반짝이는 눈, 둥근 얼굴과 볼터치, 작고 정돈된 몸의 비율로 귀여움을 만든다. 눈 크기나 머리 크기만 늘려 미술 개선을 대신하지 않는다.
- 헤어에는 둥근 볼륨·큰 머리 다발·층별 명암·광택을 주며, 단발·긴 머리·곱슬·묶은 머리의 실루엣과 개성을 구분한다. 단색 덩어리나 가는 선 몇 개로 머리카락을 끝내지 않는다.
- 의상마다 색과 소재, 소매·카라·허리·옷자락·주름, 단추·리본·꽃·자수·레이스 같은 핵심 디테일을 설계한다. 머리장식·신발·펫까지 얼굴과 같은 수준으로 다듬고 부위별 입체 명암을 통일한다.
- 의상은 제공 소재의 적합한 부분을 활용하고 따로 조합해도 어색하지 않게 준비한다. 큰 실루엣과 작은 포인트의 균형을 잡아 피부·표정·손·발을 알아볼 수 있게 한다. 완성 캐릭터 JPEG 전체를 부위별 착용 레이어 대신 붙이지 않는다.
- 대표 전신 한 명을 먼저 완성해 실제 로비·상점 크기와 작은 맵 크기에서 참고와 비교한다. 단순 도형 몸통·신발, 평면 옷, 가려진 표정이 남아 있으면 미술 미완성이다. 이후 다양한 성별·피부·머리색·의상 조합과 걷기·점프·앉기를 검수한다.
- 기존 원화·구매·부위별 착용·색상 변경과 숨쉬기·눈 깜박임·펫·천사 모션을 보존한다. 지침 추가만으로 현재 모든 아바타가 새 참고 수준에 도달했다고 보고하지 않는다.

사용자 추가 요청(2026-10-01): **“아바타 뼈대는 예뻐. 이제 얼굴, 머리, 옷들, 펫들, 장식들을 잘 정리하면 될 것 같아.”** 현재 SD 뼈대와 비율을 유지한다. 부위별 원본·상품 ID·색상·정렬점을 [아바타 라이브러리](assets/아바타-라이브러리.md) 기준으로 관리하고, 새 장식은 실제 머리·옷에 착용한 상태로 검수한다. 목·소매·허리의 틈과 감은 눈의 사각형 패치·중복 속눈썹은 미완성으로 판단한다.

사용자 추가 요청(2026-10-01): 농장·제작 건물·상점·사찰·야외 소품 시트 6장을 **맵 제작의 기본 소재**로 보관한다. [맵 소재 라이브러리](assets/map-library/README.md)의 원본 확보 상태와 분류를 확인한 뒤 사용한다. 채팅 미리보기와 파일명만으로 원본 이미지를 저장했다고 보고하지 않는다. 원본은 그대로 보존하고 셀·바닥 앵커·그리기 순서·충돌 영역을 별도로 관리한다. 도트 맵 소품 참고가 매끄러운 SD 아바타 스타일을 되돌리는 근거가 되지 않는다.

사용자 ZIP 자료는 [전체 소재 보관함](assets/library/index.html)에서 검색한다. 맵·풀·건물·인터페이스·버튼·아이콘·테두리 원본 ZIP과 이미지, 원래 이름·별칭·해시·실제 그림 확인 상태를 저장소에 함께 보관한다. 같은 이미지는 중복 파일명을 묶고, 많은 다운로드보다 현재 숲속 마을의 재질·시점·조합에 맞는 자료를 선택한다. 미확인 이미지를 시각 검수 완료로 표시하지 않는다. 불투명 JPEG나 체커무늬 화면은 투명 PNG가 아니다. 저장 완료, 소품 준비, 게임에 실제 적용·검수 완료를 구분하며, 기존 SD 원화와 현재 기본 화면을 참고 JPG로 대체하지 않는다.

## 일반 퀴즈의 고정 규칙

교사 흐름은 **게임 방식 선택 → 문제 작성 → 수업 설정**이다. 일반 퀴즈는 다음 다섯 방식을 지원하며 같은 저장 문제 묶음을 실시간 수업과 나중에 혼자 풀기에 재사용한다. 학생별 정답·점수·진도는 저장하고 재접속 시 이어 간다.

- `sequence` 순서풀이: 울타리로 둘러싼 정해진 숲길에 꿀단지 관문을 차례로 둔다. 해당 학생이 정답을 맞혀야 자기 관문이 열리고 다음 구간으로 이동한다. 오답이나 다른 학생의 정답으로 열리지 않는다.
- `free` 자유풀이: 성·용암·사막·숲 구역이 있는 큰 2D 맵에서 원하는 순서로 탐험한다. NPC·사물 가까이 다가가야 문제를 열며 완료는 학생마다 독립적이다.
- `round` 라운드전: 시작하면 각 아바타가 자기 체크무늬 소풍 돗자리 한 장 위로 자동으로 걸어 들어간다. 모두 같은 문제를 제한 시간 안에 풀고 정답 공개 뒤 개인 점수와 마지막 순위를 확인한다.
- `team` 팀전: 교사가 팀 수와 무작위 균등 배정 또는 학생 선택을 정한다. 무작위 배정은 팀 간 인원 차이가 최대 한 명이어야 한다. 학생은 팀 색을 달고 울타리 안 가을 퀴즈 경기장에서 각자 풀며 개인 점수를 팀별로 합산한다. 팀원이 맞혀도 자기 문제는 완료되지 않는다.
- `coop` 협동전: 학생마다 독립적으로 풀고 반 전체의 맞힌 문제 수를 합산한다. 제한 시간 안에 반 공동 목표에 도달하면 함께 성공한다. 같은 학생의 같은 정답은 한 번만 합산한다.

일반 문항 유형은 `choice` 객관식, `short` 주관식(짧은 정답), `match` 선 잇기, `order` 순서 맞추기 네 가지다. 선 잇기는 학생이 짝을 고르면 실제 연결선을 표시하고, 순서 맞추기는 교사가 입력한 올바른 순서로 채점한다. 서술형은 추가하지 않는다. O/X 정답 문항도 공통 문제 작성기에서 운영하며 기존 저장 자료를 보존한다. 이전 OX룸은 일상 교사 탭에 다시 추가하지 않는다. 메인 로비의 움직임 연습에서 걷기·점프·앉기를 익힐 수 있게 한다.

개발 기준은 이 `퀴즈나라/` 폴더 하나다. 실행 파일 목록은 `tools/deployment-files.cjs`이며, 수정 후 `node tools/check-source.cjs`를 실행한다. 배포는 `node tools/build-deployment.cjs`로 만든 이 폴더 안의 `배포용/` 전체로 한다. 수동 배포와 GitHub 자동 배포는 같은 실행 파일 목록을 사용한다. 원격 최신 변경을 먼저 확인하고 퀴즈 경로만 커밋한다.

레이아웃·글꼴 변경은 `tools/verify-layout.cjs`, 음향 변경은 `tools/verify-audio.cjs`, 게임 규칙·결제 변경은 `tools/verify-game.cjs`와 `tools/verify-economy.cjs` 등 해당 검사를 실행한다. `?demo=1` 체험 모드로 실제 수업 데이터에 쓰지 않으며, 자동 검사와 실제 화면을 함께 확인한다. 재생성 가능한 `검증/` 출력은 GitHub에 올리지 않는다.

기존 검증 도구가 새 다섯 방식까지 실행했다고 가정하지 않는다. `개발환경.md`의 방식별 검수 항목을 실제로 확인하고, 기존 OX·가로세로 검사 결과와 새 일반 퀴즈 결과를 구분한다.

GitHub 업로드는 채팅의 기기 간 동기화나 클라우드 실행을 뜻하지 않는다. 연결된 기기와 실제 이전·푸시 결과를 확인하고 완료를 보고한다.
