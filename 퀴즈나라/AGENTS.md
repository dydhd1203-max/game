## 아바타·옷·머리·모자

- 기준 캐릭터는 `assets/avatar-reference-candidates/body-study-2026-10-04.png`(사용자 지정). 몸·기본복 v2는 이 그림에서 만들었다.
- 새 옷 그림은 **그림 틀 + ChatGPT**로 만들고 파이프라인이 기준 몸에 맞춰 잘라 넣는다. **옷 원화는 진한 피부 그림틀**(상품 `"base": "dark"`, 2026-10-16)로 받고, 받은 원화는 `tools/garment/receive.py`로 한 번에 저장·자르기·확인판·게임 검사를 한다(`아바타-제작기준.md` '진한 피부 그림틀·긴팔'). Higgsfield는 쓰지 않는다. 반팔·반바지·신발부터 했고, 긴팔·긴바지·치마·원피스·부츠는 5단계에서 종류별 동작을 만든 뒤 요청한다.
- ChatGPT 옷 색이 상점 고정색과 비슷하면 경고만 남기고, 눈에 띄게 다르면 다시 요청한다.
- 기본 옷은 무료 시작 상품이다(남 top:tee:5·bottom:shorts:9, 여 top:tee:3·bottom:shorts:5, 신발 shoes:sneaker:8). 남자 새 계정 기본 하의는 5단계에서 반바지(shorts:9)로 바꾸고, 저장된 학생 옷은 바꾸지 않는다. 학생 화면 '구두' 뒷발 테두리 결함은 5단계 때 고친다.
- 새 옷은 유령 선을 지운 팔·목 그림(`sd-foundation-ref-arms-clean.png`, `-neck-clean.png`)을 쓴다(승인). 기본 옷은 3단계 끝에 비교해 보여 준 뒤 바꾼다.
- 머리: 기존 머리 그림 24개를 유지하고 목 자르기·사이 피부색을 자동 규칙으로 맞춘다. 머리카락은 자연스럽게, 머리–목 연결은 `아바타-제작기준.md` 규칙을 지킨다. **얼굴 크기는 머리 모양과 상관없이 같다**(기본 머리 크기, 아주 넓은 머리만 최대 약 5% 줄임). 옆얼굴 위치 맞춤은 끄고, 840px에서만 보이는 목 이음 흐린 점선은 그대로 둔다(2026-10-17).
- 머리·모자·얼굴·얼굴 장식은 조합마다 그리지 않고 **하나씩 원화로 받아 게임이 맞춘다**.
- 모자는 원화로 만들고 머리 모양마다 따로 그리지 않는다. 푹 쓰는 모자(테두리 위 머리 숨김)·얹는 장식(머리 윗선에 앉힘)으로 나눈다. 그리는 순서는 뒷머리 → 모자 뒤층 → 얼굴 → 머리(모자 선 위 잘림) → 모자 앞층이다. 안경·얼굴 장식·귀걸이·목걸이·등 장식도 같은 방식으로 모자 다음에 확인한다. **헤드폰은 뺐다**(2026-10-16): 귀 기준점을 귀걸이와 함께 만든 뒤 다시 요청하고, 학생 화면 상점에서는 5단계 때 판매만 내린다(저장 데이터는 지우지 않음).
- 바닥 앉기(양반다리)는 원화로 그린 '앉은 기준 몸' 위에 옷 층을 겹친다. 엉덩이가 바닥에 닿고 무릎이 바깥으로 벌어지며 정강이가 몸 앞에서 교차, 신발은 신긴 채, 손은 무릎 위, 옆모습은 무릎 꿇기와 구분. 120·280px에서 확인한다. 검사는 `python3 tools/verify-seated-art.py`, `python3 tools/verify-seated-items.py`, `node tools/verify-seated-runtime.cjs`이고 280px 비교판을 직접 본 뒤에만 '맞다'고 보고한다.
- 승인된 모션: 앞모습 고개 인사에서 얼굴이 앞머리 밑으로 숙여짐, 사다리는 손발이 조금 미끄러져도 차분한 박자(초당 약 3번), 손 흔들기·기뻐하기의 펼친 손.

## 원화 요청

- **원본 그림에 없는 모양**(앞으로 짧아지는 모습, 돌아간 신발, 짚는 손 등)과 **코드로 맞추기 어려운 머리·모자**는 수치 조정 전에 바로 원화를 요청한다. 그림 검수에서 두 번 실패하면 수치 조정을 멈춘다. 원화가 더 빠르고 좋으면 작업자가 먼저 말한다.
- 요청은 필요한 것을 모아 **압축파일 하나**로 드린다: 첨부 그림(쓰임이 드러나는 이름, 예 `09-여자-조끼.webp`) + `00-요청방법.txt`. 30MB를 넘으면 15장 이하씩 나눈다.
- 요청 전 점검(2026-10-16 효율 점검): ① 참고 그림을 먼저 보고 설명을 쓴다(얼굴 페인트를 줄무늬로 썼는데 상점 그림은 점이었음). ② 그리는 자리가 자르는 도구의 구역(얼굴 장식은 그림틀 머리 칸) 안인지 본다(마스크를 '턱 끝까지'로 요청해 목 칸으로 내려와 다시 요청함). ③ 자르기 도구가 못 잡을 것이 보이면(그림틀에 있는 색 등) 원화가 오기 전에 도구부터 고친다. ④ 묶음을 보낼 때 대화에서도 '장식마다 그림틀+참고 그림 첨부 → 요청 문장 붙여 넣기 → 결과만 이 이름으로 보내기'를 짧게 알린다(요청 묶음이 그대로 돌아온 일).
- 요청에 필요한 말(그림틀에서 새로 그리기, 원본 그대로 받기, 파일 이름, 실패 시 다시 요청할 문장)은 **모두 요청 파일에 써 넣는다**. 사용자에게 따로 전해 달라고 부탁하지 않는다. 공통 문장은 `assets/garment-template/프롬프트.md` '묶음 요청 공통 안내', 지난 요청문은 `assets/garment-template/requests/`.

## 게임·화면

- 목표는 넥슨 **큐플레이**의 진행·화면 구성·연출이다. 원작 로고·그림·음원은 복사하지 않는다. 흐름: 로그인 → 숲속 마을(`SCREENS.village`) → 위쪽 띠 **QUIZQUIZ** → 퀴즈 로비 → 대기실 → 무대 퀴즈 / 서바이벌 OX → 결과. 학생도 방을 만들 수 있다.
- **UI는 큐플레이의 파란 느낌**(코발트 창, 하늘색 광택 테두리, 남색 제목 띠·아이템 칸, 광택 파랑·주황 알약 버튼, 아래 채팅·버튼 바, 참고 `디자인기준/21~25-큐플레이UI-*.png`)으로 바꾼다. 맵 그림은 그대로 두고 UI 층만 바꾼다. 사탕 큰 문구, 살아 있는 움직임, 꾸민 아바타, 읽기 쉬운 글꼴은 살린다. 6단계 전까지 지금 화면은 그대로다.
- 서바이벌 OX는 한 화면짜리 경기장(매달린 문제판, 디지털 집계판, 둥근 O·X 웅덩이, 덤불 테두리)이다. 문제 은행은 3학년 2학기 수학·사회·과학 객관식·단답형(OX는 OX), 단원별로 많이 저장하고 고른 수만큼 무작위 출제, 학년·학기 칸은 3학년 2학기만 연다, 그림 문제는 작은 그림 + 돋보기.
- 손으로 그린 느낌(굵은 외곽선, 평평한 채색, `steps()` 애니메이션). 모든 맵·로비·대기실은 작은 움직임이 늘 있는 살아 있는 화면이고, 동작 줄이기·숨긴 탭·화면 밖에서는 멈추며 30명 성능 예산을 지킨다.
- 글꼴: 본문 나눔스퀘어라운드, 버튼·작은 제목 ExtraBold(`QuizDisplay`), 큰 문구 `candy-title.js` 사탕 글씨(한글 주아·영어 Fredoka), '퀴즈'가 들어간 큰 문구는 **QUIZ**(QUIZ만 하늘색). 6단계에서 큐플레이식 글꼴로 바꾼다. 버튼은 `qplay-buttons.css`(기본 이끼, 주요 금색, 보조 나무, 선택 옥빛, 뒤로·닫기·나가기 버섯 빨강).
- 맵 그래픽은 사용자가 제공한 에셋만 골라 배치한다. 새 AI 맵 그림이나 임의 SVG 지형으로 대신하지 않고, 부족하면 요청한다. 버튼·창·O/X 구역 같은 UI 층은 직접 그린다.
- 공용 맵 아바타: 입력 120px × 카메라 0.76, 걷기 337.5px/s, 같은 방향키 두 번이면 506.25px/s 달리기, 통행 반경 7, 나무 뒤에서는 겹친 신체 부분만 불투명도 0.38. 출입구는 닿으면 이동, 사다리 ↑↓, C 앉기, E 칠판·상호작용, M 지도, 1·2·3 손 흔들기·인사·신나!(맵 아래 동작 버튼줄은 없음). 교실은 30자리와 칠판(E → QUIZQUIZ 로비), 운동장 벤치는 배경 그림이다.
- **운영자**: 아이디 **선생님**과 정해진 비밀번호로 학생과 같은 로그인 창에서 들어가고, 위쪽 띠 '운영자' 탭에서만 운영자 화면(내 퀴즈·새 퀴즈 만들기·학생 관리·QUIZQUIZ 방)을 연다. 비밀번호는 해시(`window.ADMIN_PIN_HASH`)로만 두고 문서에 적지 않는다. 체험 주소 `?demo=1&role=admin`. 운영자 화면은 작성·관리가 편하면 된다. 기존 저장 데이터는 지우지 않는다.
- 퀴즈 묶음(`quiz/bank`) 문항은 `choice`·`short`·`match`·`order`와 O/X이고 QUIZQUIZ 방에는 `match`·`order`가 나오지 않는다. 저장 형식은 [개발환경](개발환경.md).
- 상점: 남녀 전용 목록, 상품마다 고정색 하나, 한벌옷은 상·하의와 함께 입지 않음, 피부색은 첫 톤 무료·이후 100골드 영구 구매, 미리보기는 저장·결제하지 않음. **배경은 팔지도 그리지도 않는다**(2026-10-16, 산 기록은 남김). 지금은 숲속 옷 가게이고, 6단계에 **QUIZSHOP**(착용 칸 + 아이템가방, 쪽 넘김, 금화 아이콘, 굵은 테두리 글씨, **남/여 바꾸기는 운영자만**)으로 바꾼다. 계획은 [상점 UI 계획](상점UI-계획.md), S1 시안부터 확인받는다.
- 디자인 검수: 그림·모션·화면 비평은 `.claude/skills/quiz-art-critique`, 사용자 확인 항목은 검수실 페이지(https://claude.ai/artifact/AQp4fhEksbf1R1TAFVvEiZ)에 사진과 함께 올린다.

## 작업·검수 규칙

- 수정 후 `node tools/check-source.cjs`와 바뀐 부분의 검사(레이아웃 `verify-layout.cjs`, 상점 `verify-starlight-shop.cjs`, 맵 `verify-school-room.cjs`·`verify-forest-village.cjs` 등)를 돌리고, `node tools/build-deployment.cjs` → `--check`, 배포 폴더(`/배포용/`) 주소에서 한 번 더 확인한다.
- `?demo=1` 체험 모드만 사용하고 실제 Firebase에 쓰지 않는다.
- 자동 검사 통과는 미술 완료가 아니다. 실제 기본 화면을 캡처해 직접 보고, 구현됨·직접 확인됨·미확인을 나눠 기록한다.
- 화면을 바꾸면 사용자에게 보이기 전에 `tools/verify-visual-polish.cjs`로 겹침·넘침·리본 이탈을 잡고, 만들어진 `확대-모음.png`(로고·큰 문구·상단바 2배 확대)를 직접 본다. 잔실수를 사용자가 찾게 하지 않는다. 새 화면을 만들면 그 화면도 이 도구에 넣는다.
- 작업 중 화면은 배포 전임을 밝힌다. main 푸시와 Cloudflare 배포 성공(GitHub 커밋의 Cloudflare 검사 결과)을 따로 확인해 보고한다.
- 재생성 가능한 캡처(`검증/`)는 올리지 않는다.
- 오래 걸리는 작업은 먼저 시간을 줄인다(2026-10-15 사용자: "너무 오래걸려"). 독립적인 일은 동시에(4코어) 돌리고, 바뀐 부분만 다시 만들고, 같은 계산을 두 번 하지 않게 결과를 저장한다. 문제를 하나씩 찾아 고칠 때마다 전체를 다시 돌리지 말고, 여러 문제를 모아 한 번에 고친다. 한두 개만 어긋난 원화·자료는 코드로 맞추지 말고 다시 요청한다. 30분 넘게 걸릴 일은 시작 전에 예상 시간을 알린다.
- 머리 모양과 모자를 코드로 맞추기 어려우면(묶은 자리가 모자 테두리 위인 양갈래·포니테일, 원화의 앞·옆·뒤 모자 크기가 서로 다름) 잘라 내기를 더 다듬지 말고 바로 원화를 다시 요청한다(2026-10-15 사용자: "머리스타일, 모자 매칭 어려우면 원화요청해", "남자 모자쓴 뒷모습은 원화다시요청해서고쳐야돼"). 모자 쓴 머리 원화의 첫 그림은 `tools/hair/make-hat-hair-base.cjs`로 게임 그림 그대로 뽑는다.
- 자르기 규칙을 고칠 때는 어려운 사례 3~4개(그 묶음만 자르는 명령, 예: `seated-layers.py items 칸`, `build-hat.py` 한 장)로 먼저 맞추고, 전부 다시 자르기는 마지막에 한 번만 한다(2026-10-16 점검: 앉은 옷 46벌 다시 자르기 약 10분을 문제 하나에 6번, 모자 18종을 규칙마다 전부 다시 자름). 10분 넘는 작업 전후에는 바로 커밋한다(작업 프로세스 재시작으로 한 번을 통째로 다시 돌림).
- 규칙을 고치며 맞출 때(2026-10-16 효율 점검): 어려운 사례만 다시 자르고, 전체는 마지막에 한 번 + 회귀 검사(얼굴 `build-face.py --check`). 같은 항목을 그림 검수에서 두 번 고쳐도 안 되면 그 자리에서 멈추고 원화 다시 요청을 검토한다(마스크를 4번 고친 일). 원인을 보려고 일회용 스크립트를 반복해 짜지 말고 도구의 확인 그림 옵션(`build-face.py --debug`)을 쓴다.
- 찾은 문제는 그 자리에서만 고치지 않는다(2026-10-15 사용자 지시, 2026-10-16 "앞으로 쭉"). 어려운 경우마다 ① 왜 놓쳤는지 ② 막는 규칙 ③ 다음에 자동으로 잡는 검사(옛 결과에 돌려 실제로 잡히는지, 새 결과에서 거짓 경고가 없는지 확인) ④ 기준 문서 표까지 한 묶음으로 한다. 왜 놓쳤는지 적고, 같은 문제를 다음에 자동으로 잡는 검사나 손작업을 없애는 도구로 바꾼 뒤 기준 문서에 남긴다. 예: [아바타 제작 기준](아바타-제작기준.md) '앉은 옷 층 만들기와 검사'.
- 토큰 절약(2026-10-14 사용자 요청, 검색 제외는 `.ignore`): 여러 에이전트 작업은 한 번에 하나만 돌린다. 에이전트 한 명이 오래 일하지 않게 일을 작게 나누고, 긴 로그는 파일로 남겨 요약만 읽는다. 그림은 필요한 부분만 잘라 비교판 한 장으로 보고, 다시 검증할 때는 바뀐 부분만 본다. 묶음이 끝나면 새 세션으로 넘어가며, 넘기기 전에 [인계](인계.md)를 고치고 임시 폴더의 필요한 자료를 저장소로 옮긴다(클라우드 컨테이너는 세션이 끝나면 사라진다).
