사용자 배포 요청(2026-10-01): Netlify 수동 배포는 **이 폴더 안의 `배포용/` 전체**로 한다. `index.html`만 올리지 않는다. 런타임 수정 후 필요한 원화 변경을 `node tools/build-avatar-file-data.cjs`로 반영하고, `node tools/build-deployment.cjs`로 전체 배포본을 다시 만든다. 완료 전 `node tools/build-deployment.cjs --check`와 실제 배포 폴더 경로의 브라우저 검사를 수행한다. 저장소 루트·좀비 게임의 `배포용`과 혼동하지 않는다.

사용자 교사 운영 요청(2026-10-01): 상단은 **내 퀴즈·수업 관리·학생 관리**와 **새 퀴즈 만들기**로 운영한다. 내 퀴즈는 문제 보관·수정·새 수업/혼자 풀기 열기, 수업 관리는 이미 배포한 활동의 입장·진행·공유·결과, 학생 관리는 계정·비밀번호·골드다. 별도 퀴즈룸·기존 OX·패션왕을 일상 교사 탭에 다시 추가하지 않는다. 기존 저장 데이터를 삭제하지 않으며 OX 문항은 공통 문제 작성기에 포함한다.

사용자 최종 지시(2026-10-01): **“모바일은 신경 안 써도 돼.” “선생님 화면은 사실 신경 안 써도 되긴 하는데, 애들한테 보일 때는 내가 보내준 에셋들을 많이 활용해서 풍성하게 보여야 돼. 가독성은 떨어지지 않되.”** PC·노트북의 실제 학생 화면을 디자인·검수의 기준으로 한다. 모바일 대응·추가 모바일 검수에 시간을 쓰지 않는다. 교사 화면은 문제 작성·수업 진행의 편리함과 읽기·입력 기능을 우선하고, 장식 확장에 미술 작업을 집중하지 않는다. 이전 문서의 모바일 작업 지침보다 이 지시를 우선한다.

학생의 로비·상점·아바타·탐험 맵·문제창·결과 화면에는 제공 자료를 적극 활용한다. 제작 전에 [전체 소재 보관함](assets/library/index.html)에서 실제 쓸 자료를 고르고 선택한 파일·사용 부위를 기록한다. 화풍·시점·광원·크기를 맞춰 숲속 마을의 장소를 구성한다. 자료를 저장하거나 녹색 버튼으로 바꾼 사실만으로 에셋 활용·풍성한 디자인을 완료했다고 보고하지 않는다. 배경·건물·식생·생활 소품·장식이 연결된 풍경을 만들고, 현재 예쁜 SD 뼈대와 비율·자연스러운 의상 착용을 유지한다. 질문·답안·학생 이름·점수·버튼에는 밝고 차분한 읽기 공간을 확보한다. 구체적인 제작 순서와 완료 기준은 [디자인기준.md](디자인기준.md#제공-에셋으로-학생-화면을-만드는-순서)를 따른다.

- 기존 세밀한 얼굴·헤어·상의·하의·신발·펫·천사 이펙트와 숨쉬기·눈 깜박임·날갯짓을 보존한다. 걷기·점프·앉기를 추가해도 세밀한 원화와 의상 조합을 임시 아바타로 바꾸지 않는다.
- 사용자 제공 숲·마을·계곡·Kingshot·도시·숲속 정원 참고 이미지(2026-10-01)를 맵의 최소 미술 목표로 삼는다. 건물의 원근과 지붕·벽·창문·재질, 나무의 잎 덩어리와 수종 차이, 지형의 높낮이·물·빛·그림자를 함께 다듬는다. 단순 도형이나 반복 장식을 늘린 상태를 이 기준에 도달했다고 보고하지 않는다. 목표와 실제 화면의 달성 수준은 구분하고, 사용자에게 보여 줄 기본 플레이 화면으로 판단한다.
- 메인 로비는 숲과 색칠한 나무 간판, 퀴즈나라 로고와 **3학년 3반**을 유지한다. 게임 방식별 세계와 장식은 구분하고 문제·입력·이름·팀 색을 읽기 쉽게 배치한다.
- 최신 공통 UI 기준(2026-10-01)은 사용자 최종 선택인 **숲속 마을**이다. `interface.zip`의 나무·양피지 UI와 햇살 든 마법 숲을 기본 자료로 삼으며 [기본 인터페이스 보관함](assets/interface-library/README.md)에 원본을 보관한다. 학생의 로그인·로비·상점·옷장·모든 게임·결과 화면에 따뜻한 나무·크림색 종이·이끼 녹색·금색 테두리와 옥빛 포인트를 적용한다. 교사 화면은 같은 기본 재질·색상을 사용하되 추가 장식보다 입력·저장·수업 진행을 우선한다. 학생 화면의 나무 간판·진열대·잎·꽃은 풍성하게 다듬고 문제·본문·입력란은 읽기 쉽게 유지한다. 기존 Royal Match 참고의 입체감과 버튼 두께는 품질 참고로 유지하되 밝은 파란 플라스틱이 전체 화면을 지배하지 않게 한다. 중요한 제목은 둥글고 굵은 한글과 윤곽선, 수치는 크림색 판, 진행은 읽기 쉬운 캡슐로 표현한다. 현재 SD 아바타 뼈대·비율과 방식별 맵 세계는 유지한다.
- 맵 변경은 각 방식의 실제 학생 시작 위치와 기본 플레이 시점에서 확인한다. 출발·진행·사물 접근·문제 열기·정답 뒤 이동·종료 화면을 저장하고 직접 열어 미술을 확인한다. 별도 조망 화면은 이 검수를 대체하지 못한다.
- 화면에 그린 울타리·닫힌 관문·장애물의 실제 충돌, 길 찾기와 모든 문제의 접근 가능성을 확인한다. 점프·대각 이동으로 닫힌 순서 관문이나 맵 경계를 우회하지 못해야 한다. 실제 키보드와 화면 조작 버튼도 사용한다.
- 자동 검사 통과나 코드에 이름이 있다는 사실만으로 미술·플레이 완료를 보고하지 않는다. 구현 위치, 실행 검사, 직접 확인한 화면을 구분하고 필수 미확인 항목은 남은 작업으로 보고한다.

- 미술 검수 기록에는 같은 크기의 변경 전·후 기본 화면, 참고와 대조한 입체감·깊이·재질·밀도 항목, 남은 부족함을 적는다. 사용자 참고 최소 수준을 달성하지 못했으면 달성했다고 보고하지 않는다. 기능 검사 통과는 미술 완료 근거가 아니다.

## 아바타 원본과 소재

얼굴·머리·옷·신발 원본과 소재 출처는 [아바타 라이브러리](assets/아바타-라이브러리.md)에 보존한다. 신규 제작·방향·동작·미술 검수 규격은 [아바타 제작 기준](아바타-제작기준.md)만 따른다. 사용자 제공 맵 자료는 [전체 소재 보관함](assets/library/index.html)을 사용하며 아바타 제작 방식 변경을 이유로 맵 원화를 바꾸지 않는다.

## 일반 퀴즈의 고정 규칙

교사 흐름은 **게임 방식 선택 → 문제 작성 → 수업 설정**이다. 일반 퀴즈는 다음 다섯 방식을 지원하며 같은 저장 문제 묶음을 실시간 수업과 나중에 혼자 풀기에 재사용한다. 학생별 정답·점수·진도는 저장하고 재접속 시 이어 간다.

- `sequence` 순서풀이: 울타리로 둘러싼 정해진 숲길에 꿀단지 관문을 차례로 둔다. 해당 학생이 정답을 맞혀야 자기 관문이 열리고 다음 구간으로 이동한다. 오답이나 다른 학생의 정답으로 열리지 않는다.
- `free` 자유풀이: 성·용암·사막·숲 구역이 있는 큰 2D 맵에서 원하는 순서로 탐험한다. NPC·사물 가까이 다가가야 문제를 열며 완료는 학생마다 독립적이다.
- `round` 라운드전: 시작하면 각 아바타가 자기 체크무늬 소풍 돗자리 한 장 위로 자동으로 걸어 들어간다. 모두 같은 문제를 제한 시간 안에 풀고 정답 공개 뒤 개인 점수와 마지막 순위를 확인한다.
- `team` 팀전: 교사가 팀 수와 무작위 균등 배정 또는 학생 선택을 정한다. 무작위 배정은 팀 간 인원 차이가 최대 한 명이어야 한다. 학생은 팀 색을 달고 울타리 안 가을 퀴즈 경기장에서 각자 풀며 개인 점수를 팀별로 합산한다. 팀원이 맞혀도 자기 문제는 완료되지 않는다.
- `coop` 협동전: 학생마다 독립적으로 풀고 반 전체의 맞힌 문제 수를 합산한다. 제한 시간 안에 반 공동 목표에 도달하면 함께 성공한다. 같은 학생의 같은 정답은 한 번만 합산한다.

일반 문항 유형은 `choice` 객관식, `short` 주관식(짧은 정답), `match` 선 잇기, `order` 순서 맞추기 네 가지다. 선 잇기는 학생이 짝을 고르면 실제 연결선을 표시하고, 순서 맞추기는 교사가 입력한 올바른 순서로 채점한다. 서술형은 추가하지 않는다. O/X 정답 문항도 공통 문제 작성기에서 운영하며 기존 저장 자료를 보존한다. 이전 OX룸은 일상 교사 탭에 다시 추가하지 않는다. 메인 로비의 움직임 연습에서 걷기·점프·앉기를 익힐 수 있게 한다.

개발 기준은 이 `퀴즈나라/` 폴더 하나다. 실행 파일 목록은 `tools/deployment-files.cjs`이며, 수정 후 `node tools/check-source.cjs`를 실행한다. 배포는 `node tools/build-deployment.cjs`로 만든 이 폴더 안의 `배포용/` 전체로 한다. 수동 배포와 GitHub 자동 배포는 같은 실행 파일 목록을 사용한다. 원격 최신 변경을 먼저 확인하고 퀴즈 경로만 커밋한다.

레이아웃·글꼴 변경은 `tools/verify-layout.cjs`, 음향 변경은 `tools/verify-audio.cjs`, 게임 규칙·결제 변경은 `tools/verify-game.cjs`와 `tools/verify-economy.cjs` 등 해당 검사를 실행한다. `?demo=1` 체험 모드로 실제 수업 데이터에 쓰지 않으며, 자동 검사와 실제 화면을 함께 확인한다. 재생성 가능한 `검증/` 출력은 GitHub에 올리지 않는다.

기존 검증 도구가 새 다섯 방식까지 실행했다고 가정하지 않는다. `개발환경.md`의 방식별 검수 항목을 실제로 확인하고, 기존 OX·가로세로 검사 결과와 새 일반 퀴즈 결과를 구분한다.

GitHub 업로드는 채팅의 기기 간 동기화나 클라우드 실행을 뜻하지 않는다. 연결된 기기와 실제 이전·푸시 결과를 확인하고 완료를 보고한다.
