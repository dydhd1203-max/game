# 퀴즈나라 작업 안내

3학년 3반 학생 21~30명이 함께하는 큐플레이풍 퀴즈·아바타 게임이다. 저장소의 좀비 게임(`클로드/`)과 그 배포본은 건드리지 않는다.

## 먼저 읽을 문서

- [큐플레이 목표](큐플레이-목표.md): 게임 목표, QUIZQUIZ 로비·무대 퀴즈·서바이벌 OX 설계, 녹화본 분석
- [디자인 기준](디자인기준.md): 색·글꼴·버튼·창·큰 문구·살아 있는 화면·퀴즈 방식별 맵
- [아바타 제작 기준](아바타-제작기준.md): 몸·옷·모션 / [숲속마을 디자인 지침](숲속마을-디자인지침.md): 맵
- [개발환경](개발환경.md), [배포안내](배포안내.md), 최신 검수 기록(`*-검수.md`)

## 사용자 결정 (최신이 우선)

2026-10-09 (3단계 시작)

- 새 옷 그림은 **그림 틀 + ChatGPT**로 만든다. 작업자가 기준 몸 시트(그림 틀)와 프롬프트를 주면 사용자가 ChatGPT 이미지 생성으로 옷 입힌 시트를 만들어 올리고, 파이프라인이 고정된 기준 몸에 맞춰 잘라 넣고 검사한다. Higgsfield는 쓰지 않는다.
- 3단계 틀·도구는 **반팔·반바지·신발**(지금 동작 코드가 지원하는 종류)부터 완성한다. 긴팔·긴바지·치마·원피스·부츠는 자료 구조만 준비하고, 그 상품을 옮길 때 동작을 추가한다.
- 머리는 **기존 머리 그림 24개를 유지**하고 목 자르기·사이 피부색·얼굴 크기를 머리마다 자동 규칙으로 맞춘다. 새 머리는 '목 없는 머리 + 앞/뒤 머리카락 층' 틀로 만든다.
- 기준 몸의 팔·목 그림에 남은 기본 티셔츠 소매 끝 선·옷깃 선(새 옷에서 '유령 선'으로 비침)은 **생성 규칙으로 지우고 피부로 이어 그린다**. 관절·비율은 그대로다. 전후 확대 사진(`검증/옷틀/팔목-유령선-전후.jpg`)을 본 사용자가 승인했다("오키 이어서 진행해줘"). 새 옷은 정리한 팔·목 그림(`sd-foundation-ref-arms-clean.png`, `-neck-clean.png`)을 쓰고, 기본 옷은 3단계 끝에 다시 비교해 보여 준 뒤 바꾼다.
- ChatGPT 옷 색이 상점 고정색과 **비슷하면 그대로 쓰고 경고만** 남긴다. 눈에 띄게 다르면 다시 요청한다.
- 기준 캐릭터의 기본 옷은 **무료 시작 상품**과 연결한다(남 top:tee:5·bottom:shorts:9, 여 top:tee:3·bottom:shorts:5, 신발 shoes:sneaker:8). 남자 새 계정의 기본 하의는 5단계 전환 때 청바지에서 **반바지(shorts:9)**로 바꾼다. 이미 저장된 학생 옷은 바꾸지 않는다.
- 상품을 다 옮길 때까지 **학생 화면은 지금 아바타 그대로**다. 새 기준 캐릭터는 체험 주소(`?avatar=foundation`)에서만 보인다(5단계에서 전환).

2026-10-08 밤

- 앞모습 고개 인사에서 얼굴이 앞머리 밑으로 숙여지는 모습을 사용자가 승인했다("얼굴 숙이는거 괜찮아"). 옆모습 기뻐하기 등 남은 확인은 작업자 추천대로 한다(직접 본 비교 화면에서 얼굴을 가리지 않고 더 자연스러운 쪽).
- 사다리를 탈 때 손발이 **조금 미끄러져도 된다**. 손발을 칸에 딱 붙이느라 박자가 빨라지는 것보다, 차분한 박자(초당 약 3번)를 우선한다.
- 손 흔들기·기뻐하기에서 쓰는 **펼친 손** 그림을 사용자가 승인했다("손 괜찮아").

2026-10-08 저녁

- 머리스타일 아바타를 많이 만들 것이므로 **머리카락을 자연스럽게 살리고 머리–목 연결을 어색하지 않게** 한다. [아바타 제작 기준](아바타-제작기준.md)의 '머리–목 연결 규칙'을 지키고, 고친 내용과 원인을 꼼꼼히 기록한다.
- 사용자에게는 한국어로 말한다.

2026-10-08 오후 (아래 숲속 색 결정보다 우선)

- **전체 UI를 큐플레이의 파란 느낌·버튼·구도로 바꾼다. 마을·교실·운동장 등 맵 그림은 그대로 두고 그 위의 UI만 바꾼다.** 참고는 `디자인기준/21~25-큐플레이UI-*.png`(로비·교환방·상점·가방·퀴즈무대)와 OX 녹화본 장면. 코발트 창, 하늘색 광택 테두리, 남색 제목 띠, 남색 아이템 칸(EMPTY), 광택 파랑·주황 알약 버튼, 둥근 크롬 아이콘 버튼, 아래쪽 채팅·버튼 바. 상점·버튼 등 모두 포함. 지금 디자인의 좋은 점(사탕 큰 문구, 살아 있는 움직임, 꾸민 아바타 주인공, 읽기 쉬운 글꼴)은 살린다. 원작 로고·그림은 복사하지 않는다.
- 서바이벌 OX는 운동장 맵이 아니라 녹화본처럼 한 화면짜리 경기장(매달린 문제판, 디지털 집계판, 둥근 O·X 웅덩이, 덤불 테두리)으로 만든다.
- 문제 은행: 3학년 2학기 수학·사회·과학, 객관식·단답형(OX는 OX). 단원별로 최대한 많이 저장하고 방 만들기에서 고른 문제 수만큼 무작위 출제. 학년·학기 칸은 만들되 3학년 2학기만 연다. 그림 문제는 작은 그림 + 돋보기 확대.

2026-10-08 오전

- 목표는 넥슨 **큐플레이**다. 진행 방식·화면 구성·연출을 따르고 색·재질은 숲속 마을(나무·크림 종이·이끼·옥빛·금색)을 쓴다. 원작 로고·그림·음원은 복사하지 않는다.
- 흐름: 로그인 → 숲속 마을 → 상단 **QUIZQUIZ** → 퀴즈 로비(방 목록·방 만들기·바로 시작·채팅·내 아바타) → 대기실 → 무대형 일반 퀴즈 / 서바이벌 OX → 결과. 학생도 친구끼리 방을 만들고, 수업 때는 선생님이 방을 만든다. 무대 퀴즈와 서바이벌 OX를 먼저 만든다.
- 옛 게임처럼 **손으로 그린 느낌**: 굵은 외곽선, 평평한 채색, 계단식(`steps()`) 프레임 애니메이션.
- **모든 맵·로비·대기실은 살아 있는 화면**이다. 조명·반딧불·물결·흔들림 같은 작은 움직임이 늘 있다. 동작 줄이기·숨긴 탭·화면 밖에서는 멈추고 30명 성능 예산을 지킨다.
- 글꼴: 본문 나눔스퀘어라운드, 버튼·작은 제목 나눔스퀘어라운드 ExtraBold(`QuizDisplay`), 큰 문구는 `candy-title.js` 사탕 글씨(한글 주아·영어 Fredoka). '퀴즈'가 들어간 큰 문구는 **QUIZ**로 쓰고 QUIZ만 하늘색.
- 버튼은 `qplay-buttons.css`의 큐플레이식 판이다. 기본 이끼, 주요 금색, 보조 나무, 선택 옥빛, 뒤로·닫기·나가기 버섯 빨강.
- 상점은 **숲속 옷 가게**(`assets/forest-shop.png`). 맵 아래 동작 버튼줄은 없애고 1·2·3 키로 손 흔들기·인사·신나!를 한다.
- 기준 캐릭터: 사용자가 `assets/avatar-reference-candidates/body-study-2026-10-04.png`를 "기준캐릭터 디자인"으로 지정했다. 몸·기본복 v2는 이 그림에서 직접 만들었다([기준 캐릭터 검수](기준캐릭터-검수.md)). 순서: ① 기준 캐릭터 마무리 → ② 모션 재제작 → ③ 옷 제작 틀·파이프라인 → ④ 상점 아이템 1개 시범 전환 → ⑤ 모든 화면 적용 → ⑥ 상점·무대·OX 파란 UI와 문제 은행. 단계마다 검사·캡처 후 작업 브랜치에 올리고, main(실제 배포)은 확인 뒤 합친다.
- 바꿀 때 **옛 디자인·지침·파일은 지워** 코드와 저장소를 가볍게 한다. 필요하면 git 기록에서 꺼낸다.
- 검사를 통과한 결과물은 main에 올린다(사용자 허락). main은 Cloudflare Pages `game`(https://game-5ni.pages.dev)에 자동 배포된다.

이전부터 유지하는 결정

- 아이들이 좋아하는 맵·화면·아바타 미술에 가장 공을 들인다. 기능만 붙인 임시 도형으로 끝내지 않는다.
- PC·노트북(그램·크롬북) 학생 화면이 기준이다. 모바일은 추가 작업하지 않고, 교사 화면은 작성·진행이 편하면 된다.
- 맵 그래픽은 사용자가 제공한 에셋만 골라 배치·조합한다. 새 AI 맵 그림이나 임의 SVG 지형으로 대신하지 않고, 부족하면 필요한 에셋을 요청한다. 버튼·창·O/X 구역 표시 같은 UI 층은 직접 그린다.
- 학생 입장은 `SCREENS.village`, `?classroom=수업ID` 링크는 해당 수업으로 들어간다.
- 공용 맵 아바타: 입력 120px × 카메라 0.76, 걷기 337.5px/s, 같은 방향키 두 번이면 506.25px/s 달리기, 통행 반경 7. 나무 뒤에서는 겹친 신체 부분만 불투명도 0.38. 출입구는 닿으면 자동 이동, 사다리 ↑↓, C 앉기, E 칠판·상호작용, M 지도.
- 교실은 30자리와 칠판 수업·퀴즈 열기. 운동장 벤치는 배경 그림이다.
- 교사 상단은 내 퀴즈·수업 관리·학생 관리와 새 퀴즈 만들기. 기존 저장 데이터는 지우지 않는다.
- 일반 퀴즈 방식 `sequence`·`free`·`round`·`team`·`coop`, 문항 `choice`·`short`·`match`·`order`와 O/X. 저장 형식은 [개발환경](개발환경.md).
- 상점: 남녀 전용 목록, 상품마다 고정색 하나, 한벌옷은 상·하의와 함께 입지 않음, 피부색은 첫 톤 무료·이후 100골드 영구 구매, 미리보기는 저장·결제하지 않음.

## 작업·검수 규칙

- 수정 후 `node tools/check-source.cjs`와 바뀐 부분의 검사(레이아웃 `verify-layout.cjs`, 상점 `verify-starlight-shop.cjs`, 맵 `verify-school-room.cjs`·`verify-forest-village.cjs` 등)를 돌리고, `node tools/build-deployment.cjs` → `--check`, 배포 폴더(`/배포용/`) 주소에서 한 번 더 확인한다.
- `?demo=1` 체험 모드만 사용하고 실제 Firebase에 쓰지 않는다.
- 자동 검사 통과는 미술 완료가 아니다. 실제 기본 화면을 캡처해 직접 보고, 구현됨·직접 확인됨·미확인을 나눠 기록한다.
- 화면을 바꾸면 사용자에게 보이기 전에 `tools/verify-visual-polish.cjs`로 겹침·넘침·리본 이탈을 잡고, 만들어진 `확대-모음.png`(로고·큰 문구·상단바 2배 확대)를 직접 본다. 잔실수를 사용자가 찾게 하지 않는다. 새 화면을 만들면 그 화면도 이 도구에 넣는다.
- 작업 중 화면은 배포 전임을 밝힌다. main 푸시와 Cloudflare 배포 성공(GitHub 커밋의 Cloudflare 검사 결과)을 따로 확인해 보고한다.
- 재생성 가능한 캡처(`검증/`)는 올리지 않는다.
