FIVE PARTS
1. Frozen body.
- These stay byte- and value-identical: assets/sd-foundation-ref-data.js (body fields), sd-foundation-ref-arms/legs/neck.png, and SPEC/SPEC_F in avatar-foundation.js. check-source hash-guards them.
- derive() never runs on a garment. A body change needs --allow-body-change plus user approval.
- One-time frozen build artifacts feed every garment build: owner map; zones (armhole S/A seams, sleeve and foot envelopes, hem/neck/opening/sole bands, waist cover line); hair-occlusion mask; class limits derived from body coverage and runtime constants.
2. Garment build = 'what changed against the frozen reference'.
- Each figure of the upload U is registered onto the frozen grid. U is then compared with the template T and with B: the frozen body plus the other basic slots, i.e. what shows when the product slot is empty.
- Only the product's own pixels are taken from the upload. Nothing else is ever reused, because ChatGPT re-renders every pixel.
- These replace every palette heuristic, and every value the runtime measures today: per-sheet colour models, a skin strip gated by frozen skin zones, DP seams inside frozen bands, frozen ownership zones for the part split, rule-based hidden-cloth rebuild, and offline metadata.
3. Data-driven demo runtime.
- Garment records are keyed 'cat:shape' (ci stays a legacy token). Atlases are cropped per sex and loaded lazily.
- Garment ids go into every template, atlas, pool, cache and DOM key. Fallback is per slot, with an explicit reason.
- The basic outfit becomes the first three records (top:tee, bottom:shorts, shoes:sneaker). They are packed losslessly and flagged legacy: their raised sleeve, underarm, edge tone and side span are still computed by today's code, now keyed by garment id. The refactor is therefore gated on R0 identity over the whole motion matrix.
- Pipeline records carry the same data precomputed.
- Only after the pipeline rebuilds the basic outfit (user-approved, reviewed diff) are these deleted: the legacy heuristics, the 4 full-sheet garment PNGs, and the garment code in build-reference-body.py.
4. Hair.
- The 24 paintings stay byte-exact. They are converted offline into foundation-owned layers (skin, features, hair-front, hair-back, no neck), with landmark face scale, an automatic neck cut and one skin formula (the body's toneMatrix).
- That makes 'no-neck head + front/back hair layers' the single runtime model.
- New hairstyles reuse it: a shared base head plus a 'change only the hair' template, run through the same registration code as garments.
- avatar-pixel.js and avatar-direction.js are never edited, not even behind flags.
5. Students unchanged.
- Every new path runs only behind QPDemo + ?avatar=foundation, or in the studio.
- index.html gets inert script tags and an edit inside the existing demo gate (normalise with avatarForSex first). avatar-image.js gets one new prefix route.
- A guard compares the old renderer's strings, normal-URL screens, the network log and protected-file hashes against a worktree of the pre-stage-3 commit.

HOW THE USER USES IT (about 2 minutes)
① Start a new ChatGPT chat for each product.
② Attach template-sheet.png first and the design reference second.
③ Paste the prompt.
④ Download the result with ChatGPT's download button, at original size (PNG preferred; WebP or JPEG accepted).
⑤ Upload it in our chat.
The worker then stores it byte-exact as assets/garment-sources/<cat>-<shape>-<ci>-chatgpt-<date>.<ext>, with its sha256 and prompt in the README row, and runs `python3 tools/garment/build-garment.py <cat:shape> --sheet <file>`. On failure the user gets the annotated report and ONE Korean sentence to paste into the same ChatGPT chat.

WHY CHATGPT CAN FOLLOW IT
- The template is OpenAI image generation's own earlier output, so its style, proportions and layout are in-distribution.
- 'Change only X' is a local edit with explicit invariants.
- The 3:2 canvas matches the model's 1536x1024 landscape output, so the only expected global change is a uniform scale (×0.9429).
- Lengths are stated relative to the visible current garment, not as numbers.
- The design reference fixes colours and details.
- Evidence: the first real attempt held all six figures within 0.6 px, and only the tops changed.
- Resolution: about 15.4 sheet px per body unit, against 8.46 screen px per unit at the 280 px shop size, i.e. 1.8× oversampled.
##### registration
Shared module tools/avatar_build/register.py with matte.py, also used by the hair pipeline. Numpy and PIL only; scipy and OpenCV are absent. All geometry is in frozen sheet px: the 1448x1086 grid, CELLS, COLLAR_Y 264/786.

STEPS
1. Input.
- PNG, WebP or JPEG.
- Long side must be ≥1200 px, else SIZE_SMALL ('ChatGPT 내려받기 버튼으로 원본 크기를 올려 주세요').
- The source is stored byte-exact with its sha256 before anything else.
2. Matte.
- If ≥5% of pixels are transparent, use the alpha. A periodic two-tone checkerboard → BACKGROUND.
- Otherwise the 12 px border median must be ≥240 with std ≤6, else BACKGROUND.
- Foreground = pixels not border-connected to near-white (scanline flood fill; the drawn outline is the barrier). This keeps white collars and cuffs; the threeway prototype lost the female white collar with a per-pixel whiteness test.
- Dark pixels below the frozen floor +3 px that are not in the template → SHADOW.
- Foreground components outside the figure boxes (+30 px): >400 px → FOREIGN_MARK; 40–400 px are removed with a warning.
3. Layout.
- Projection bands must give exactly 2 rows × 3 columns of figures (LAYOUT_COUNT; crops and missing figures land here).
- Rows must be ordered male, then female (LAYOUT_ORDER).
- The side view must correlate better with the template profile than with its mirror (LAYOUT_MIRROR).
4. Global initialisation from the six boxes (head top, soles). The expected scale is 1536/1629.
5. Per-figure similarity fit: s, dx, dy; no rotation or shear, because a pose change is rejected, never warped away.
- Coarse to fine: s ±3%, shift ±16 px, steps 1 px → 0.1 px.
- Objective: robust Lab error with lightness weight .7, gradient-weighted, on the STABLE mask = template foreground below collar+10, minus the product slot's frozen zone dilated 12 px. For a top: forearms/hands, legs, shoes and the shorts below the hem band. For shorts: torso above the hem band, arms, shins, shoes. For shoes: everything above the ankle band.
- This colour objective gives ≤0.6 px on the real sheet; the silhouette-only fit gave up to 2.4 px. Silhouette IoU is still computed as a diagnostic.
6. Diagnostics.
- A free affine fit: |rotation| >1.5° or |sx/sy−1| >2% → SQUASH (a square or squashed output).
- Each figure's scale against the six-figure median: ≤3% is absorbed; 3–6% gives warning W_SCALE; >6% → FIGURE_SCALE.
7. One resample into sheet space per cell: PIL resize with a sub-pixel box (exact scale + translate) and Lanczos, giving a 1448x1086 RGBA plus the matte alpha. There is no second resample anywhere.
8. Drift checks.
- Stable-region ΔE: median ≤4 and p95 ≤10 (real sheet 2.25 / 6.0), else BODY_DRIFT.
- Stable silhouette IoU ≥.93. Real sheet .961–.971 under the silhouette fit; squash negative .62–.81.
- Part residual shift (±8 px search) for each forearm+hand, shin and shoe, and the torso/shorts outline for a shoes product: ≤1.5 px pass; 1.5–3 px warning; >3 px → POSE_ARM / POSE_LEG, naming figure and part. Prototype baseline 1–3 px; 8 px drift reads 8 px.
- Head/hair shift: report only, since heads are discarded. Hair covering more garment than the frozen hair-occlusion mask (+150 px per figure) → HAIR_OVER_GARMENT.
- Other slots changed: after a per-sheet linear tone fit on stable pixels, the share of each non-product slot with blurred ΔE >10 must stay within: shorts .30, shoes .20, legs .05, arms .10 (real maxima .15 / .05 / 0 / .04). A median colour shift ΔE >8 also counts. Either → OTHER_SLOT_CHANGED('반바지'/'신발'/'윗옷').
- Single-sex products: the untouched row is checked the same way → SINGLE_SEX_CHANGED.
9. Class geometry, measured after segmentation. Limits live in tools/garment/frozen/limits.json and are generated from frozen body data and runtime constants, not from basic ±px.
- Top:
  - Sleeve opening inside the record's sleeve box and ≥.3 u above the elbow → else SLEEVE_LONG.
  - Opening not above the arms layer's clean-skin start (the arm layer carries basic-cuff scraps above it) → else SLEEVE_SHORT.
  - Hem ≥ the bottom's frozen waist cover line + .24 u (seated breathing .14 + .10) → else HEM_HIGH.
  - Hem ≤ hip row + .25 u → else HEM_LOW.
  - Collar top no more than .1 u above the basic collar outline → else COLLAR_HIGH. The browser checks the female FRONT_HAIR_CLIP margin ≥.10 at the nod peak.
  - Exposed neckline skin must lie inside the neck layer's opaque art (alpha>200), eroded 1 px → else NECK_OPEN. The real male V reaches y=289, exactly the layer's end.
- Shorts:
  - Cuff not above shorts_bottom −8 (copied thigh rows) → else SHORTS_SHORT.
  - Cuff ≤ knee −7 px (floor-sit tubes end .42 before the knee) → else SHORTS_LONG.
  - Waist hidden under the hem → else WAIST_VISIBLE.
  - Legs separated at x=16 → else SKIRT_LIKE.
- Shoes:
  - Sole within ±2 px of the frozen floor → else SOLE_OFF_FLOOR.
  - Shoe top covers the leg layer's end and stays ≥ ankle −20 px → else SHOE_LOW_OPENING / SHOE_HIGH.
  - Both feet present → else SHOE_MISSING.
- All:
  - Main cloth colour agrees across the three views within ΔE ≤8 → else VIEW_INCONSISTENT.
  - Main colour vs the shop colour ΔE >15 → COLOUR_OFF, a warning only, never auto-recoloured.
  - Garment pixels of skin hue left after the strip → UNTINTED_SKIN.

CALIBRATION
Thresholds are provisional. They are calibrated on four inputs: the identity input, the template at 1536 WebP q80, the synthetic set, and the real shirt:10 sheet. Every limit must pass the basic outfit with ≥2 px margin, pass the real sheet, and fail its negative control. A limit is never loosened so far that a negative passes. Each later real sheet re-checks the calibration.

ACCEPTANCE TESTS (tools/garment/test_register.py)
- template-sheet.png as the upload: |dx|, |dy| ≤.1 px and |s−1| ≤5e-4.
- Template at 1536x1024 WebP q80: joint error ≤1 px.
- Real sheet: ≤0.6 px and ≤0.2% from the global fit; no OTHER_SLOT_CHANGED.
- Drift variants: s .97/1.03, ±10 px, one figure +2% / +5 px, 1024² padded input, JPEG q70, WebP q60. Each recovered within .3 px.
- ≤60 s per sheet.

##### segmentation
Modules: tools/garment/segment.py, seam.py, fill.py, metadata.py, pack.py and build-garment.py. They run on the registered sheet-space image. No fixed palette is used anywhere.

INPUTS
- U: the registered upload.
- T: the template, i.e. the reference on white.
- B: a composite of the frozen layers EXCEPT the product slot. It holds the body (neck extended under the collar, arms into the sleeves, legs into the shorts), the other basic slots and the reference head, with B_alpha.
- O: the frozen owner map. It was made once from the ORIGINAL 7 layers and is stored in tools/garment/frozen/, so a later rebuild of the basic outfit never shifts it.
- zones.json, the hair-occlusion mask and limits.json.

1. CHANGE MAP. D_T and D_B are window-min Lab distances (r = 2 px, absorbing sub-pixel drift, lightness weight .7), median-filtered. τ = max(7, p95 of stable D_T + 1), with hysteresis at τ/2.

2. COLOUR MODELS learned from THIS sheet (numpy k-means plus Gaussian NLL):
- skin, k=3: from eroded visible forearm/hand/shin/neck pixels away from the product envelope. Shaded skin is included; classify()'s rule misses the shaded cuff band.
- product, k=4 (covers prints): from changed pixels deep inside the envelope.
- neighbouring unchanged slots: from their eroded zones.
- hair: from the template's hair near the collar.

3. LABELLING per pixel. This is plan-production's rule with plan-pipeline's gates.
- Unchanged (D_T < τ) → owner O. It is product only if O is a product part, which keeps a new shirt's cream collar or cuffs when they match the old ones.
- Changed, matching B, B_alpha > .5 → the body or another slot shows through. Accepted only when all of these hold: within 24 px of the old garment/body boundary; 4-connected to unchanged body pixels; on body parts that have painted art there. Exposure where there is no body art feeds HEM_HIGH, NECK_OPEN or SHOE_LOW_OPENING.
- Changed, not matching B, inside the product's allowance zone (its frozen zone dilated 20 px; never above the collar −6 or into the head) → product.
- Changed outside the zone → foreign, which feeds OTHER_SLOT_CHANGED.
- Skin gate: inside the frozen body skin zones (dilated 4 px), the skin-model winner is skin, never garment. This kept a skin-coloured synthetic top at IoU .92–.96.
- Line-art rule: dark ridges within 2 px of a frozen body outline that lie outside the product interior belong to the body.
- Unchanged reference hair lying on the garment (female bob tips, back collar) is a hole, rebuilt in step 6.

4. BOUNDARIES by DP seams (seam.py): a smoothness-constrained path inside frozen bands. Cost = colour log-likelihood ratio + an outline-ridge term (the drawn line between cloth and skin separates cream from skin) + a distance prior to the basic boundary.
- hem: product vs bottom. Columns covered by the hand are excluded (profile tails).
- armhole: torso vs sleeve, front and back, in a band around the frozen S/A seam.
- cuff/opening: sleeve vs skin, in the upper-arm frame.
- collar: cloth vs neck skin.
- shorts opening: cloth vs thigh.
- shoe top: shoe vs ankle.
The prototype hem seam came within 0–2 px of the median.

5. PART SPLIT by frozen ownership, without colour.
- Front/back sleeve = garment outside the torso side line from the frozen shoulder-top S to the armpit A (S and A are frozen body data).
- Profile sleeve = garment inside the upper-arm capsule (frozen joints and radii), grown outward along the arm normals to the sleeve's own painted outline, at most 3.5 u.
- Shoes = the garment component in each frozen foot zone, split at the centre in front/back. The profile has one drawing, as today.
- Bottom = one piece, with the centre seam at body x=16.

6. HIDDEN CLOTH. Hole = frozen occluders at rest ∩ the slot's target silhouette.
- Occluders: arm/hand over the torso and shorts; the new sleeve over the torso cap; reference hair over the collar/shoulders; the basic hem over a new bottom's waist.
- Targets:
  - front/back torso: side_outline continued from the NEW painted side contour up to the shoulder;
  - side views: edge_cover generalised to the hem and the front/back edges under the arm;
  - bottom: extended up to the frozen waist cover line (harmonic continuation), so any compliant top overlaps it;
  - under the female bob: occlusion mask ∩ the frozen basic shirt alpha, rebuilt as plain cloth, with the percentage reported.
- Fill: rebuild_cloth (harmonic shading + exemplar detail, prints excluded by print_mask relative to the garment's own median), then outline_profile/draw_outline on the new edges. Exemplar and harmonic run only inside the product's cells, to keep a build under 3 min.

7. POST RULES.
- Skin strip: garment pixels with high skin likelihood inside the arm/leg/neck zones are dropped, revealing the already-filled body layer. This fixes the pale bands.
- Seam fade 6 px from the frozen seam; cuff crisp 22 px; prints kept opaque.
- Pin-hole closing, clean_edges, drop_specks.
- Alpha: known-background unmixing against the measured white for the outer silhouette, alpha = |U−W|/|F−W|. Ownership cuts get 4× supersampled coverage.

8. METADATA (metadata.py), computed offline:
- Sleeve: cuff (t along the resting upper arm) and opening polyline. This replaces cuff_top.
- Sleeve box: the actual extent in the sleeve frame + .15 u. Today's basic reaches 4.11–4.21 u against the fixed 4.0 edge.
- Raised-sleeve art: geometric removal of the inner strip below the cuff top, inward of the cuff's inner end. This replaces the green/cream test.
- Underarm per side: edge polyline, inset, line/cloth colours, under profile and cuff, from the shirtSide algorithm ported to Python.
- Hem and collar polylines.
- SEAT {cut, apex, cuff, rise}: apex and cut/cuff from the shorts mask outlines. rise uses a new rule fitted on the cuff band's own upper outline (the prototype's rise was off 4–7 px). The hand table stays as regression truth for the basic outfit.
- SIDE_SEAT {cut, cuff} plus the opaque span at cut−1, which replaces the runtime rowSpan read.
- edgeTone, waistTop, cuffAlong (today .81), and the shoe ankle/opening/sole rows.

9. OUTPUT: one cropped atlas per sex, a record JS, and an index entry. Debug overlays, the label map and a parts sheet go to 검증/옷/<id>/.

##### risks
- Only one real ChatGPT sheet exists (0.6 px, only the tops changed). Other runs may drift in arms, pose, proportions or layout. Thresholds are calibrated on that sheet plus synthetic variants, so the first new products may need 2–3 retries and a recalibration (never loosened past a negative).
- ChatGPT re-renders every pixel and redraws prints: the real shorts differ in up to 15% of pixels. The design never reuses non-product pixels from the upload, but the T/B comparison thresholds must tolerate this style drift while still catching real slot changes.
- Cream or skin-coloured garments are hard to separate: the female 카라 셔츠 is about ΔE 6–7 from skin, and white collars sit against a white background. The geometry gates, outline ridge and connectivity matte help, but seams may wobble. The prototype still showed female white-collar holes, which the WP5 matte must fix.
- Body coverage limits stage 3. The real male V-neck reaches y=289, exactly the neck layer's end (zero margin). The arms layer carries basic-cuff scraps, and the thigh rows above shorts_bottom−8 are copied. Deeper necklines and shorter sleeves or shorts need body art changes, which need user approval.
- Hidden cloth under the bob and the arms is rebuilt by rule, not drawn. Distinctive back collars (sailor, hood) or prints hidden there cannot be captured from one sheet.
- Auto-extracted seat metadata is error-prone: the prototype rise was off by 4–7 px. Wrong rows give torn seats or cream wedges, so every garment needs a seated visual review. The hand table stays as truth for the basic outfit.
- Puff sleeves and wide collars stretch short-sleeve assumptions: a per-record box increases sleeve raster memory, and the female FRONT_HAIR_CLIP .10 margin must be re-measured per collar.
- The left view mirrors the right, so the shirt pocket and the blouse bow flip sides. This conflicts with 아바타-제작기준.md:33 until left figures are supported.
- Paint-pool pressure: the basic-only crowd already uses 38.18 of 40 MiB, and mixed garments multiply sleeve and shorts entries. The 24 MiB tier on small Chromebooks may thrash. Half resolution changes approved art and needs approval.
- R0 identity is fragile. It depends on lossless crops, PNG chunk hygiene, integer rects and the same Chromium build. A false alarm could stall WP3; a loosened gate would hide regressions.
- Shared-file edits (index.html gate and script tags, avatar-image.js route) could leak into the student path or file:// play. The students-unchanged guard and the routing unit test are the protection.
- avatar-foundation.js and avatar-foundation-outfit.js are edited by the garment WPs (WP3, WP9, WP11) and the hair runtime (H3). Concurrent patches can overwrite each other, so the lock order must be strict and R0 re-run after each handover.
- Hair automation visibly changes the demo: face size up to ×1.17 or ×.92, faces slightly less pink, and the bow look for long bangs. Offline classification can mislabel cream highlights, brows or lashes, and boundary unmixing can halo under dark skin or light hair.
- SVG filter cost on 30 heads (skin plus hair-front/back filters) may raise update time. Any code or verifier that serialises the SVG into an image loses external head hrefs; verify-foundation-browser's differ() must move to screenshots first.
- The female back view borrows the male neck painting (f-back neck is null). Nape-revealing styles (pony, bun, twin) may show a wrong-width neck, and fixing it changes the frozen body.
- The numpy-only exemplar and harmonic loops are slow. A build must stay under 3 min by limiting work to the product's cells, or the feedback loop suffers.
- The task text assumed no real sheet exists. The user may expect stage 4 to start from a fresh sheet, so whether to reuse it is asked rather than assumed.
- Baseline noise: verify-school-room is broken on main, verify-layout and verify-visual-polish fail on unrelated items, and the tools default to /usr/bin/chromium (absent here). Unrecorded noise could hide regressions.
- All performance numbers are cloud software rendering. Gram and Chromebook FPS, memory and file:// play on school PCs are unmeasured and must be reported as such.
- The repo-root AGENTS.md zombie-game art rules (curved, rubber, cloth, metal) and 21-player standard must not be applied here. 퀴즈나라 uses flat hand-drawn 1–2-step shading.
