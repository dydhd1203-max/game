# 표시 성능·측면 앉기·마을 마감 — 2026-10-03

기준 수정 전은 `0d40de6`이다. 사용자 요청의 두 개선은 다수 아바타 표시 성능과 긴 옷의 측면 바닥 앉기다. 원래 화면의 분홍 착장은 **후드+치마**였으며, 한벌옷 `dress`·`robe`에도 같은 접힘 문제가 있었다. 계정·재화·보유 아이템·얼굴·머리·원본 PNG는 변경하지 않았다.

## 확인한 원인과 수정

- `avatar-poses.js`는 치마/긴 상의의 서 있는 밑단을 세로 `.55`배로 줄였다. 관절은 앉았지만 옷에는 무릎 위로 펼쳐진 실루엣이 없었다. `avatar-pixel.js`에 기존 측면 팔레트·명암·봉제선·자수 규칙으로 접힌 옷자락을 따로 정의했다. 기존 6종 치마와 `dress`·`robe`의 좌우 바닥 앉기에 사용한다. 긴 상의의 몸통도 허리까지 분리해 서 있는 밑단과 중복하지 않는다. 앞·뒤·책상 앉기·서기는 원래 그림을 유지한다. 몸이나 머리를 줄이지 않았다.
- 매 프레임 문서 전체에서 모달을 찾고 신발/목/팔의 동일한 노드를 다시 탐색하던 작업을 줄였다. 관절 상대 좌표는 동일한 2D 행렬을 작은 수치 배열로 계산하며 CSS 변형·중첩 SVG의 브라우저 계산 fallback을 유지한다.
- 맵의 정적인 측면/후면 의상·피부·신발과 팔 그림을 **같은 SVG 원화가 들어 있는 이미지**로 묶었다. 색과 그림을 재생성하거나 해상도를 낮추지 않았다. 이미지 로딩 전/실패 시 기존 인라인 그림을 유지하고, 손·관절·깜박임은 계속 움직인다. 상점의 인라인 그림은 그대로다.
- 소매의 동일한 변형 격자를 유지하면서 완전히 투명한 원본 영역의 삼각형 계산을 생략하고 원본 소매 분리를 재사용한다. 친구들의 인사 진행률도 한 프레임에서 같은 시각으로 계산한다.
- 몸과 펫/천사 효과를 동일한 좌표·크기의 SVG 두 층에 표시해 날갯짓 때문에 몸 전체를 다시 그리는 부담을 줄였다. 모달/탭/명시적 정지 때 두 층을 함께 멈춘다. 화면 밖 친구는 표시·포즈 갱신을 멈추고, 돌아올 때 현재 방향·동작을 즉시 적용한다. 인원 목록과 위치 공유는 유지한다.
- 마을 북쪽 개울 시작점과 기존 정원 의자 주변에 종꽃·노란 꽃·양귀비·크림색 꽃·작은 들꽃 **7무리**를 배치했다. 처음 배치의 떨어진 덩어리는 직접 화면을 보고 물가/의자 가까이 다시 모았다. 의자 밑동 충돌과 다리→꽃마당 검수 경로를 추가했다. 제공 원본·기존 편집본을 사용하며 새 맵 원화를 만들지 않았다.

## 실행 증거

체험 모드 `?demo=1`, 실제 Firebase SDK 차단, Chromium, `/workspace/quiz-cloud/run-node.sh`를 사용했다. 재생성 출력은 `/workspace/quiz-cloud/avatar-polish-2026/`에 두고 Git에 넣지 않는다.

- `tools/verify-seated-hems.cjs`: 2성별×2피부색×8옷자락×4방향×2크기 = **256조합**. 양 무릎의 그림 안 포함, 머리 크기, 발목 접지, 책상/서기 복원, 옷자락을 8단위 떼어 놓은 실패 대조 통과. 모양의 예쁨을 자동 판정하는 검사는 아니다.
- `tools/verify-avatar-map-rendering.cjs`: 인라인 원화와 맵 캐시 방식 **240화면** 비교. 남녀·반팔/후드/드레스·4방향 요청·걷기/앉기/인사 올림·정점·내림·96/280px. 기존 인사는 정면으로 돌아보므로 인사 중 측면/후면 그림까지 검증했다는 뜻은 아니다. Chromium의 인라인/외부 SVG 경계 래스터화 차이를 분리해 검사한다. 실제96px의 최대 차이는12/255, 2보다 큰 차이 픽셀은 최대32개였다. 확대280px는 선 경계 차이가 더 커서, 평탄한 내부 색차·변경 픽셀 수·평균차를 함께 제한한다. 2px 위치 오류는 실패했다. 최초의 단순 픽셀 허용치는 경계 차이 때문에 실패했고, 실제 차이 위치를 확인한 후 이 기준으로 분석했다.
- 소매 격자는 이전 모듈과 같은 원본·성별·밝은/어두운 피부·반팔/후드·서기/걷기/인사·5시점으로 대조했다. **120개 PNG의 모든 RGBA 픽셀이 완전히 일치**한다(`mesh-pixels/report.json`).
- `tools/verify-avatar-local-transform.cjs`: 80착장/방향/동작×3시점, 브라우저 기본 행렬 oracle·6변형 사례·잘못된 좌표 실패 대조 통과.
- `tools/verify-curated-fitting.cjs`: 현재 공개 상의24종×피부5색, 목120행·팔105행·복원72행, 오류0. 이 검사는 앞모습 접촉/복원을 다루며 전체 의류 미술 완료를 뜻하지 않는다.
- `tools/verify-avatar-world-layers.cjs`: 펫/효과 단일 소유, 몸과 같은 좌표계, 전체 정지/재개, 화면 밖 친구의 복귀, 착장 교체, 계정 불변, 장면 종료 정리 통과.
- `tools/verify-forest-plaza.cjs`: 배포본에서 등반·높이 공유·C/F·인사·재접속·다리·물 애니메이션 7묶음 통과. 원본 윤곽 검사는44보호 영역·10실패 대조·9편집본 통과.
- 학교/운동장7묶음, 실제 측면 학교 착장6조합(후드/한복/멜빵), 마을7묶음·13실제 경로·31꽃 출입 여유·모든F 왕복·더블탭 달리기까지 배포본에서 통과했다. 기존 학교 착장 도구의 예전 시작 화면 가정과 인라인 path 전용 판정을 현재 마을/캐시 그림에 맞췄다.

확대 미술 비교는 `before/sit-*.png`와 `after/sit-*.png`, 실제 마을 화면은 `world/`에 있다. 1366×768과1920×1080에서 중앙광장·개울·집 앞·비밀정원·달빛 나무집·하늘섬을 캡처했다. 최종 이동 검사 기록은 숲속마을 구현 검수 문서에 함께 적는다.

## 성능 측정과 남은 한계

같은1366×768 클라우드 Chromium에서 다른 무거운 브라우저 작업을 멈추고 측정했다. 기본 후드+치마·펫·천사 착장, 본인1명은 휴식, 친구29명의 포즈 표시 부하이며 실제30명 네트워크 접속이나 학교 기기 측정이 아니다. 안정화2.2초 후80프레임, 혼합은 일부 걷기와 실제1500ms 인사를1700ms마다 재생한다.

| 30명 표시 | 이전 중앙값 / p95 | 개선 후 중앙값 / p95 |
|---|---:|---:|
|휴식|50.1 / 66.7ms|33.3 / 50ms|
|친구29명 걷기|100 / 116.8ms|66.7 / 83.4ms|
|걷기·휴식·인사 혼합|99.9 / 266.7ms|50 / 83.3ms|

화면 내부 요소는57,780개에서23,700개로 줄었다. 마지막 수치는 화면 밖 표시 중지의 추가 이득을 포함하지 않는, 전원이 보이는 부하다. 원본 데이터는 `benchmark-before.json`, `benchmark-mesh.json`이다. 재현 도구는 `tools/measure-avatar-crowd.cjs`이며 기준 파일 폴더를 `QUIZ_AVATAR_BASELINE_FOLDER`로 주면 같은 조건으로 이전 코드도 측정할 수 있다.

**30명 전원 이동은 아직 성능 합격으로 처리하지 않는다.** 중앙값 약15fps로 추가 렌더링 개선이 필요하다. 이번 작업은 불필요한 계산·표시 비용과 큰 인사 끊김을 줄인 개선이다. 실제 그램/크롬북, 서로 다른 착장30명, 실제 Firebase30명 접속은 미검증이다. 기존 모든 의류를 새 기준 뼈대에 전환한 작업도 아니다.
