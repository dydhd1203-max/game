# 별빛 아바타 상점 검수

2026-10-07. 사용자 첨부 `별빛 아바타 상점 UI.png`의 화면 구성에 맞춰 일반 주소의 상점을 변경했다. 후속 요청인 버튼 모양과 글씨 표현도 포함한다. 기준 몸/일반 의류의 전환은 이번 UI 변경과 구분한다.

## 적용

- 왼쪽 실제 착장, 중앙 7개 상품 분류와 하위 16개 부위, 오른쪽 현재 착장 목록. 상품 목록은 기존 `publicItems`를 그대로 사용한다.
- 보라색 리본과 밤하늘·별 등불·나무 프레임·분홍 원형 무대는 참고 편집 원화 `assets/starlight-shop.png`다. 캐릭터와 상품, 문자, 가격을 배경에 합성하지 않았다.
- 돌아가기/닫기 분홍색, 분류 크림색, 선택 분류 보라색, 구매/입어 보기 초록색 버튼은 `starlight-shop-buttons.png`의 실제 광택·흰 테두리·아래쪽 두께를 사용한다. 원본 좌표와 해시는 `assets/starlight-shop.json`에 있다.
- 굵고 둥근 기존 `Jua` 한글 글꼴과 색 외곽선·그림자를 쓴다. 참고 그림의 영문 폰트 파일은 제공되지 않아 동일 폰트 자체의 복원은 아니다. 문구는 한국어 실시간 텍스트다.
- 오늘의 스타일은 기존 상품을 입어 보는 안내다. 참고 그림의 묶음 판매·할인율·가상 가격을 새 구매 기능으로 만들지 않았다. 카드 선택은 미리보기이며 실제 구매·무료 착용은 오른쪽 버튼에서 한다.
- 오른쪽 착장에는 실제 착용한 상품의 그림과 이름을 표시한다. 신발 썸네일은 맨다리 없이 신발만 표시하도록 기존 `QPAvatar.thumb`를 수정했다.
- 가격, 고정색, 성별 허용 목록, 과거 색상 구매 ID, 보유 기록, 피부색 가격과 영구 구매, 저장 경로는 그대로다. 뒤로/닫기는 마을로 돌아간다.
- 노트북은 세 열, 태블릿은 두 열, 휴대폰은 세로 흐름이다. 좁은 화면의 조작 버튼이 아바타 위로 겹치지 않도록 별도 배치한다.

## 검사

실행 도움: `/workspace/quiz-cloud/run-node.sh`, Chromium, HTTP 로컬 미리보기. 출력은 저장소 밖 `/workspace/quiz-cloud/starlight-shop-2026-10-07/`에 보관한다. 재생성 가능한 캡처는 Git에 넣지 않는다.

- `verify-starlight-shop.cjs`: 루프백 주소만 허용, 외부 요청 전부 차단, 실제 DB 객체가 `QPDemo.db`와 같은지 검사하고 체험 localStorage 접두사를 확인한다. 실제 Firebase는 쓰지 않는다. 16개 분류의 상품 개수/미리보기 무저장, 구매 1회 차감, 보유 재착용 무료, 피부색 100골드, 남녀 전환 시 구매 ID 보존, 잔액 부족, 키보드 선택과 마을 복귀를 실행한다.
- 최종 `verify-starlight-shop.cjs` 결과: PASS, 브라우저 오류 0개, 16개 분류와 위 결제/보유/키보드 동작 통과. 1920×1080, 1366×768, 1024×632, 768×1024, 390×844에서 가로 넘침·버튼 치수와 실제 클릭 수신 여부도 모두 통과했다. 상단 빈 헤더가 내 옷장 클릭을 막던 문제, 기존 모바일 CSS의 고정 346px 행이 성별·피부색 버튼을 덮던 문제를 발견해 수정했다.
- `verify-layout.cjs --shop-only`: 기존 레이아웃 도구의 상점 경로, 1920/1440/1366/1280/1024 너비와 남녀 선택 모달을 검사한다. 15개 단일 탭 가정은 7개 큰 분류+하위 탭으로 갱신했다. 이 옵션의 결과는 일반 퀴즈 전체 레이아웃 검사가 아니다.
- `verify-economy.cjs`: 기존 14개 원자적 결제/골드/피부색·과거 구매 호환 회귀 검사 통과.
- `check-source.cjs`, `build-deployment.cjs --check`: 151개 실행 파일과 원화 포함 여부·소스/배포본 일치 검사 통과. 로컬 `/배포용/`에서도 상점 회귀 검사 전체(16개 분류, 구매/보유/피부색, 5개 화면 크기)를 실행해 통과했다.
- 일반 상점의 수정 전후 화면은 같은 1366×768, 여자 기본 체험 계정, 동작 줄이기 조건으로 캡처했다. `before-shop.png`, `after-shop.png`. 최종 `after-shop.png`, `after-mobile.png`를 직접 열어 버튼 질감·문구·캐릭터·상품 배치를 확인했다. 모바일은 참고의 세 열을 세로로 재배치하며, 데스크톱 구도를 그대로 줄인 화면은 아니다.

## 적용 범위와 남은 아바타 작업

이번 변경은 **상점 UI와 신발 상품 썸네일**이다. 아바타의 얼굴·머리·실제 의류 렌더와 공유 공간 코드는 바꾸지 않았다. 일반 상점은 여전히 `QPAvatar.render`이고 `avatar=foundation` 연구 화면과 다르다.

이어서 조사한 결과, 원래 의류는 `avatar-clothes.js`의 앞 원화와 `avatar-pixel.js`의 방향별 그림, `avatar-cloth-mesh.js`의 큰 인사 소매를 사용한다. 새 몸의 `avatar-foundation-outfit.js`는 기본복 1벌만 연결한다. 일반 의류를 새 몸으로 옮기려면 앞·옆·뒤/접힌 소매 원화와 같은 관절을 공유하는 착장 어댑터, 장신구·펫/효과 보존, 실제 일반 상점/맵 검수가 필요하다. 모든 옷을 연구용 초록 반팔로 바꾸거나 UI 개선을 아바타 완료로 보고하지 않는다.

공개 사이트 배포는 GitHub 반영과 별도 확인한다. 로컬 HTTP 배포본 검수는 공개 Cloudflare 배포 성공을 뜻하지 않는다.
