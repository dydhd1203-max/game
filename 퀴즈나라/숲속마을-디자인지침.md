# 숲속 마을 디자인 지침

## 새 중앙 마을·그림체·빛과 물결 — 2026-10-05 최신

이 단락은 이전의 중앙광장 고정/반딧불 모험숲 확장보다 우선한다. 사용자 업로드 `마을`의 집·다리·물길을 중앙 허브로 쓰며 **반딧불 모험숲은 장면·출입구·지도·배포에서 제거**한다. 기존 중앙광장1~5의 원본 공원은 `picnicpark`(벚꽃 소풍공원)으로 보존한다. 중앙 마을↔학교 운동장↔교실, 중앙 마을↔비밀정원↔나무집↔하늘섬, 중앙 마을↔가을공원↔캠핑장↔나무집을 연결한다.

- 아바타의 공통 화면91.2px 크기는 유지한다. **집 문 높이와 아바타 키가 비슷해야 하며**, 마을 전체를 한 화면에 맞춰 줄이지 않는다. 현재 월드는4476.45×2565.75, 기본 카메라0.76이며 이동을 따라 화면이 움직인다. 문·계단·다리·입구와 본인/친구를 같은 실제 배율에서 비교한다.
- 사용자는 꽃이 과하고 기존 맵과 화풍이 다르다며 원화 편집을 명시적으로 허용했다. 전체 구도와 집·다리·물가·주동선을 유지하고 기존 공원/숲 교실의 부드러운 초록색·채색·얇은 윤곽에 맞춘다. 꽃은 현관과 주요 화단에 모으고, 연속된 꽃 울타리는 풀·낮은 덤불·여백으로 정리한다. 편집 원화와 제공 원본·참고 이미지는 출처와 해시를 구분한다.
- **후속 상세4장 모두를 각각 기존 화풍으로 편집하고 이어 붙인다.** 전체 조망 한 장을 편집해 늘리거나 상세4장을 참고로만 보관하면 요청을 충족하지 않는다. 현재 합본은2713×1555이며 상세1/3/4는1배,2는1.16배 등록이다. 원본4장·편집4장·최종 합본·접합부 보정본을 각각 보관한다.
- 중앙 나무·다리·물레방아처럼 겹친 사물은 한 번만 남기고 수관·줄기·울타리·계단 전체가 연결되도록 한다. 다른 위치의 두 구조를 반투명하게 섞어 이중 난간·유령 나무로 만들지 않는다. 경계를 바꾸는 보정은 사물 전체 윤곽까지 포함하고 넓은 원화 내부는 원래 픽셀을 유지한다.
- 원본 해상도와 월드 크기는 별개다.4장 기본 합본은2713×1555이며, 최종 실행 원화는5426×3110이다. **울타리 중첩·흐린 접합부는 작은 전체 보정본을 늘리지 말고 해당 부위를 따로 큰 crop으로 보강한다.** 현재 중앙 울타리/서쪽 벤치/동쪽 물가/북쪽 다리4곳이 상세 재편집이다. 나머지는 기본 합본의 보간이므로 전체를 손실 없는 원본 복원으로 설명하지 않는다. 배율1.65(앞선3보다45%축소)·기본 카메라0.76·공통 아바타91.2px를 유지하고 실제4개 문의 안쪽 높이와 투명 여백을 제외한 아바타 머리끝~발끝을15% 이내로 비교한다.
- `assembly.json`의4장별 기여 면적, 접합부 보정과 후속 상세 보강을 구분한다. `verify-central-village-art.py`는4장 기본 내부 픽셀·원본 해시·최종 텍스처 크기를 확인한다. 문과 아바타를 각각 확대하여 비율을 따로 바꾸지 않는다. 구도가 달라지면 길·나무·광원·물결·문·썸네일을 함께 재등록한다.
- 원화 편집 뒤에는 제거된 울타리/화단의 충돌을 지우고 새로운 나무 밑동과 수관을 다시 등록한다. 나무에 겹친 신체 부분만0.38로 표시하는 공통 규칙을 지킨다. 물 위를 걷거나 화단을 관통하는 직선 경로를 검사한다.
- 등불은 원화의 실제 발광 중심에 따뜻한 halo를 등록하고 주변 바닥에는 더 약한 빛을 둔다. 창문 빛은 창틀 위치에 맞춘다. 화면 전체를 어둡게 하거나 큰 흰 원·강한 반짝임으로 밝기를 과장하지 않는다. 캐릭터·이름·버튼은 광원 위에서 읽혀야 한다. 미세한 밝기 변화와 실제 전후 픽셀을 검사한다.
- 물결은 원본 수면 내부의 작은 패치만4Hz/4단계로 변형한다. 물가·다리·돌·오리·수련은 고정한다. 원화의 잔물결을 사용하며 새 강/물가를 그리지 않는다. 화면 밖 갱신 중지·지도/메뉴 정지·동작 줄이기·장면 종료 시 정리를 조명과 함께 검증한다.
- 새 장면 검사는 `tools/verify-central-village.cjs`, 전체 왕복은 `tools/verify-auto-portals.cjs`,9공간 지도는 `tools/verify-world-explorer.cjs`, 공통 아바타는 `tools/verify-school-avatar-size.cjs`로 한다. 제거된 모험숲 등반/버섯/룬 검사를 현재 합격 근거로 쓰지 않는다. 기능 검사와 실제 미술 확인·선명도 한계를 구분한다.

## 지도·상단 안내·살아 있는 환경 — 최신 추가 기준

- 작은 지도는 실제 전체 맵 그림 위에 나·같은 공간 친구·화면 범위·입구를 표시한다. `M` 또는 지도 버튼으로 큰 지도를 열고 `M`/Esc/닫기로 돌아온다. 장소를 고르면 현재 출입구 그래프에서 도출한 경로와 첫 입구 이름을 안내한다. 지도에서 목적지를 눌렀다고 자동 이동하거나 아직 없는 길을 표시하지 않는다.
- 지도는 현재9공간의 실제 장면 크기, crop, 카메라와 동일한 좌표를 쓴다. 교실·운동장 썸네일은 현재 조립 장면에서 만들어 옛 울타리·수업 화면·촬영 캐릭터를 넣지 않는다. 나와 친구의 위치는 현재 공간의 최신 상태로 갱신하고 다른 공간 친구를 이곳에 표시하지 않는다.
- 상단은 따뜻한 종이색 위 진한 글자와 이름 있는 아이콘 버튼을 사용한다. 제공 시트에서 UI를 추출할 때 회색 시트 배경을 남기지 않는다. 글자를 이미지로 만들지 않으며 소리 상태 갱신 뒤에도 이름이 유지되어야 한다. 1366×768·1920×1080과 좁은 노트북 폭에서 제목·친구 수·도구가 겹치거나 잘리지 않는지 직접 확인한다.
- 추가 UI 때문에 입장한 아바타가 화면 아래나 버튼 뒤에 숨어 시작하면 실패다. 지형 배율·발 위치·충돌은 유지하면서 카메라의 첫 화면만 안전한 범위로 맞춘다. 지도 모달은 키보드 초점을 관리하고 열려 있는 동안 이동·환경 효과를 멈춘다.
- 바람은 나무·꽃·풀 원본의 일부 잎에서 작게 표현한다. 이미 배경에 박혀 있는 나무를 다시 통째로 회전시켜 잔상/두 개의 윤곽을 만들지 않는다. 현재 방식은 경계 고정 픽셀 변형이며 줄기·뿌리·주변 바닥·가림 윤곽은 유지한다. 원본에 애초 없던 꽃을 있다고 가정해 바닥/벤치를 흔들지 않는다. 좌표 목록마다 원본 crop을 확대해 실제 소재를 확인한다.
- 불은 원래 모닥불 내부와 그 위 작은 불티만 움직인다. 받침대·장작 바닥·텐트·의자까지 늘리거나 원본을 흰색/검은색으로 지우지 않는다. 캠핑장·가을공원 원본 불을 구분해 위치와 주기를 검사한다.
- 두더지는 구름 위 버섯섬의 기존 구멍3개에만 둔다. 입구·바닥을 새로 그리지 않는다. **머리는 구멍보다 작아야 한다.** 현재 구멍의 실제 갈색 안쪽 폭30px에 대해 머리/앞발을 포함한 원화 폭을24px 이하로 맞추고 양쪽 흙 테두리가 보여야 한다. 원화의 실제 alpha 경계·방향 회전까지 비교하며 이미지 박스만 비교하지 않는다. 구름섬의 매끈한 면 채색과 둥근 음영을 따르고 세밀한 실사 털·과도한 유리 눈 표현은 사용하지 않는다. 원본 갈색 영역에서 측정한 세 중심은 `(197,121.75)`, `(645,281.75)`, `(533,377.75)`이며 장면의 실제 그림 배율2.1로 등록한다. 머리 내밀기→잠깐 둘러보기→내려가기→완전 숨기를 서로 다른 간격으로 재생한다. 몸의 아래쪽은 구멍 안으로 잘리고 원래 흙 테두리가 남아야 하며, 구멍 앞에 서 있는 동물처럼 보이면 수정한다. 생성한 원화는 제공된 맵 원본과 구분해 보관한다.
- 효과는 클릭·충돌·자동 출입을 가로채지 않는다. 화면 밖은 갱신하지 않고 숨긴 탭·지도/메뉴·동작 줄이기에서는 정지한다. 첫 로딩이 동작 줄이기여도 불티가 재생되거나 교실 창문이 불투명한 흰 사각형이 되지 않아야 한다. 장면 종료 때 canvas 메모리와 이벤트를 정리한다.
- 혼잡하면 장식 갱신만 낮춘다. 현재 기본20Hz/최대18개, 10명부터 약14Hz/12개, 20명부터 약11Hz/8개이며 아바타 입력·카메라·출입 속도는 줄이지 않는다. 전체 나무 수가 아닌 화면에 보이는 부분만 그린다. 1/10/30명 로컬 측정은 실제 Firebase 동시 접속·학교 기기 성능과 구분한다.
- 자동 검사는 그래프·위치·모달·프레임 변화·정지·정리와 UI 겹침을 검증한다. 최소 두더지의 상승/최고/하강, 원본 불 전후, 각 맵의 실제 카메라와 큰 지도를 직접 보고 판단한다. 자동 PASS는 잘못된 원본 crop이나 어울리지 않는 화풍까지 판정하지 않는다.

## 최신 공통 표시·나무 부분 가림 — 2026-10-04

마을광장에서 보이는 아바타 크기를 교실·운동장과 연결된7개 마을 공간 모두에 적용한다. 렌더 입력120px와 실제 화면91.2px 기준을 구분하고 공간별 카메라 배율을 보정한다. 걷기337.5px/s·달리기506.25px/s, 통행 반경7이다.

나무 원본은 그대로 두고 아바타 중 **나무와 겹친 부분만 반투명**하게 표시한다. 머리·팔이 밖에 있으면 그 부분은 선명해야 한다. 전체 캐릭터 opacity, 일부 나무만 불투명 전경으로 덮는 방식, 사각형 전체를 지우는 마스크는 쓰지 않는다. 수관·줄기 윤곽과 앞뒤 깊이를 공통 등록하며, 원본 좌표·crop·배율을 변환한다. 저목·꽃밭·자전거·하늘은 나무 수관으로 등록하지 않는다. 나무 앞에서는 정상 표시, 두 수관 아래에서는 한 번만 반투명, 이름/말풍선과 사다리·높은 데크는 별도 판정을 확인한다.

`map-avatar-display.js`가 공통 크기와 부분 가림을 담당한다. 지도에 나무를 추가·이동·확대하면 해당 가림 데이터도 함께 바꾸고, 실제 화면에서 수관의 위·아래·좌·우 경계와 노출된 머리/팔/다리를 검수한다. 과거 주황 나무의 전체 전경 알파 검사와 전체 캐릭터 투명도 PASS를 현재 부분 가림의 통과 근거로 사용하지 않는다.

## 최신 원본 맵 복원·두 공원 연결 — 2026-10-04

사용자의 후속 요청으로 중앙광장은 **중앙광장1~5가 겹쳐 보여 주는 한 원본 맵**의 구도를 유지한다. 추가 집·큰 나무·개울·우물·식생 덧붙임은 실행 장면에서 제거한다. 기존 원본 연못·벚나무·탁자·커피 자판기·선착장은 살리고, 요청된 학교가는 길 표지판만 입구 옆에 둔다. 과거 추가 나무/개울 검사 PASS를 현재 광장 완료 근거로 쓰지 않는다.

100% 원본 ZIP 여섯 개/사진20장은 `assets/forest-village-library/original-resolution/`에 보존한다. 겹치는 부분으로 메뉴·이름·촬영 캐릭터를 제외하고 동일 물체를 맞춘다. 사진1~5를 별개의 광장으로 붙이지 않는다. 나무·울타리·그림자가 접합선에서 잘리면 실패다. 모든 사진에 가려진 구석은 전체 사물을 보존한 기존 자료를 사용하고 그 범위를 기록한다. 해상도 복원율을100%라고 과장하지 않는다. 캠핑장4만 약0.218% 촬영 배율 차이를 명시적으로 정합하며 다른 사진은 정수 위치로 복사한다.

현재 연결은 중앙광장↔가을공원↔캠핑장↔달빛 나무집, 중앙광장↔비밀정원↔달빛 나무집↔하늘섬, 중앙광장 오른쪽↔반딧불 모험숲이다. 낮/단풍/황혼/밤을 한 바닥에 사각형으로 붙이지 않고 작은 방향 화살표가 있는 접촉 입구로 연결한다. 가을공원의 텐트·그네·벤치, 캠핑장의 모닥불·캠핑카·호수 구도를 보존하고 새 집/나무를 반복하지 않는다. 호수·먼 산·하늘을 보행 지면으로 판정하지 않는다.

후속 사용자의 ‘오른쪽에 신비로운 놀이터를 자율적으로 꾸미기’ 요청에 따른 새 모험숲은 원본 해상도 복원과 구분한다. 버섯6개·달빛 돌3개·나무 위 구름다리와 ↑↓ 사다리를 가진 별도 공간이며, 생성한 원화를 원본 사진인 것처럼 표시하지 않는다. 원본 보관/합성/생성/실행 상태는 각각 기록한다.

현재 검사는 `verify-original-forest-maps.py`(픽셀/출처/제외 영역), `verify-forest-village.cjs`(7공간/현재 구도/이동/미술 캡처), `verify-auto-portals.cjs`(접촉 왕복), `verify-forest-climbing.cjs`(모험숲 실제 등반/놀이)다. `verify-forest-plaza.cjs`는 현재 마을 검사로 연결하는 호환 진입점이며 퇴역한 개울을 검사하지 않는다. 실제 기록은 [100% 원본과 공원 검수](숲속마을-원본100-검수.md)를 따른다.


갱신: 2026-10-03. **이 문서는 현재 숲속 마을의 단일 제작·미술 검수 기준이다.** 사용자의 최신 요청은 먼저 지침을 세운 뒤 제공한 실제 게임 맵들을 선별·연결하는 것이다. 예전의 ‘옷 가게를 먼저 만들고 숲 마을은 마지막’, ‘중앙 분수 필수’, ‘`map.zip`이 최우선 참고’ 조건을 대체한다. 공간의 현재 구현 상태는 [메타버스 작업 인계](메타버스-다시만들기.md), 아바타는 [아바타 제작 기준](아바타-제작기준.md)을 따른다.

**현재 구현·실행 결과는 [숲속마을-구현검수.md](숲속마을-구현검수.md)에 따로 기록한다.** 이 문서의 요구 전체를 자동 검사 PASS로 간주하지 않는다. 기존 교실·운동장·아바타·상점 기능·재화·구매·저장 데이터와 다른 작업의 변경을 보존한다.

이번 환경의 원본 대응·해시는 `assets/forest-village-library/sources.json`, 원본은 같은 폴더의 `originals/`에 보관되어 있다. 파일이 로컬에 있다는 사실과 Git 등록·게임 적용·배포 상태는 별도로 확인한다. 이전 `map.zip`과 [전체 소재 보관함](assets/library/index.html)의 집·마을·풀·물·소품은 연결 부위와 부족한 생활 요소를 보완하는 후보로 사용한다. 파일명만 보고 사용자 제공 자료라고 판단하지 않고 출처를 확인한다.

- **먼저 원본 구도를 보존할 구역을 정한다.** 집–마당–울타리–길 또는 나무–쉼터–물가처럼 이미 자연스러운 묶음을 기준으로 연결한다. 모든 맵을 낱개 소품으로 해체하여 임의로 흩뿌리지 않는다.
- 깨끗한 게임 영역은 넓은 조각으로 재사용할 수 있다. 원본의 UI·로고·글자·촬영 아바타까지 들어 있는 화면 전체를 배경으로 붙이지 않는다. 실제 캐릭터가 사물 뒤로 가야 하는 곳은 필요한 전경과 충돌을 분리한다.
- 원본 바이트·파일 해시를 보존한다. 사용 영역, 잘라낸 윤곽, 배율, 지면 기준점, 배치 위치와 용도를 기록해 원본 문제와 조립 문제를 구별한다.
- 새로 보이는 맵 그림은 제공 에셋으로 구성한다. 임의 SVG 도형·새 AI 이미지로 길·지형·건물을 대신하지 않는다. 원본의 부분 표시·클리핑·배치와 보이지 않는 충돌·경로 계산은 가능하다.
- 조명·시점이 다른 맵은 먼저 어울리는 영역을 선별한다. 필요한 경우 숲의 깊이·높이 변화·구역 전환으로 차이를 설명하되, 전환 연출로 잘못된 접합을 가리지 않는다. 무리한 늘이기·회전·색 덮기로 원본 그림체를 훼손하지 않는다.
- 개별 투명 PNG를 일괄 필수로 요구하지 않는다. 꼭 필요한 연결 부품이 가려졌거나 맞는 방향·해상도의 원본이 없을 때만 **부족한 부위·시점·용도**를 구체적으로 요청한다. 전체 배치 참고는 50% 축소본도 사용하며 추출 정보가 부족한 부분만 100% 자료를 요청한다.

## 3. 전체 배치와 학교 연결을 먼저 정한다

기본 이동 관계는 **만남 광장 ↔ 집과 골목 ↔ 기존 운동장 ↔ 학교의 두 출입구에서 F ↔ 기존 교실**이다. 탐험길은 광장·골목에서 갈라져 특별한 장소로 이어진다. 마을에서 교실로 곧바로 보내 학교 진입 과정을 생략하지 않는다.

- 학생의 기본 입장은 `SCREENS.village`다. 마을↔운동장 및 학교 두 문↔교실 왕복을 계속 회귀 검사한다. 지정 수업 링크의 직접 참가는 보존한다.
- 먼저 광장, 생활 골목, 운동장으로 가는 주동선, 탐험 갈래, 돌아오는 길, 구역 사이 접합부를 전체 배치에 표시한다. 큰 마을을 빈 땅과 긴 이동 거리로만 늘리지 않는다.
- 광장은 친구를 찾고 대화·인사·C 앉기를 하기 쉬운 만남 장소다. 중심 볼거리는 실제 원본과 동선에 맞춰 고르며 분수를 필수로 두지 않는다. 입장 지점과 사람이 모일 공간은 장식의 충돌 밖에 둔다.
- 집은 길을 향한 현관, 작은 마당, 이웃집과의 관계를 가진다. 골목은 완만하게 굽고 다음 집·나무집·정원 입구가 조금씩 보이게 한다. 불필요한 갈림길과 의미 없는 막다른 길을 만들지 않는다.
- 운동장 경계에 맞는 진입·복귀 지점을 마련한다. 기존 운동장과 학교·교실 원화 배치를 통째로 바꾸지 않는다. 학교 정문과 동쪽 출입구의 F 복귀, 문 밖 F 무동작, 길게 누르거나 연타할 때 즉시 왕복하지 않는 동작을 보존한다.
- 현재 맵 아바타 96px, 걷기 225px/s, 같은 방향키 두 번 누르고 유지하는 달리기 337.5px/s를 기준으로 크기와 이동 시간을 점검한다. 사물 축척 문제를 아바타 크기나 이동속도 변경으로 해결하지 않는다.
- 여러 학생이 모이는 공간을 확보하고 21~30명 규모의 화면 혼잡을 별도 살핀다. 로컬 표시 부하·이름 겹침 검사와 실제 Firebase 다중 접속 검증을 구분한다.

## 4. 사물은 ‘놓인 이유와 지면’을 갖는다

배치할 때 이미지 사각형만 맞추지 않는다. **보이는 윤곽, 땅에 닿는 부분, 통행을 막는 부분, 앞뒤로 가리는 부분, 이용하는 위치**를 함께 맞춘다.

| 항목 | 배치 규칙 | 어색함으로 판정할 예 |
|---|---|---|
| 축척·시점 | 96px 캐릭터와 문·계단·의자·나무를 함께 비교한다. 같은 지면은 공통 축척이며 원본 원근을 확인한다. | 위쪽이라는 이유로 집이 작아짐, 문보다 큰 아바타, 서로 다른 경사의 지붕을 억지로 맞춤 |
| 지면·높이 | 건물 기초·나무 밑동·벤치 다리·울타리 기둥의 접점을 맞춘다. 계단·데크·섬은 높이를 따로 관리한다. | 공중에 뜬 집, 잔디에 묻힌 의자, 데크 위 소품의 발이 아래 지면에 붙음 |
| 출입 방향 | 현관과 계단 끝이 실제 길·마당을 향하며 접근·도착 자리가 비어 있어야 한다. | 문 앞이 울타리, 길과 떨어진 계단, 문에서 나오자마자 나무에 끼임 |
| 보행·충돌 | 건물·줄기·벤치·돌의 바닥은 길 밖에 둔다. 수관이 길 위로 드리우는 것과 줄기가 길을 막는 것을 구분한다. | 보이는 길이 막힘, 닫힌 울타리를 통과함, 길 가운데 벤치가 놓임 |
| 앞뒤 가림 | 지면 기준과 실제 높이에 맞춰 아바타가 집·나무·데크의 앞뒤를 지난다. 원본 한 장 안의 필요한 전경을 분리한다. | 뒤로 걸어도 지붕 위에 표시됨, 앞으로 나와도 가려짐, 다리 밑·위가 뒤바뀜 |
| 용도·관계 | 벤치가 쉴 풍경·대화 공간을 향하고 화분·우편함·도구가 해당 집·정원에 속하게 한다. | 벽만 보는 벤치, 나무 몸통에 박힌 화분, 주인 없는 소품이 길에 흩어짐 |
| 빛·경계 | 원본의 광원·접촉 그림자·바닥색을 비교하고 연결 가능한 소재를 선택한다. | 사물마다 빛 방향이 다름, 잘린 검은 그림자, JPEG 사각 바탕·밝은 테두리가 남음 |

배치 기록에는 원본/사용 영역, 구역·역할, 배율·방향, 지면 기준점과 높이, 충돌, 가림 순서, 필요한 상호작용·접근점을 남긴다. 비상호작용 장식에는 없는 기능을 기록하지 않는다. 사물 하나의 위치를 바꾸면 연결된 충돌·접근점·그림자도 함께 확인한다.

## 5. 풍성함은 장소의 묶음과 밀도 변화로 만든다

**휑한 공간을 꽃 몇 개로 메우거나 모든 빈 곳을 채우는 방식으로 해결하지 않는다.** 큰 볼거리, 중간 크기 생활 공간, 작은 디테일이 연결되어야 한다.

- 주택은 ‘집+현관길+작은 마당+그 집에 맞는 소품’, 쉼터는 ‘그늘+앉거나 모일 자리+바라볼 풍경’처럼 만든다. 실제 제공 소재 안에서 조합하며, 예시에 있는 소품이 없다고 임의 제작하지 않는다.
- 광장·길은 사람이 머물고 지나갈 여유를 두고, 마당·정원·숲 가장자리는 크고 작은 원본을 겹쳐 풍성하게 만든다. 전경의 식생, 중경의 생활 공간, 후경의 숲이 이어지게 한다.
- 넓은 잔디·수면도 목적, 가장자리의 구성, 시선이 향하는 대상이 있으면 완성된 풍경이다. 넓기만 한 단색 바닥과 멀리 떨어진 소품 몇 개를 ‘여백’이라고 정당화하지 않는다.
- 전체 조망뿐 아니라 **카메라가 한 화면씩 이동할 때** 살핀다. 연속된 여러 화면에서 집·쉼터·목적지·풍경 변화 없이 바닥만 지나면 크기나 구역 배치를 다시 조정한다.
- 큰 사물 사이에 중간 크기 묶음이 빠져 휑한지 먼저 확인한다. 작은 꽃·돌의 개수를 늘리는 것으로 집과 집 사이의 관계를 대신하지 않는다.
- 골목 입구·모퉁이·물가·지도 끝·서로 다른 원본의 연결부까지 완성한다. 대표 광장만 풍성하고 나머지가 비어 있으면 완료하지 않는다.
- 밀도 수치나 사물 개수는 빈 구간을 찾는 보조 자료다. 모든 화면에 같은 점유율을 강제하거나 자동 점수만으로 미술 합격을 선언하지 않는다.

## 6. 같은 에셋의 반복이 풍경을 지배하지 않게 한다

- 같은 집·특징적인 나무·큰 버섯을 일정한 간격이나 격자로 늘어놓지 않는다. 색 변경·좌우 반전·미세한 크기 변경만 한 복제는 새 종류로 세지 않는다. 글자·광원·문 방향이 있는 원본을 무조건 반전하지 않는다.
- 같은 원본을 재사용하더라도 주변의 마당·식생·기능·묶음과 거리의 리듬이 달라야 한다. 이웃한 화면을 걸어서 볼 때 같은 조합이 계속 나타나는지 확인한다.
- 생활 골목·정원·나무집·버섯 공간은 각각 다른 실루엣과 중심 풍경을 가진다. 구역 이름만 바꾸고 같은 나무·벤치 세트를 반복하지 않는다.
- 잔디·길·숲 배경 같은 반복 소재는 사용할 수 있다. 타일 경계, 같은 꽃 점, 규칙적인 그림자가 격자처럼 드러나지 않는지 기본 배율에서 확인한다. 꽃·바위를 늘어놓아 반복이나 이음새를 숨기지 않는다.
- 배치 목록에서 원본별 사용 횟수와 가까이 모인 복제·동일 소품 묶음을 찾아 검토한다. 많이 쓴 원본을 무조건 실패로 보지 말고, 화면의 단조로움과 장소의 구별 여부를 함께 판정한다.
- 사용 가능한 종류가 부족하면 해당 구역 크기·묶음을 먼저 조정하고 필요한 원본을 구체적으로 요청한다. 다양성 부족을 조용히 대량 복제로 대체하지 않는다.

## 7. 길·숲·물가·높낮이로 맵을 자연스럽게 잇는다

- **색과 조명이 맞는 구역만 연속 지면으로 잇는다.** 잔디·수관·길·물가의 색온도, 밝기와 광원을 실제 이동 화면에서 비교한다. 어울리지 않으면 입구·목적지·출구·복귀 위치가 명확한 F 텔레포트로 연결한다. 전체 색 덮기나 큰 그림자로 접합을 감추지 않는다. 낮의 정원끼리도 색이 다르면 이 원칙을 적용한다.
- 연결부에는 양쪽 원본의 길 폭·바닥색·그림자·나무 크기·물가 높이를 함께 놓고 확인한다. 사각 맵의 모서리와 직선 잘림이 보이면 접합이 끝난 것이 아니다.
- **길 → 다리 → 길**이 같은 보행면으로 이어져야 한다. 다리 밑의 수면을 유지하고 물 위에 포장을 깔지 않는다. 다리 그림을 잠시 숨긴 지면 검사와 실제 횡단을 모두 확인한다.
- 숲 가장자리는 큰 나무–관목–풀과 빈틈이 자연스럽게 이어지게 하되 길·입구는 열어 둔다. 겹침으로 잘림을 감추기 전에 원본과 지형 연결을 바로잡는다.
- 하늘섬은 떠 있는 높이·가장자리·접근과 복귀를 읽을 수 있어야 한다. 섬 밑면을 평지 연못에 쓰지 않는다. 오르는 경로 또는 명확한 전환 지점을 전체 배치에서 정하고, 제공 소재와 현재 조작으로 가능한지 확인한다.
- 큰 나무집은 밑동·출입구·계단/데크가 연결되어야 한다. 원본에 보인다는 이유만으로 사다리 타기 기능이 있다고 보고하지 않는다.
- 비밀정원은 약한 단서, 따라갈 수 있는 갈래길, 도착했을 때의 풍경·쉼터를 갖춘다. 숨겨 놓기만 하거나 막다른 곳에 장식 하나를 놓는 것으로 끝내지 않는다.
- 큰 버섯은 일상 집·골목과 대비되는 특별한 풍경으로 사용한다. 기능이 있는 플랫폼인지 바라보는 지형인지 구별하고, 오를 수 없는 그림에 조작 안내를 붙이지 않는다.
- 실제 이용 가능한 문·계단·통로에는 접근과 돌아오는 경로가 있어야 한다. 장식용 문·창은 시각적으로 구별하고 허위 버튼·상호작용 안내를 달지 않는다.

### 사물의 전체 윤곽 보존 — 잘린 나무 재발 방지

2026-10-03 첨부 비교 화면의 결함은 내부 접합선에서 수관·줄기가 직선으로 끊기고, 잔디 패치가 주변 나무 일부를 지운 모습이다. 다음을 나무·덤불·울타리·벤치·집·그림자 모두에 적용한다.

- 맵 조각의 경계를 사물 한가운데로 통과시키지 않는다. **수관–줄기–밑동–접촉 그림자 전체**를 포함하는 영역을 선택하고, 실제로 가려진 원본을 억지로 복원하지 않는다. 필요한 전체 원본이 없으면 경계를 옮기거나 별도 공간으로 연결한다.
- UI·촬영 캐릭터·사물을 지울 때 주변 사물까지 덮는 사각 잔디 패치를 금지한다. 지울 대상의 전체 윤곽과 보호할 주변 사물을 각각 표시한다. 남은 반쪽 줄기·뿌리·의자 다리·울타리 기둥도 결함이다.
- 전경 분리와 마스크에서는 소스 crop, 알파, 배율, 오프셋, 레이어별 단독 화면을 확인한다. 원본에서 완전한 사물이 조립 뒤 잘리면 추출 또는 조립 문제로 기록한다. 임의 그림·블러·큰 그림자·덤불 덧대기로 숨기지 않는다.
- 원본 가장자리에 원래 걸쳐 있는 숲과 **새로 만든 맵 내부 절단**을 구분한다. 카메라 화면 경계의 정상적인 가림은 이동해 전체를 다시 보아 판단한다. ‘원래 화면 밖’이라는 이유로 접합부의 잘린 사물을 예외 처리하지 않는다.
- 자동 검사에는 원본 대비 보호 영역의 픽셀 보존, 추출물 크기/해시, 기록된 수정 마스크 밖 변경, 전경의 기준점 일치와 자원 로딩을 포함한다. 나무 절반을 잔디로 지우거나 투명하게 자르는 **실패 대조**도 반드시 검출해야 한다.
- 모든 수정 마스크 주변을 확대해 원본/추출본으로 비교하고, 실제 96px 플레이 화면에서 경계 양쪽을 걸으며 앞뒤 가림·남은 조각·색 경계까지 직접 본다. 픽셀 검사 PASS는 등록하지 않은 모든 사물의 미술 합격을 보장하지 않는다.

### 꽃밭·화단 배치

- **사용자 추가 요청(2026-10-03): 제공 에셋을 현재 맵 화풍에 맞게 다듬을 수 있다.** 원본은 보존하고 수정본의 출처·참고 맵·수정 내용을 따로 기록한다. 색상만 맞추지 말고 시점, 외곽선, 명암, 형태, 축척, 접촉 그림자를 함께 조정한다. 이는 제공 사물의 화풍 편집 허용이며 새 사물·새 맵을 임의 생성하는 허용으로 확대하지 않는다. 아래 화풍 차이 때문에 무조건 제외하던 판단보다 이 최신 요청을 우선한다.
- 화풍 편집은 대표 한 종류부터 원본/수정본/기존 맵 사물을 같은 크기로 비교한다. 원본 픽셀 추출과 생성 편집을 혼동하지 않으며, 편집본을 원본 그대로 재사용했다고 보고하지 않는다. 실제 맵의 인접 사물과 96px 아바타를 함께 보고 확대 화면도 확인한 후 적용한다.
- 집 앞은 돌봄이 느껴지는 작은 화단, 물가는 낮은 들꽃, 비밀정원은 조금 더 풍성한 꽃밭으로 구분한다. 중심 꽃 1~2색과 작은 보조 꽃을 묶고, 모든 색·종류를 한곳에 섞지 않는다.
- 꽃잎·잎·줄기·뿌리·접촉 그림자를 함께 추출한다. 옆 돌이나 회색 시트 배경이 붙거나 꽃잎 끝이 잘린 추출물을 배치하지 않는다. 원본 색을 임의로 바꿔 종류를 늘리지 않는다.
- 길·문 앞·F 입출구·착지점·모임 중심은 비운다. 화단은 집의 마당과 잔디 경계를 따르고 물 위, 나무줄기 중간, 벤치 좌석 위에 놓지 않는다. 낮은 꽃도 땅의 기준점으로 앞뒤 순서를 정한다.
- 같은 꽃 덩어리를 등간격 줄 세우거나 같은 화단 전체를 복제하지 않는다. 원본의 다른 꽃을 조합하고 무리의 크기·간격·방향에 이유를 둔다. 반복을 숨기려 과도한 크기 변경·회전·블러를 하지 않는다.
- 기존 꽃 시트가 있어도 화풍·명암·축척이 맞는지 먼저 본다. 현재 맵의 꽃을 재사용한 곳과 별도 보관함에만 있는 꽃 종류를 구분해 보고한다.
- 추출물의 원본 RGB 보존, 출입구/복귀점과 꽃 배치의 겹침을 검사한다. 실제 96px 화면과 확대 화면에서 꽃잎 잘림·바닥의 사각 경계·길 침범·반복·앞뒤 가림을 직접 확인한다.

## 8. 사람·움직임·읽기 공간

- 아바타와 친구의 이름·대화가 집·수관·UI 아래에서 읽히는지 확인한다. 친구에게 가까이 가서 인사하고 앉을 공간을 두며, 가짜 접속 학생을 실제 친구처럼 표시하지 않는다.
- PC·노트북 학생 화면을 우선한다. 1366×768과 1920×1080 기본 카메라에서 길·입구·아바타가 보이게 하고 한 화면에 마을 전체를 넣으려고 축소하지 않는다.
- 초등 고학년이 좋아할 작은 발견과 정교한 생활감을 살린다. 모든 사물에 얼굴·반짝임·큰 안내판을 붙이거나 UI를 확대해 유아적인 인상을 만들지 않는다.
- 물결·잎·꽃·등불 등 원본에서 분리 가능한 일부만 자연스럽게 움직인다. 건물·돌·물가·줄기·뿌리·충돌 위치는 고정하고 모든 사물을 같은 주기로 흔들지 않는다.
- 이름·대화·문제·조작 버튼은 차분한 바탕에 읽기 쉽게 둔다. 장식이나 수관이 필수 입구·다리 착지점·탐험 단서를 계속 가리지 않는지 이동하며 본다.
- 화면 밖·숨긴 탭·모달·동작 줄이기 설정을 반영하고 장면 종료 때 효과·이벤트·구독을 정리한다. 성능 때문에 필요한 이동 반응을 늦추지 않는다.

검사는 정상 장면만 통과시키는 형태로 만들지 않는다. 격리된 검사 장면에서 아래 결함을 의도적으로 넣어 검사 또는 미술 검토가 실제로 문제를 찾는지 확인한다. 실제 맵이나 사용자 저장 데이터에 결함을 남기지 않는다.

- 건물 지면 기준점을 옮겨 공중에 뜨게 한 경우.
- 나무 밑동·벤치 충돌을 길이나 문 앞에 놓은 경우.
- 문이 울타리를 향하거나 계단 끝이 실제 보행면에서 떨어진 경우.
- 집 사이의 중간 크기 공간 묶음을 빼 연속 화면이 휑해진 경우.
- 같은 집·나무·소품 세트를 등간격으로 복제한 경우.
- 수관·지붕의 순서를 바꿔 아바타가 항상 위에 그려지거나 앞에서도 가려지는 경우.

미술 항목을 완전 자동 판정한다고 약속하지 않는다. 자동으로 찾을 수 없는 어색함은 고정된 비교 화면과 실제 이동 영상으로 검토한다. 사용자가 발견한 새 결함은 원인·수정·같은 조건의 비교와 함께 이 지침 및 해당 회귀 검사/미술 항목에 추가한다.

## 12. 화풍 보정·전경·표시 성능의 후속 검수

- 제공 집을 화풍 보정할 때 지붕·현관·계단·테라스의 배치를 식별 가능하게 유지한다. 원본, 생성 편집 시트, 실제 crop/축소본의 해시와 배율을 구분해 기록한다. 투명 여백을 포함한 전체 비율을 지키고, 밑동을 기준으로 재배치한다. 큰 미리보기만 보지 말고 맵 96px 아바타 옆에서 문·나무·꽃과 비교한다.
- 사물을 지운 자리의 잔디는 직선 테두리·색 사각형·옛 사물의 잔상을 검사한다. 필요한 경우 원본 잔디끼리만 좁은 지면 연결 영역에서 섞는다. 제거할 사물 내부는 완전히 제거하고, 주변 윤곽과 기록된 마스크 바깥 원본을 보호한다.
- 현재 나무 부분 가림 마스크는 배경 원본과 crop·위치·배율을 정확히 공유한다. 과거 불투명 전경 재복사는 사용하지 않는다. CSS `z-index`는 **정수**여야 한다. 특히 1.8·2.1배 맵의 바닥 좌표를 그대로 소수 z-index에 쓰지 않는다. 전경을 2px 옮긴 실패 대조를 검출하고, 아바타가 실제로 설 수 있는 앞·뒤 좌표에서 캡처한다. 이동 목적지가 충돌로 거부돼 입장점으로 돌아간 화면을 가림 검수로 사용하지 않는다.
- 충돌은 선물 상자·건물·나무의 바닥을 막되, 위쪽 그림 전체를 사각형으로 막지 않는다. 추가 충돌 이후 학교·정원·사다리·전망대의 실제 이동 경로를 다시 실행한다.
- 성능 변경은 아바타의 원화·관절·착장을 바꾸지 않는다. 브라우저 기본 좌표 계산과 최적화 계산을 비교하고, 같은 성별·피부·착장·방향·시점·배율의 화면을 비교한다. 색 차이는 투명도까지 합성해 판단한다. 휴식 중인 친구의 느린 호흡을 분산 갱신하더라도 걷기·달리기·인사·방향 전환·새 착장은 즉시 반영한다.
- 성능 측정 때는 다른 무거운 브라우저 검사를 병렬로 실행하지 않는다. 1명·10명·30명과 휴식/이동·인사를 구분하고 중앙값·느린 프레임을 함께 기록한다. 클라우드 로컬 가상 아바타 측정은 실제 학교 기기·Firebase 동시 접속 검사와 별개다. 개선 비율만으로 성능 합격을 선언하지 않는다.

## 13. 중앙광장·오르는 나무·흐르는 개울

2026-10-03 추가 요청과 `4622.jpg`를 반영한다. 같은 참고 원본은 `assets/water-library/originals/water-73dbad95a5ece375.jpg`에 있다. 청록 지붕, 따뜻한 창문, 나무에 기대어 있는 방·데크, 풍성한 꽃과 맑은 물을 분위기 기준으로 삼는다. 참고 그림의 원근을 현재 게임 바닥에 그대로 붙이지 않는다.

- 광장의 중심은 **실제로 올라가 머무는 큰 나무**다. 사용자 제공 나무집의 사다리·계단·데크 형태를 살려 낮 마을 화풍으로 편집한다. 입장점과 친구들이 만나는 앞마당은 비우고 꽃·우물은 가장자리의 정원에 둔다. 기본 카메라에서 중심 볼거리와 내 캐릭터가 함께 읽혀야 한다.
- 나무의 접지는 뿌리, 충돌은 실제 밑동에 맞춘다. 지상/아래 데크/위 방의 이동면을 구분한다. 나무를 클릭했다고 수관 속 아무 좌표로 걷거나, 데크에서 바닥으로 떨어지지 않는다. F로 실제 사다리·계단을 연속 이동하며 사다리는 등반, 계단은 걷기 자세를 사용한다. 그림에서 연결되지 않은 방에 갈 수 있다고 안내하지 않는다.
- 난간 전경은 동일한 나무 원본의 정확한 위치·배율을 공유한다. 바닥 아바타의 나무 뒤 가림과 데크 위 아바타의 난간 가림을 따로 검사한다. 나무 전체를 전경으로 겹쳐 올라간 아이를 통째로 숨기지 않는다.
- 등반 중 클릭·앉기·인사·F 반복, 모달/탭 정지·재개, 새로고침·장면 복귀를 검사한다. 중간 저장은 안전한 끝점으로 복원하고 도착한 데크 높이는 보존한다. 친구에게 중간 등반 높이도 보여야 한다. 작은 중간 발판에 앉을 공간이 없으면 위 방의 넓은 바닥을 사용한다.
- 개울은 제공 물 원본을 편집한 물가·낙차·수면을 사용한다. 수면 내부만 움직이며 돌·풀·다리·충돌은 고정한다. 물 영역은 걸을 수 없고 실제 다리의 판자 방향을 따라 통행해야 한다. 다리는 기존 길과 만나야 하며 보행로가 수면에서 끊기면 안 된다.
- 수면 연속 프레임의 변화와 다리 판자·물가 돌의 픽셀 고정을 각각 검사한다. 움직임 줄이기·숨긴 탭·모달에서는 효과를 정지한다. 물 아래로 꽃·잔디 사각형을 덧대어 잘린 물가를 가리지 않는다.
- 작은 꽃은 파란 종꽃·양귀비·노란 꽃 등 제공 종류를 화풍에 맞게 보정하여 집 앞, 물가, 큰 나무 둘레에 서로 다른 묶음으로 둔다. 원본과 편집 시트·crop·배율·바닥 기준점은 기록한다. 길·F 접근점·사다리 발판·도착점 위에 놓지 않는다.
- 꽃무리는 같은 간격의 작은 섬처럼 흩뿌리지 않는다. 물가·의자·집 앞처럼 기준 사물을 정하고 높은 꽃 뒤에 낮은 꽃을 모아 실제 화단으로 읽히게 한다. 꽃을 놓기 전후 기본 카메라를 비교해 배경 잔디 위에 떠 보이는지, 의자 다리/그림자를 덮는지, 통행 여유가 남는지 확인한다. 기존 의자를 살리면 밑동 충돌과 앞쪽 접근 경로도 함께 확인한다.
- 큰 볼거리를 넣기 위해 기존 사물을 옮기거나 지울 때 **전체 사물**을 다룬다. 인접 벤치의 다리, 의자의 발, 꽃덤불, 울타리, 그림자까지 확대하여 확인한다. 복원할 사물은 온전한 원본으로 같은 위치에 복원하고, 새로운 지면과 기존 길 사이에 다각형 잔디 모서리·나무 잔상·반쪽 사물이 남지 않게 한다. 보호 픽셀 회귀 검사와 직접 확대 검수를 함께 한다.

- 같은 배경 위에 재등록하는 전경 crop과 다른 장소로 옮기는 단독 에셋을 구분한다. 전경용 큰 마스크를 다른 잔디색의 구역에 그대로 옮기지 않는다. 단독 꽃나무는 수관·줄기·꽃잎 전체를 포함하고 원래 울타리·벤치·잔디가 알파에 남지 않는지 대비색 배경과 실제 새 지면에서 확인한다.
