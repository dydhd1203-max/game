# 퀴즈나라 개발·실행 환경

갱신: 2026-10-01

현재 학생 기본 입장은 `SCREENS.village`의 햇살숲 마을입니다. 교실 링크가 있으면 해당 수업으로 직접 들어갑니다. 이번 작업에서 배포는 미뤄 두었으므로 기준 소스만 최신이며 기존 `배포용/`은 이전 묶음입니다. 다음 배포 준비 때 `node tools/build-deployment.cjs`로 전체를 갱신합니다.

## 숲속 마을과 실내 상점

`village-scene.js`는 2700×1950의 지형·계단·다리·충돌·문과 원화 앵커를 관리합니다. `village-world.js`/`.css`는 작은 SD 아바타의 실제 이동, 따라가는 카메라, 길 찾기, 발견과 대화를 담당합니다. 돌계단과 굽은 나무계단은 연속 높이를 사용하고 통나무의 줄사다리는 정해진 진입점까지 걸어간 뒤 실제 발 위치·높이를 연속 갱신합니다. 점프가 절벽·물을 우회하지 않으며 포즈와 발 그림자를 별도로 관리합니다.

`village-shop-scene.js`는 옷 가게의 벽·가구 충돌, 주인·알바생, 다채로운 옷 진열·마네킹·거울·피팅룸을 제공합니다. 주인에게 말 걸기→상품 고르기, 알바생→피팅/옷장 안내, 거울→보유 옷장, 피팅룸→상의부터 입어 보기, 출구→마을로 연결합니다. 실제 구매·착용·골드는 기존 `SCREENS.shop`을 재사용하며 시험 착용은 실제 구매가 아닙니다. 나무집 교실은 기존 수업 목록, 별 관측탑은 기존 혼자 연습으로 연결합니다.

`village-presence.js`는 로그인당 한 연결을 유지하고 `quiz/village/{반 이름}/connections/{접속ID}`에서 위치·높이·방향·아바타·인사만 공유합니다. 수업 답·골드·진도를 이 경로에 저장하지 않습니다. 이동은 150ms 단위의 변경분, 대기 중에는 10초 heartbeat를 전송합니다. 서버 단절 시 자기 연결만 제거하며 오래된 기록은 35초 후 표시에서 제외합니다. 같은 계정의 여러 탭은 접속ID로 분리하고 화면에서는 가장 최근 방의 친구 한 명으로 정리합니다. 실제 Firebase Database 규칙이 새 `quiz/village` 경로의 읽기·쓰기를 허용해야 하며, 권한 오류 시 혼자 탐험과 연결 대기 안내를 유지합니다. 별도 백엔드 인증이나 외부 Database 규칙 변경은 이번 작업에 포함되지 않습니다.

인사·감정 표현의 시간은 `getTime()`으로 서버 시각에 맞추고, 걷기·등반은 프레임의 유효 시간으로 진행합니다. 모달·숨김 탭 후 등반을 재개해도 멈춘 시간을 한 번에 이동하지 않습니다. 화면 종료 때 RAF·입력·구독과 포즈를 정리하고, 로그아웃 때 공유 연결을 종료합니다.

원화는 `assets/forest-town-{landmarks,foliage,exploration,tailor-room,tailor-details}.png`에 생성 원본 바이트로 보존합니다. 같은 이름의 JSON·제작기록에는 참고한 사용자 자료, SHA, 안전한 추출 영역·바닥/문/사다리 앵커를 보관합니다. 투명 atlas crop SVG는 CSS에서도 overflow를 숨겨 이웃 셀이 함께 나오지 않게 합니다. 지형 바닥·절벽과 작은 새는 다듬은 SVG이며 전체 배경이 손으로 그린 한 장의 원화라고 설명하지 않습니다.

이 문서는 `퀴즈나라/` 폴더의 퀴즈 게임만 설명합니다. 사용 순서는 [사용법.md](./사용법.md)를 봅니다.

## 저장소와 기준 파일

저장소는 `https://github.com/dydhd1203-max/game`이며, 개발 기준은 **`퀴즈나라/` 폴더**이며, Netlify 배포본은 이 폴더 안의 **`배포용/`**에 모읍니다. 기준 파일은 `퀴즈나라/index.html`입니다. 기존 게임의 파일이나 배포 폴더를 수정할 필요가 없습니다.

별도 프레임워크 빌드나 앱 실행용 npm 설치는 없습니다. 브라우저가 HTML, 외부 JS/CSS와 `assets/`의 원화·글꼴을 읽습니다. 런타임 파일은 `tools/deployment-files.cjs`를 기준으로 관리합니다. 헤어 목록은 남자 12종·여자 8종으로 구분하고 얼굴은 기본 상품을 포함해 8종입니다. 상의 14종과 하의 11종은 별도 세밀 원화를 12색으로 염색합니다. 햇살 천사는 몸·후광과 양 날개를 분리해 CSS로 움직입니다. 피부색 통일, 눈을 감는 모습과 표시 크기는 [디자인기준.md](./디자인기준.md)를 따릅니다. 원화 생성 프롬프트는 `assets/`의 제작 기록에 보관합니다.

## 로컬 미리보기

전체 ZIP을 압축 해제한 뒤 `퀴즈나라/index.html`을 직접 여는 실행도 지원합니다. Chrome의 `file:` 이미지 원점은 Canvas 픽셀 읽기가 제한되므로, `avatar-image.js`는 로컬 파일에서 `assets/avatar-file-data.js`의 원본 PNG 데이터 URL을 사용합니다. 웹 서버에서는 기존 PNG를 사용하고, 원점이 없는 임베드의 `SecurityError`에서도 같은 원본 데이터로 재시도합니다. 브라우저 보안 설정을 변경하지 않습니다.

로컬 데이터는 `node tools/build-avatar-file-data.cjs`로 내려진 후드·천사·분리 신발을 포함한 아홉 원본 PNG에서 생성합니다. 원화를 바꾸면 다시 생성해야 하며 `tools/check-source.cjs`가 원본과 일치를 검사합니다. 파일 전체를 제공해야 하며, 인터넷이 필요한 실제 Firebase 연결과 로컬 이미지 표시는 별개입니다.

Node.js가 있는 터미널에서 `퀴즈나라` 폴더로 이동해 실행합니다.

```powershell
node tools/preview-server.cjs
```

`http://127.0.0.1:4173/?demo=1`은 격리된 체험 모드입니다. Firebase 대신 localStorage에 저장하며 선생님·학생으로 새 일반 퀴즈 흐름을 확인합니다. 기존 체험 메뉴와 컴퓨터 친구 세 명은 기존 스피드 퀴즈·OX·팀 가로세로 체험용입니다. 실제 Firebase 데이터에는 쓰지 않습니다. 로컬 서버는 Node.js 내장 모듈만 사용하며 4173 포트가 사용 중이면 기존 프로세스를 확인합니다. 앱 검증과 사용자에게 공유할 사이트 배포는 별도 단계입니다.

`http://127.0.0.1:4173/`은 실제 모드입니다. HTML 위쪽 Firebase 설정을 사용하고 실제 Firebase SDK를 불러옵니다. 실제 수업의 계정·문제·방·패션왕 데이터는 `quiz` 경로를 사용합니다. 실시간 수업에서는 선생님 브라우저가 제한 시간 종료·라운드 정답 공개를 진행하므로 수업 중 열어 둡니다. 현재 클라이언트 교사 암호와 기존 Database 규칙을 사용하며 백엔드 인증·권한 정책 변경은 별도 작업입니다.

## 일반 퀴즈와 움직임 모듈

교사 동선은 `일반 퀴즈 만들기`의 **방식 선택 → 문제 작성 → 수업 설정**, 이후 `수업·혼자 풀기`의 진행 화면입니다. 학생은 수업 참가 목록 또는 `?classroom=수업ID` 참여 링크로 입장합니다. 일반 모드는 `sequence`, `free`, `round`, `team`, `coop`이며 OX·기존 스피드 퀴즈·팀 가로세로는 별도 퀴즈룸에 유지합니다.

| 파일 | 책임과 공개 API |
|---|---|

| `teacher-builder.js` / `.css` | `QPTeacherBuilder.mount(container, {set, mode, onBack, onSave, onNext})`. 질문 목록·편집·복제·순서 변경·실제 답할 수 있는 미리보기를 담당합니다. 저장은 호스트의 `onSave`·`onNext` 콜백이 수행합니다. |
| `quiz-classroom.js` / `.css` | `QPClassroom`의 수업 생성·참가·채점·진도 저장과 `QPTeacherClassroom.mountSetup`, `mountDashboard`. 수업 설정·교사 진행·학생별 상태·팀 합계·협동 목표를 담당합니다. |

### 문항 저장 형식

문제 묶음은 `{title, mode, qs}`이며 `qs`에는 아래 네 형식을 저장합니다. 기존 `{q, a, c}` 문항은 보기가 있으면 객관식, 없으면 주관식으로 정규화합니다.

```js
{ id, type: "choice", q, a: "정답 보기", c: ["오답 1", "오답 2"] }
{ id, type: "short", q, a: "정답/다른 정답", aliases: ["추가 인정 답"] }
{ id, type: "match", q, pairs: [{left: "강아지", right: "멍멍"}, /* ... */] }
{ id, type: "order", q, items: ["정답 순서 첫째", "둘째", "셋째"] }
```

객관식은 정답과 서로 다른 오답이 필요하고, 선 잇기·순서 맞추기는 두 개 이상의 중복 없는 항목이 필요합니다. 주관식은 짧은 정답을 비교하며 서술형을 추가하지 않습니다. 선 잇기의 제출 배열은 왼쪽 항목별로 연결한 원본 오른쪽 항목 인덱스이며, 순서 맞추기는 학생이 놓은 원본 항목 인덱스 순서입니다. 두 유형의 올바른 배열은 `[0, 1, …]`입니다. 선 잇기 UI는 실제 SVG 연결선을 표시합니다.

### 수업 저장과 규칙

- `quiz/bank/{setId}`: 저장한 문제 묶음. 제목·기본 방식·문항·작성/수정 시각을 보관합니다.
- `quiz/classrooms/{id}`: 만들 때의 문제 사본, `mode`, `delivery`, `settings`, 진행 상태와 참가자. `delivery`는 `live` 또는 `solo`입니다. 문제 묶음 수정이 진행 중인 수업에 자동 반영되지 않습니다.
- `quiz/classrooms/{id}/players/{uid}`: 학생의 아바타·팀·답변·점수·`completed`·현재 문제·시간·접속 상태·맵 위치. 같은 ID로 재참가할 때 저장한 답변과 진도를 보존합니다.
- `quiz/classroomActive`: 최근 만든 실시간 수업 ID. 기존 계정·룸·패션왕 경로는 각각 `quiz/users`, `quiz/room`, `quiz/fashion`입니다.

`QPClassroom`은 `create`, `read`, `watch`, `join`, `selectTeam`, `assignTeams`, `submit`, `start`, `reveal`, `next`, `end`, `leave`, `advanceSolo`, `sweep`를 제공합니다. `decorate`는 학생 진도·팀 합계·반 공동 정답 수를 계산하고 `settingsFor`는 설정값을 정리합니다. 실제 저장소는 Firebase 호환 `ref/once/on/off/transaction` 인터페이스를 주입합니다.

기본 설정은 라운드 30초, 전체 600초, 2팀, 무작위 균등 배정, 협동 목표 `문제 수 × 5`, 정답 100점입니다. 설정 화면에서 문제 수·시간·팀 수(2~6)·배정 방식·협동 목표를 변경합니다. 일반 점수와 계정 구매용 골드는 별도입니다. 같은 학생의 같은 완료 문항은 한 번만 점수·목표에 더합니다. 순서풀이는 첫 미완료 문항만, 자유·팀·협동은 원하는 미완료 문항을 풉니다. 팀 점수는 개인 점수 합계, 협동 목표는 학생별 정답 수의 합계입니다. 실시간 라운드는 같은 문제를 받고 공개 시 채점합니다.

움직임 연습에서는 좌우/A·D 걷기, Space/↑/W 점프, ↓/S 앉기를 사용합니다. 컨트롤러는 포커스가 있는 연습장·조작 버튼에서 키를 받고 답안 입력란·열린 모달에서는 이동 입력을 처리하지 않습니다. 탐험 맵의 방향키·WASD는 네 방향 이동에 사용합니다.

## 소재 보관함

사용자가 ZIP으로 보낸 맵·풀·건물·인터페이스·버튼·아이콘·창 테두리를 종류별 `assets/*-library/`에 원본 바이트 그대로 보관합니다. [전체 소재 보관함](assets/library/index.html)은 모든 종류를 검색하고 개별 보관함으로 연결합니다. 원본 ZIP도 유지하며, 같은 이미지의 여러 파일명은 한 원본에 별칭으로 연결합니다. 이름·종류·화풍·시점·분류·해시와 실제 그림 확인 상태를 제공하며, 원본 보관과 투명 소품 준비·게임 적용 상태는 구분합니다.

각 폴더의 `index.html`을 열면 목록을 검색·필터링하고 원본을 볼 수 있습니다. 원본 이미지와 `catalog-data.js`를 포함한 폴더 전체가 필요합니다. `catalog.json`을 갱신하면 `node tools/build-map-library.cjs`로 종류별 보관함과 전체 검색의 로컬 표시 데이터를 다시 생성합니다. 이 목록 JS 덕분에 파일로 여는 보관함에서도 JSON 네트워크 요청이 필요 없습니다. `check-source.cjs`는 목록 일치와 원본 이미지·ZIP 해시를 확인합니다. 클라우드에서는 웹으로 검색·필터·원본 표시를 확인했으며, 학교 Windows의 직접 열기와 별도 검증으로 구분합니다.

현재 공통 UI 컨셉은 숲속 마을입니다. `forest-village-theme.css`가 마지막 스타일 층이며 `assets/forest-village-frame.png`의 모서리와 나무 레일을 가변 크기 패널에 표시합니다. 본문·상품·아바타를 그림으로 덮지 않고 버튼·입력 기능을 유지합니다.

## 배포와 다운로드

수정 후 `퀴즈나라/` 폴더에서 `node tools/check-source.cjs`로 문법과 실행 파일을 확인합니다. `node tools/build-deployment.cjs`로 최신 실행 파일 전체를 `배포용/`에 모으고 `node tools/build-deployment.cjs --check`로 원본과 일치를 확인합니다. 실행 파일 목록은 `tools/deployment-files.cjs`입니다.

GitHub의 [최신 전체 ZIP](https://github.com/dydhd1203-max/game/archive/refs/heads/main.zip)을 내려받고 압축을 풉니다. **`game-main/퀴즈나라` 폴더 전체**를 사용합니다. `index.html`만 내려받으면 이미지·스타일·글꼴이 빠집니다.

Netlify 수동 배포에는 **`game-main/퀴즈나라/배포용` 폴더 전체**를 끌어다 놓습니다. `index.html`만 올리지 않습니다. 배포본에는 JS·CSS·원화·글꼴·`_headers`와 해시 검증용 `배포정보.json`이 들어 있으며 사용자 원본 ZIP·개발 도구는 제외합니다. GitHub 연결 배포는 Base directory를 `퀴즈나라`로 정하면 이 폴더의 `netlify.toml`이 빌드 명령 `node tools/build-deployment.cjs`, 게시 디렉터리 `배포용`을 설정합니다. 다른 게임 사이트와 분리하여 배포합니다.

## 검증 범위

`node tools/check-source.cjs`는 이 폴더의 HTML과 외부 스크립트의 문법 및 실행 파일을 확인합니다. `tools/verify-game.cjs`는 격리된 체험 모드의 기존 세 게임과 구매 흐름을 확인하는 브라우저 검증 도구입니다. 이 결과로 새 다섯 일반 모드까지 검증했다고 판단하지 않습니다. 브라우저 검증에는 Playwright와 브라우저 실행 환경 및 실행 중인 로컬 미리보기 서버가 필요합니다. 기존 도구에는 Windows Chrome 절대경로를 지정한 파일이 있으므로 Linux·클라우드에서 실행할 때 실제 실행 파일 경로와 도구 지원 설정을 먼저 확인합니다. 문서의 명령 나열은 검사 실행·통과 기록이 아닙니다.

새 마을은 `node tools/verify-village-presence.cjs`로 연결 어댑터를, `tools/verify-village-wave.cjs`로 실제 인사·등반 원화를, `tools/verify-village-world.cjs`로 두 학생의 실제 이동·교실·상점·줄 이동과 PC 배치를 확인합니다. 새 두 브라우저 도구는 `QUIZ_BROWSER_EXECUTABLE`로 실제 브라우저 실행 경로를 지정하며 `QUIZ_PREVIEW_URL`로 미리보기 주소를 지정할 수 있습니다. 통합 검수의 `QUIZ_VERIFICATION_OUTPUT`은 결과 디렉터리이며 `QUIZ_VILLAGE_LAYOUT_ONLY=1`은 미술 위치 변경 뒤 관련 PC 배치만 검사합니다. 이동·모션 변경에는 전체 흐름과 해당 경로 검수를 사용합니다. 모든 검수는 격리 체험 어댑터를 사용하고 실제 Firebase SDK 요청을 차단합니다.

`node tools/verify-demo.cjs`는 기존 체험 메뉴에서 스피드 퀴즈 → OX → 팀 퍼즐로 전환하고, 컴퓨터 친구 세 명의 답변·점수와 두 팀의 퍼즐 진행을 확인합니다. 확인 화면은 `검증/체험-퀴즈.png`, `검증/체험-OX.png`, `검증/체험-팀퍼즐.png`에 저장합니다.

`node tools/verify-art.cjs`는 피부색·머리·얼굴·상의·하의를 다르게 조합한 전신 아바타 여섯 명을 크게 표시해 `검증/아바타-디테일.png`에 저장합니다. 이 이미지는 원화와 옷의 선명함, 머리 위치와 피부색을 눈으로 비교하는 자료입니다. 자동 검사만으로 미술 품질을 판정하지 않으며, [디자인기준.md](./디자인기준.md)에 따라 실제 로비·꾸미기·게임 화면도 함께 확인합니다.

`node tools/verify-economy.cjs`는 추가 패키지 없이 실행합니다. 실제 계정 저장·연습 보상·수업 지급·구매 함수로 보상 중첩, 일일 한도, 재시도와 로그인 전환 시 계정 혼동을 검사합니다.

`node tools/verify-avatar-motion.cjs`는 같은 의상을 입은 남녀 아바타의 서로 다른 원화와 뜬 눈·반쯤 감은 눈·감은 눈을 실제 애니메이션 시점별로 확인합니다. `node tools/inspect-outfits.cjs`는 상의·하의 전체 조합을 큰 그림으로 저장합니다. 효과음·BGM 검증은 `node tools/verify-audio.cjs`로 실행합니다.

`tools/verify-avatar-stability.cjs`는 이전 도트 렌더의 픽셀 고정·한 픽셀 단위 포즈를 검사한 과거 도구입니다. 새 일러스트형 SD 아바타에는 부드러운 모션 기준을 적용하며 이 과거 결과를 새 렌더 검증으로 보고하지 않습니다. 최신 검수에서는 실제 전신·상품 그림의 표시, 피부·머리·옷 색, 반투명 가장자리, 깜박임과 부드러운 숨쉬기, 이동·점프·앉기를 확인합니다.

`node tools/verify-avatar-gender.cjs`는 남녀 상점·옷장·무작위 헤어·성별 전환과 예전 계정의 혼합 헤어를 확인합니다. `node tools/verify-pets.cjs`는 새 펫 16종과 12색, 펫·천사 동시 착용을, `node tools/verify-body.cjs`는 가는 피부 윤곽과 신발 9종·12색 및 로비·상점 표시 크기를 확인합니다.

머리는 남녀 각각 4×3 시트의 독립 셀을 384×384로 처리하고, 피부·헤어를 염색한 뒤 384×480 전용 이미지로 표시합니다. 원화에서 측정한 눈·턱 위치로 전신과 눈 깜박임을 정렬하고, 앞머리와 몸 뒤의 긴 머리를 별도 레이어로 나눕니다. 실제 원본 해상도·셀 경계·랜드마크·해시는 `assets/sd-heads.json`에 있습니다. 상의·하의와 신발은 `assets/sd-wardrobe.json`을 함께 참고합니다. 곡선·반투명 가장자리를 유지하며, 신발의 비율은 전신의 세로 배율을 고려해 맞춥니다.

`node tools/verify-sd-avatar.cjs`는 새 SD 머리·의상·신발의 실제 표시와 12색 염색, 피부색, 반투명 가장자리, 눈 위치·깜박임을 확인합니다. `node tools/verify-file-avatar.cjs`는 일반 웹 원점과 실제 원점 없는 sandbox에서 원화 로딩 및 원본 픽셀·투명도 일치를 확인하고, 로컬 파일 탐색이 실행 환경의 정책으로 막히면 미검증으로 기록합니다. 이 결과를 학교 Windows에서 직접 실행한 것으로 보고하지 않습니다.

`node tools/verify-avatar-fitting.cjs`는 실제 원화 알파 영역으로 상의·하의 25종의 목선·소매·허리 연결과 60개 포즈의 접촉을 확인합니다. DOM에 적힌 정렬 좌표만으로 통과시키지 않습니다. 부위별 원본과 추가 소재 등록 방법은 [아바타 라이브러리](assets/아바타-라이브러리.md), 맵 소재의 확보 상태와 분류는 [맵 라이브러리](assets/map-library/README.md)를 확인합니다.

`node tools/verify-feedback.cjs`는 실제 Chrome에서 첫 클릭의 음향 준비, 버튼 누르기·복원, 주변 배치 유지, Enter·Space, 비활성 버튼, OX 위치·선택음 중복과 모션 줄이기를 확인합니다.

`node tools/verify-clothes.cjs`는 원화 25종의 분리와 125개 색 조합에서 염색·장식·투명도 유지, 다섯 전신의 상의/하의 분리를 확인합니다. `node tools/verify-effects.cjs`는 천사 구매 520골드 차감, 펫 동시 착용, 상점 날갯짓, 벗기와 무료 재착용을 확인합니다.

주 사용 환경은 LG 그램과 크롬북입니다. 1920×1080, 1440×900, 1366×768, 1280×632, 1024×632 크기의 브라우저 화면에서 노트북 배치를 확인합니다. `verify-layout.cjs`는 내 아바타 배경의 경계·가운데 정렬·중복 배경과 스크롤바도 검사합니다. 실제 교실 기기 성능은 해당 기기에서 따로 측정해야 합니다. 기존 다른 게임의 FPS 측정 결과는 이 퀴즈 게임의 성능 근거로 사용하지 않습니다.

## 새 일반 퀴즈의 완료 전 검수

아이들이 좋아하는 맵·UI·아바타에 가장 많은 공을 들이는 고정 지침은 [AGENTS.md](./AGENTS.md)와 [디자인기준.md](./디자인기준.md)를 따릅니다. 문법·데이터 검사와 실제 학생 화면의 미술·플레이 검수를 함께 합니다.

1. 교사 화면에서 방식 선택 → 네 유형 작성·미리보기 → 저장 → 수업 설정 → 참여 링크 → 대기실·시작·진행·결과를 확인합니다. 저장한 묶음을 다시 열고 다른 방식으로 재사용합니다.
2. 학생 두 명 이상으로 같은 수업에 들어갑니다. 한 학생의 정답이 다른 학생의 문항·관문을 완료시키지 않는지, 오답 재도전·정답 중복 제출·재접속 진도 보존을 확인합니다. 실시간과 혼자 풀기에서 각각 확인합니다.
3. 순서풀이 시작점부터 숲길을 따라 모든 관문을 풉니다. 닫힌 꿀단지·울타리의 충돌과 우회 방지, 정답 뒤 통과를 확인합니다. 자유풀이의 성·용암·사막·숲 모든 구역을 실제로 이동하며 근접 NPC 문제와 접근 가능한 경로를 확인합니다.
4. 라운드 시작 때 각 아바타가 자기 체크무늬 소풍 돗자리 한 장으로 걸어 들어가는지, 동일 문제·시간·제출·공개·점수·최종 순위를 확인합니다. 혼자 라운드의 제출·시간 종료·다음 문제도 확인합니다.
5. 팀전의 가을 경기장 안 이동·경계 충돌·팀 색을 확인합니다. 교사 지정 팀 수, 무작위 균등 배정(팀 간 인원 차이 최대 한 명), 학생 팀 선택, 개인 완료와 팀 합계가 맞는지 확인합니다. 협동전은 반 전체 정답 합계·중복 방지·기한 전 성공·시간 종료를 확인합니다.
6. 네 유형을 실제 학생 화면에서 풉니다. 객관식 보기, 주관식 추가 인정 답, 선 잇기의 실제 선과 재연결, 순서 맞추기의 끌기·키보드/버튼 조작과 정답 순서를 확인합니다. 기존 OX·가로세로·상점·골드도 변경 범위에 따라 회귀 확인합니다.
7. 각 모드의 기본 학생 시작 시점·진행 경로·사물 앞·답안 UI·정답 뒤 이동·결과를 저장하고 이미지를 직접 엽니다. 세밀한 아바타와 걷기·점프·앉기, 깜박임·숨쉬기·펫·천사 날갯짓을 확인합니다. 조망용 화면과 자동 통과만으로 미술 완료를 판단하지 않습니다.

실행 결과에는 사용한 데이터·학생 수·화면 크기·실행한 검사·직접 연 화면을 남기고, 구현됨/직접 확인됨/미확인 또는 보류를 구분합니다. GitHub 푸시·사이트 배포·실제 그램/크롬북 성능은 별도 증거가 있을 때만 완료라고 보고합니다. 재생성 가능한 `검증/` 출력은 커밋하지 않습니다.

## 다른 컴퓨터에서 이어서 작업하기

개발 기준은 이 `퀴즈나라/` 폴더입니다. 저장소 루트의 `index.html`과 `배포용/index.html`은 최적화 중인 좀비 게임이므로 수정하거나 배포에 포함하지 않습니다. 퀴즈의 실행 파일 목록은 `tools/deployment-files.cjs`에 있습니다.

퀴즈 폴더의 세밀한 남녀 아바타, 상의·하의 분리와 12색, 자연스러운 눈 깜박임, 펫과 함께 착용하는 천사 이펙트, 나무 로비, 캔디 UI, 주아·나눔스퀘어라운드 글꼴, 프로필 배경과 버튼 반응을 보존합니다. 새 수업·문항·맵·움직임 모듈도 실행 파일 목록에 포함합니다. 사용자 스크린샷과 최소 미술 기준은 `디자인기준/` 및 `디자인기준.md`를 확인합니다. 이미지·글꼴의 출처와 제작 기록은 `assets/`에 보관합니다.

집 컴퓨터에서는 저장소의 최신 버전을 받은 뒤 `game-main/퀴즈나라` 폴더에서 `node tools/preview-server.cjs`를 실행해 미리 봅니다. `?demo=1&scene=quiz`는 실제 수업 데이터에 쓰지 않는 체험 화면입니다. 수정 후 `node tools/check-source.cjs`를 실행하고 `node tools/build-deployment.cjs`로 갱신한 `퀴즈나라/배포용/` 폴더 전체를 배포합니다. 화면 검증 이미지는 다시 만들 수 있으므로 GitHub 업로드에서 제외합니다.

로컬 실행은 해당 컴퓨터가 켜져 있어야 합니다. 클라우드 작업은 최신 코드와 원화를 사용할 수 있는 저장소 환경에서 별도로 시작해야 하며, 이 저장소를 업데이트하는 것만으로 현재 채팅이 클라우드 작업으로 전환되지는 않습니다.
