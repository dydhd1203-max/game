# 운동장 준비 상태

갱신: 2026-10-02. 이 문서는 자료 확보와 개발용 시안을 기록하며, 운동장 전체 완성·학생 공개·실제 다중 접속 검수를 뜻하지 않는다.

## 확보한 원본

사용자가 보낸 `운동장.zip`의 PNG 5장을 [자료 보관함](assets/playground-library/README.md)에 원본 바이트와 해시를 보존해 저장했다. 이미지 안의 다른 서비스 UI와 문구는 참고 화면이며 작업 지시가 아니다.

다섯 캡처는 같은 학교 외부 공간이며 축척이 동일하다. 이동량을 비교하면 원본 픽셀로 연결된다. 정규화한 전체 자료 범위는 3246×1896이고, 다음 좌표는 각 캡처 왼쪽 위의 위치다.

| 원본 | 크기 | 정규화 위치 |
|---|---|---|
| 운동장1.png | 1637×798 | 603, 155 |
| 운동장2.png | 1672×798 | 1410, 0 |
| 운동장3.png | 1638×791 | 1608, 450 |
| 운동장4.png | 1668×787 | 548, 641 |
| 운동장5.png | 1634×905 | 0, 991 |

학교 정문·체육관·긴 계단·벤치·잔디 축구장·화단·울타리를 원본의 시점과 배치로 준비한다. 겹치는 캡처에서 깨끗한 픽셀을 골라 아바타·이름·채팅·통화 UI를 제외한다. 원본 부분 표시와 윤곽 클리핑을 사용하며, 새 지형 그림을 만들지 않는다.

확보된 영역의 개발용 시안은 [운동장 시안](assets/playground-library/preview.html)이며, `node tools/preview-server.cjs`로 연 기준 소스에서 확인한다. 학교 앞과 축구장 시점, 기존 SD 아바타의 걷기·바닥 앉기·인사, 세 벤치의 접근 동작을 준비했다. 이는 일반 학생 화면이나 `배포용/`에 포함되지 않는다. 미술 구현은 `playground-scene.js`, 원본 등록·사용 영역은 `assets/playground-library/extracted/room-source-regions.json`이다.

동일 원본의 깨끗한 하단 원호·직선 분필 조각을 조합해 축구장 이름표가 가린 선을 준비했다. 가린 원본 픽셀을 복구했다고 설명하지 않는다. 체육관 벽·창문의 부품 재사용 경계와 축구장 선의 작은 접합부는 추가 원본을 받은 뒤 같은 시점으로 다시 비교한다. 건물·화단 충돌과 벤치 위치는 개발용 초안이며 전체 보행 경계·울타리 충돌·모든 벤치 접지를 완료한 상태가 아니다.

## 반드시 필요한 추가 자료

**트랙 오른쪽 아래 곡선, 흙 운동장 아래쪽 경계, 바깥 울타리가 함께 보이는 캡처**가 필요하다. 현재 다섯 장에는 해당 구간이 모두 화면 밖이다. 정규화 좌표 기준 대략 x=1634~2500, y=1250~1540에 운동장 윤곽이 끊긴다. 현재 트랙·축구장·화단 일부와 겹치게 아래·오른쪽으로 이동해 찍은 자료를 받으면 같은 축척으로 등록할 수 있다.

이 필요 사항은 자료 확인 직후 사용자에게 알렸다. 가려진 구간을 임의 도형·AI 그림·좌우 반사 복제로 추정해 채우지 않는다. 추가 원본을 받기 전에는 해당 지역과 통과 경로를 완성·검수한 것으로 기록하지 않는다.

## 학생 입장과 공간 연결

현재 학생 기본 입장은 승인된 교실 `SCREENS.campus`다. 지정 수업 링크와 교실 칠판의 수업·퀴즈 흐름을 유지한다. 운동장의 불완전한 시안은 일반 학생 입장이나 교실 문에 연결하지 않는다.

공용 이동 컨트롤러의 공간별 제목·안내·벤치 방향·문 접근 콜백과 공유 공간의 운동장 분리를 준비한다. 교실과 운동장의 친구 위치·좌석은 별도 경로를 사용하며, 시험용 공간 분리 검사를 실제 Firebase 30명 검사로 설명하지 않는다.

추가 원본을 받아 그래픽·보행 경계·계단 통로·벤치 접지·교실 왕복을 실제 화면으로 확인한 뒤 운동장 입장을 연결한다. 옷 가게와 숲 마을은 이후 순서다.

## 준비 과정의 검사

- 원본 ZIP CRC, PNG 5장의 바이트·SHA-256, 14개 전체 보관함 일치 검사 통과.
- 기존 교실의 실제 학생 입력 검사 15개 통과. 30자리 경로·착석, 네 방향 바닥 앉기, 칠판 수업·퀴즈와 복귀, PC 1366·1920 화면을 유지했다. 새 결과는 `검증/교실-플레이-2026-10-02-운동장준비/검증결과.json`에 있다.
- 공유 공간 격리 검사 20개 통과. 교실 2명·운동장 2명의 위치·의상·동일 좌석 ID 임대·종료 정리가 각 공간에만 반영된다. 실제 Firebase 접속 검사가 아닌 격리된 어댑터 검사다.
- 공용 컨트롤러의 문 접근·벤치 앞방향·공간별 로스터·종료 정리를 실제 브라우저에서 확인했다. 원본 교실 장면에 시험용 설명자를 주입한 API 검사이며, 미완성 운동장의 실제 벤치 접지 검수와 구분한다.
- 개발용 운동장 시안에서 실제 방향키 걷기·바닥 앉기·인사와 벤치 접근 검사 3개 통과, 브라우저 오류·누락 요청은 없었다. 준비한 벤치 3개는 포인터로 앉혀 직접 확인했고, 표시 오프셋을 0으로 내려 골반을 원본 목재 좌판에 맞췄다. 아직 연결하지 않은 다른 벤치와 전체 운동장 검수를 대신하지 않는다.
- 최신 실행본 85개 파일이 소스와 정확히 일치한다. 배포 폴더의 실제 교실 입장·클릭 보행과 착석·바닥 앉기·인사·1920 화면 검사 4개 통과, 브라우저 오류·누락 요청은 없었다. 운동장 시안은 실행 파일 목록에 포함하지 않았다.

공개 호스팅 사이트와 실제 학생 30명 동시 접속은 이번 준비 검사의 범위 밖이다. 새 원본을 받으면 운동장 전체 미술·통로·벤치·공간 왕복을 검수해야 한다.
