# 숲속 마을 구현·검수 기록

2026-10-03. [디자인 지침](숲속마을-디자인지침.md)과 [배치 계획](숲속마을-배치계획.md)을 적용한 첫 플레이 구현이다. 자동 검사, 직접 본 화면, 미확인 범위를 구분한다. 기존 아바타 원화·옷장·골드·구매 데이터는 보존한다. 후속 성능 보정에서 관절의 상대 좌표 계산과 중복 DOM 갱신만 최적화했다. 아래 첫 구현 기록 이후의 최신 변경은 마지막 절을 참조한다.

## 구현한 공간과 연결

학생 기본 입장은 햇살 숲속 마을이다. 기존 지정 수업 링크는 해당 수업으로 직접 들어간다. 피크닉동산의 물가·연못·굽은 길·휴식 공간을 큰 구도 그대로 살리고, 서쪽 두 마당에 서로 다른 제공 집을 배치했다. 집은 현재 풍경용이며 실내 상점·퀴즈룸 기능을 새로 만들지는 않았다.

| 공간 | 크기 | 원본과 연결 |
|---|---|---|
| 햇살 숲속 마을 | 2230×1472 | 피크닉동산 + 제공 집 2종. 남쪽 길 F→기존 운동장, 북쪽 숲길 F→비밀정원 |
| 비밀정원 | 1924×1082 | 숲속 교실의 숲·나무집·해먹·모임 마당. 남쪽 F→마을, 나무집 앞 F→달빛 나무집 |
| 달빛 나무집 | 1703×1332 | 나무집 원본의 밑동·사다리·데크·실내. 아래 F→정원, 위쪽 F→하늘섬 |
| 구름 위 버섯섬 | 2008×1162 | 퀴즈마을 원본의 섬·사다리·버섯 전망대. 아래 F→나무집 |

잔디색·조명·시점이 다른 원본은 한 바닥에 억지로 접합하지 않고 입출구를 표시한 별도 공간으로 연결했다. 운동장 학교의 기존 두 출입구 F↔교실은 유지한다. 사다리와 계단은 원본 위 보행 경로로 연결했으며 전용 등반 애니메이션을 추가한 것은 아니다. 정원의 그루터기 의자는 원본 풍경이며 교실처럼 자리 예약을 받지 않는다.

`forest-village-scene.js`는 원본 위치·배율·지면 기준·충돌·전경·입출구·검수 경로를 관리한다. `school-room-world.js`의 기존 길 찾기·96px 아바타·225px/s 걷기·337.5px/s 달리기·C 앉기·인사 버튼을 재사용한다. 내 위치 버튼은 현재 아바타를 따라간다.

공간별 친구 목록은 `quiz/spaces/{반}/{공간}/connections`로 분리한다. 공간을 나가면 해당 구독·접속을 정리한다. `village-presence.js`의 `space` 옵션을 생략하던 기존 API 경로도 보존했다. 기존 교실 좌석과 학생별 수업·골드·구매 경로를 마을 경로로 옮기지 않는다.

## 나무 잘림과 원본 정리

사용자 제보 이미지는 [사물 절단 비교](디자인기준/숲속마을-사물절단-사용자제보.jpg)에 보관했다. 단순히 빈틈을 덮는 것 대신 수관·줄기·밑동·그림자 전체와 수정 마스크 바깥을 보호하도록 지침과 검사를 추가했다.

- 피크닉동산의 위·아래 서비스 UI는 게임 영역 밖으로 crop했다. 마당에 새 집을 놓는 곳은 기존 돗자리·탁자·나무를 각각 전체 윤곽 단위로 정리했다.
- 중앙 촬영 이름·아바타를 지울 때 시계 기둥과 옆 덤불을 함께 자르지 않도록 마스크를 좁혔다. 이름에 가려진 아래 꽃은 같은 원본의 완전한 꽃무리로 교체했다. 주변 덤불은 원래 곡선과 픽셀을 복원하고 보호 영역을 추가했다. 가려졌던 원본 꽃을 정확히 복원했다고 주장하지 않는다.
- 정원 위쪽 UI에 가려진 나무 묶음은 전체 영향 영역을 정리한 뒤 같은 원본의 완전한 나무로 대체했다. 인접 나무·울타리·문 기둥은 보호했다. 왼쪽 경계 지면은 인근 색에 맞는 원본 잔디를 선택하고 기록된 지면 마스크 안쪽 3px에서만 원본끼리 알파 연결했다. 나무·꽃 원화 자체에 블러를 적용하지 않았다.
- 하늘섬의 이름표에 가려진 징검돌은 반쪽을 남기지 않고 같은 원본의 온전한 돌로 교체했다.
- 주요 마을 수관은 원본 배경과 정확히 같은 좌표의 전경으로 분리해 아바타가 앞뒤를 지날 수 있게 했다. 원본 전체를 지우는 직사각형 전경 마스크는 사용하지 않았다.

`assets/forest-village-library/extractions.json`에 11개 추출물의 원본 해시·crop·수정 마스크·옮긴 사물의 윤곽·반전 여부를 기록했다. 원본 파일은 유지한다. 원본 바깥 가장자리의 숲과 새로 만든 내부 절단, 카메라 밖 가림은 구분해 검토했다.

## 꽃 종류·배치·화풍 편집

현재 맵에는 흰색·연보라 꽃무리, 노란 관목 꽃, 작은 주황 들꽃을 추출해 배치했다. 위쪽 집 앞, 아래 집 옆, 남쪽 물가 잔디, 정원 입구 옆과 해먹 옆으로 총 13개의 작은 꽃무리를 나눴다. 길·입장점·F 접근 영역·복귀점은 비웠다. 같은 화단 전체를 반복하지 않으며 각 꽃의 바닥 기준으로 앞뒤 순서를 정한다.

별도 풀 소재 보관함에는 흰 데이지, 노란 민들레/미나리아재비, 파란 종 모양 꽃, 붉은 꽃 등의 시트도 있다. 전체를 게임에 넣거나 전부 화풍 수정한 것은 아니다.

사용자의 후속 요청에 따라 `grass-01f0410a594bffdb.jpg`의 흰 꽃을 대표로 **이미지 편집 도구로 화풍 수정**했다. 피크닉동산의 꽃을 스타일 기준으로 삼아 두꺼운 외곽선·평평한 명암을 부드럽게 바꾸고 낮은 꽃무리와 땅 그림자를 맞췄다. 원본 보존, 수정본 출처, 1484×1060 RGBA 결과 해시·바닥 기준은 `adaptations.json`에 기록했다. 생성 편집 결과이므로 원본과 꽃잎 개수·형태가 픽셀 단위로 같다는 뜻은 아니다.

수정본은 `adapted/flowers-daisy.png`이며 집 앞 화단 한 곳에 사용한다. 원본/수정본 확대 비교, 약 64px 꽃 크기의 기존 맵 꽃과 비교, 96px 아바타가 있는 실제 배포본 화면을 직접 확인했다. 진한 만화 윤곽선과 회색 시트 배경이 사라지고 기존 꽃 옆 작은 화단으로 읽힌다. 모든 제공 에셋이 자동으로 자연스럽게 바뀐다는 보장은 하지 않는다. 이후에도 대표 수정→같은 크기 비교→실제 배치 검토를 반복한다.

재생성 가능한 검증 이미지·로그는 Git에 일괄 추가하지 않았다. 이번 환경의 자료 위치:

## 남은 확인과 적용 범위

**30명 성능은 합격으로 처리하지 않았다.** 로컬 가상 아바타 30명은 표시되었지만 이 클라우드 Chromium에서 중앙값 약 500ms/frame이었다. 동일 환경의 기존 교실과 마을 비교도 각각 약 483ms/frame이었다. 따라서 새 마을만의 성능 저하라고 단정할 근거는 없으며 학교 기기에서 원활하다고 말할 수도 없다. 별도 성능 개선과 실제 그램·크롬북 확인이 필요하다.

실제 수업 Firebase의 동시 접속·학교 네트워크 권한, 물리적 학교 기기 성능, Windows 파일 직접 열기와 Cloudflare 공개 배포 완료는 이번 검사 범위 밖이다. 데모·배포 폴더 검증과 GitHub push 성공은 공개 사이트 배포 성공과 구분한다. 검증 과정에서 실제 학생 저장 데이터에 쓰지 않았다.

물·나뭇잎 전용 애니메이션, 집 실내, 신규 옷 가게·퀴즈룸·게임룸은 후속 확장이다. 현재 화면의 기존 인사·행동 공유와 자유로운 이동을 새 일반 채팅 시스템 구현으로 보고하지 않는다.

## 후속 화풍·가림·표시 보정 — 2026-10-03

제공 집 두 채를 원형·입구·계단·테라스를 유지해 이미지 편집 도구로 보정했다. 촘촘한 선과 질감을 줄이고 햇살 마을의 색과 시점에 맞춘 뒤 밑동 기준으로 배치했다. `adapted/sources/courtyard-houses.png`는 보정 원본 시트, `adapted/flower-home.png`와 `bakery-home.png`는 실제 배포용 비율 축소본이다. `adaptations.json`에 원본·참고·생성 시트 해시와 crop/축소 레시피를 기록했다. `tools/build-forest-village-adaptations.py`로 같은 실행 이미지를 재생성했다. 집 앞 잔디의 접합은 사물 제거 영역 바깥 최대 4px 안에서만 원본 잔디끼리 연결하며 나무 원화에는 블러를 적용하지 않는다.

정원 전경 4개, 하늘섬 전경 3개를 보강했다. 하늘섬의 소수 배율에서 CSS z-index가 무효가 되는 문제는 정수로 정규화해 수정했다. 기존 마을 전경을 합친 11개 전경의 원본 좌표 일치, 일부러 2px 옮긴 실패 대조, 선물 상자 6개 바닥 충돌을 추가 검사했다. 나무 바닥 충돌도 실제 밑동에 맞췄다.

30명 표시 지연의 큰 원인은 아바타 조립 중 `getCTM/getScreenCTM`의 반복 동기 레이아웃이었다. `avatar-local-transform.js`에서 SVG transform을 조합하며 인라인 CSS·중첩 viewport는 기본 측정으로 돌아간다. 몸·머리·팔·소매·다리 원화와 의도된 관절은 변경하지 않았다. 매 프레임 동일한 팔·손 레이어를 다시 삽입하던 작업, 같은 속성·안내문을 다시 쓰는 작업을 줄이고 화면 크기는 ResizeObserver에서 갱신한다. 휴식 중 친구의 느린 호흡은 여섯 프레임에 분산하고 본인·이동·인사·방향/착장 변화는 즉시 처리한다. 원화의 접지 그림자를 유지하면서 중복 외부 drop-shadow만 제거했다.

실제 실행한 회귀 검사:

- 배포본 마을: 7개 묶음, 실제 12경로, F 왕복·입장점·C·달리기·화면 크기 2종 통과.
