# 기준 착장과 연결 검수

> 이 문서는 이전 검사 이력이다. 2026-10-04 현재 기준 캐릭터는 최종 미술 검수 중이며 [최신 연결 보강 검수](아바타-연결보강-검수.md)의 범위·제한이 우선한다. 과거 PASS를 현재 착장 완료로 사용하지 않는다.


2026-10-03. 현재 범위는 남녀 기준 캐릭터의 **초록 반팔·남색 반바지·아이보리 운동화 한 벌**이다. 기존 얼굴·머리·체형 비율과 고정 관절을 유지했다. 새 공통 뼈대의 첫 착장을 검증한 결과이며, 기존 상점 전체 의류의 전환 완료를 뜻하지 않는다. 제작 계약은 `아바타-제작기준.md` 하나를 따른다.

## 실제 원본·조립과 확인된 원인

현재 원화 5개와 해시·출처·용도는 `assets/sd-foundation-basic.json`, 원본 픽셀 영역·개구부·랜드마크는 `avatar-foundation-outfit.js`의 `definitions`에 있다. 소매·바지통·신발 원본 파일은 수정하지 않고 메모리에서 연결용 그림을 만든다. 소매의 근위부 경계는 **몸통 천 위에 겹치는 부분만** 합성하며 노출된 외곽선과 크림 소맷부리는 유지한다. 결과 SVG에는 몸통1·소매2·골반1·바지통2·신발2, 총8개 의상 이미지가 있다.

목깃과 소맷부리는 서로 다른 두 크림 띠다. 측면 wave에서 가까운 팔이 목깃 앞을 지나는 부분은 정상적인 가림이다. 목깃 전체를 강제로 드러내려고 소매를 잘라내지 않는다.

## 같은 조건의 미술 비교

체험 환경 `avatar-standard.html`에서 남자 short / 피부1 / 우측면 / wave 진행0.5 / 시간0을 고정하고 280px·96px 및 확대를 캡처했다. 이전 장면은 해당 조립 코드 작업 스냅샷으로 재현했다. 머리·목·몸통·원본 소매·조립 소매·팔을 분리해 확인했다. 확대 화면의 위쪽 얼굴 잘림은 의도된 확대 범위이며 전신 화면으로 머리·손 존재를 함께 확인했다.

직접 확인한 결과는 `/workspace/quiz-cloud/outfit/`에 있고 재생성 이미지는 Git에 넣지 않는다.

- `connection/before-after.png`: 같은 대표 측면 wave의 전후 비교.
- `connection/before-profile-wave.png`, `after-profile-wave.png`, `isolated-parts.png`: 280/96px 및 단독 부위 확인.
- `connection/wave-0.12.png`, `wave-0.22.png`, `wave-0.5.png`, `wave-0.78.png`, `wave-0.88.png`: 남자 밝은 피부/여자 어두운 피부 × 네 방향 × 올리기·최고점·내리기. 각 카드에280/96px를 같이 표시한다.
- `neck-idle.png`, `neck-wave.png`: 턱·목 옆선·목깃, 앞/옆/뒤 소매의 확대 비교.
- `final-browser/`: 교실 바닥/책상, 운동장 걷기·달리기·아빠다리의 실제96px.
- `continuous-0.png`, `continuous-1.png`: 배포본 검수 화면에서 연속 재생 중 수집한 걷기·달리기·인사·점프 프레임.

표현이 다른 원화를 만지지 않고 숫자로 접촉만 맞춘 상태를 미술 완료로 취급하지 않았다. 큰 팔 올림을 대기 원화의 과도한 변형으로 처리한 중간안은 폐기하고 인사용 그림으로 교체했다.

## 기존 반팔·후드에 추가 적용한 연결 수정

사용자가 추가로 보낸 일반 착장 화면의 남녀 `tee`, `hood` 4개는 `avatar-pixel.js`·`avatar-clothes.js`·`avatar-poses.js` 경로다. 첫 기준복 검수 이후 이 4개에도 별도 수정했다. 전체 상점이 새 공통 뼈대로 전환됐다는 의미는 아니다.

실제 원인을 분리해서 확인했다. 소매를 떼는 넓은 마스크가 몸통 겨드랑이 천까지 제거했고, 일부 소맷부리는 마스크 아래에 남았다. 분리한 전체 소매를 회전하면 어깨 접합부가 떨어졌다. 남자 정면 머리 아래 표시 범위보다 피부 목이 좁았고, 여자 목깃 뒤쪽 선도 목 위로 올라왔다.

`avatar-cloth-mesh.js`는 원래 몸통과 장식을 유지하며 작은 동작에서는 원래 소매의 어깨 접합을 고정하고, 큰 인사에는 `sd-wardrobe-wave.png`의 해당 성별/아이템 소매·겨드랑이 그림을 사용한다. 큰 소매를 무리하게 늘려 무늬가 접히던 중간안은 버렸다. 앞쪽 손만 기존 손 레이어에서 이동하며 새 손을 복제하지 않는다. 피부 → 소매 앞 테두리 → 손 순서를 유지한다. `avatar-pixel.js`의 정면 목 곡선은 턱 아래와 목깃을 잇도록 넓혔으며 머리 위치와 원본 머리 PNG는 바꾸지 않았다.

새 원화 출처·해시·참고 파일은 `assets/sd-wardrobe-wave.json`에 있다. 기존 `sd-tops.png`, `sd-hood.png`, `sd-clothes-male.png`는 수정하지 않았다. `verify-wardrobe-connections.cjs`는 작업 전 소스를 별도 경로로 공급해 동일 시간·피부·아이템·진행률에서 비교한다. 4개 상의 × 인사8시점 × 전후 =64행, 추가 방향80건을 확인했다. 인사 최고점/올리기/내리기의 겨드랑이 연결 단면과 턱 아래 피부를 실제 알파로 검사하고 옛 잘못된 마스크/좁은 목이 실패하는지 확인했다. 사진은 `wardrobe-final/`에 있다.

기존 인사는 여전히 정면을 향한다. 방향을 요청한 것과 실제 방향을 구분해 기록하며 이를 측면/후면 인사 원화 통과라고 하지 않는다. 네 방향 인사는 새 기준복에서 별도 검수했다.

## 기존 신발의 착화감 수정

`avatar-shoes.js` 원본 `sd-shoes-parts.png`에는 살구색/파란색으로 채워진 입구와 발등이 있었다. 신발 전체를 다리 위에 그렸고, 기존 다리는 발끝까지 둥근 일정 굵기였다. `avatar-poses.js`의 회전 기준46은 밑창 근처였는데 실제 종아리는44.55에서 끝나 움직일 때 분리될 수 있었다. 측면/후면은 `avatar-shoes-profile.js`의 SVG 그림이며 실제 입구 높이와 일부 기존 배치 기준도 달랐다.

- 원본 PNG는 유지하고, 앞 신발18개의 실제 입구 영역을 런타임에서 분리했다. 닫힌 신발의 안감이 피부 위를 덮지 않으며 뒤 칼라·발등 피부·앞 테두리를 구분한다.
- 샌들/발레화/슬리퍼의 노출 발등은 착용자의 피부 레이어로 그린다. 끈·버클·장식·밑창 색은 유지한다. 후면 발레화는 닫힌 뒤축이 발등을 가리는 정상 상태다.
- 발목 관절44.55와 밑창46.05, 아이템별 신발 입구를 구분했다. 종아리에서 발목으로 자연스럽게 가늘어지고, 신발 속 맨발 끝이 따로 남지 않게 했다. 정면·측면·후면이 동일한 움직이는 종아리를 쓴다.
- 원래 상품 ID/고정색/소유 내역은 유지한다. 신발 파츠9종(구형 `dress`는 `loafer` 별칭)을 검사한다.

`verify-shoe-wearing.cjs`는 9종×남녀×2피부×반바지/긴바지×4방향×10상태 =2,880자세, 실제 발목 변환5,760개, 앞 신발18개 입구 알파를 검사한다. 앞/옆/뒤54개 발의 피부 변경과 고정 신발 재질 픽셀을 비교하며 닫힌 후면 발레화에서는 불필요한 피부 노출을 요구하지 않는다. 옛 불투명 원본 입구와 밑창 회전은 실패 대조다. `shoes-before/`, `shoes-after2/`는 동일한 두 피부의9종 확대, `shoe-collar-final/`는 남녀4방향의 걷기·달리기·점프·두 앉기와280/96px다. 발목 변환 최대 오차0.000000804, 피부 변경28,292픽셀에서 밑창 색 변경0을 확인했다.

## 뒤에서 보는 어깨·팔 수정

사용자 지적을 확인하니 후면 전용 팔 함수는 있었지만, 소매 뿌리 형태가 측면과 비슷했고 양팔을 늘 등판 위에 올렸다. 후면 그림이 존재한다는 검사만으로 이 오류를 잡을 수 없었다.

`renderBackArm`의 어깨 끝과 손등 그림을 정리했다. `avatar-poses.js`는 뒤에서 볼 때 어깨와 위팔을 등판 아래에 연결하고, 보행 중 카메라 쪽으로 돌아오는 아래팔만 앞으로 꺼낸다. 캐릭터 앞쪽으로 나가는 팔과 앉아 무릎에 놓은 팔은 등판 뒤에 가린다. 정면/측면 복귀와 해제 시 별도 레이어를 복원한다. 같은 화면에서 발견한 후면 반바지의 뾰족한 잔여는 짧은 바지에 긴바지용 곡선 제어점43을 사용하던 원인이었고, 짧은 바짓단 내부로 제어점을 고쳤다.

`verify-back-arm-depth.cjs`는 남녀 반팔/후드 ×2피부×280/96px×대기·걷기/달리기6시점·점프·바닥/책상 앉기의 전후512행을 비교한다. 실제 후면 그림과 손등, 어깨/아래팔의 서로 다른 깊이, 정면·측면 복귀/해제를 확인한다. 몸통과 뒤쪽 팔이 겹친 실제 픽셀도 비교하고, 양팔을 등판 위에 올린 옛 상태가 실패해야 한다. 실제 등판 겹침95,910픽셀의 불일치0, 옛 앞쪽 배치를 강제한 대조에서는93,374픽셀 불일치를 검출했다. 현재 출력은 `back-arm-pixels/`에 저장한다.

마지막 소스에서 소매20종×2피부×6상태=240개, 소맷부리480점 검사(`sleeve-release/`)가 통과했다. 전체 판매 상단24종×5피부의 목120건·팔210접촉·방향 복원72건(`curated-release/`)도 통과했다. 이것을 전체 상품의 방향·특수 동작 원화 완성으로 확대하지 않는다. 특히 기존 바닥 앉기는 새 기준복의 전용 아빠다리 그림과 같지 않으며, 기존 전체 의류의 새 뼈대 전환은 후속 범위다.

일반 계정은 기존 착장을 유지한다. 새 기준 캐릭터는 검수 화면과 `?demo=1&avatar=foundation` 교실/운동장에서 확인한다. 후드+긴바지·한벌옷·다른 헤어·비대칭 의류는 새 구조의 후속 검수 대상이다.

학교 그램/크롬북 실측, 실제 Firebase30명 접속, 공개 Cloudflare 배포는 별도 미확인이다. 관리 Chromium이 `file://` 탐색을 `ERR_BLOCKED_BY_ADMINISTRATOR`로 차단하므로 직접 파일 UI는 미검증이다. 이 제한을 우회하지 않고 HTTP 배포본과 로컬 번들 원본 바이트를 확인한다.

최종 배포 폴더 HTTP 화면에서 남녀 상점 미리보기, 교실·운동장 걷기/C 앉기를 열었다(`live-final/`). 기본복 검수 화면의 연속 재생과 체험 운동장 C, 일반 계정에서 기본복으로 강제 교체되지 않는 동작도 확인했다(`release.json`).
