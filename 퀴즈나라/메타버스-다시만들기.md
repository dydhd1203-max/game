# 메타버스 다시 만들기 — 짧은 작업 인계

갱신: 2026-10-02. 메타버스 공간의 현재 범위·순서는 이 문서를 우선한다. 지난 마을 작업의 설명은 제작 이력 또는 마지막 숲 마을 단계의 참고다.

## 확정한 방향

- 사용자는 현재 교실을 확인하고 **“앞으로 맵 예시를 보내면 에셋을 이용해서 이렇게 만들자”**고 확정했다. 각 예시를 직접 확인하고 제공 원본 부품을 배치·조합해 시점·축척·색감·재질·동선을 맞춘 뒤 실제 화면과 비교한다. 부족한 소재만 구체적으로 알리고, 승인된 교실의 디자인은 유지한다.
- 기존 메타버스 마을과 실내 옷 가게 맵·연결은 제거한다. 원본 에셋 보관함, 승인된 SD 아바타, 계정·옷장·골드·선생님 문제·수업·학생 진도와 기존 퀴즈 방식의 맵은 보존한다.
- **교실 → 운동장 → 옷 가게 → 숲 마을** 순서로 한 공간씩 만든다. 숲 마을은 마지막에 만들고 완성한 공간을 잇는다.
- 학생 기본 입장은 새 교실 `SCREENS.campus`다. 지정 수업 링크 `?classroom=수업ID`는 해당 수업으로 직접 들어간다. 수업·퀴즈 목록과 기존 상품 상점은 교실의 칠판·상단 버튼으로 이용한다.
- PC·노트북 학생 화면을 우선한다. 작은 일러스트형 SD 아바타와 자연스러운 의상·방향 모션을 유지한다.
- 아바타는 공간 확장에 앞서 남녀 기본 몸과 공통 뼈대를 검증한다. 유일한 제작 규격은 [아바타 제작 기준](아바타-제작기준.md), 몸 검수 이력은 [기준 몸 검수](기준몸-검수.md), 기본 착장의 현재 단계·검사·남은 항목은 [기준 착장 검수](기준착장-검수.md)를 따른다.

## 첫 공간: 교실

참고 원본은 [교실 자료 보관함](assets/classroom-library/README.md)의 `교실 공간.zip` 안 세 스크린샷이다. 왼쪽 모둠 공간 → 가운데 30자리 교실 → 오른쪽 복도로 이어지는 배치와 원본의 축척·색감·재질을 따른다.

- 동시 학생 규모는 **21~30명**, 책상·의자는 **30자리**를 계획한다. 이는 설계 요구이며 실제 30명 접속 검증이 완료되었다는 뜻은 아니다.
- 학생은 자유롭게 돌아다니고 빈자리에 앉는다. 책상에서는 칠판을 바라보는 뒷머리가 상판 앞에 보이고 엉덩이는 의자 좌판에 맞춘다. 머리를 책상의 북쪽으로 올려 서 있는 듯 보이게 하지 않는다. 바닥 앉기는 별도 행동이며 다리·신발을 바닥에 맞춘다. `앉기.zip`의 앞·왼쪽·오른쪽·뒤를 자세 참고로 사용한다.
- 먼저 **칠판에서 선생님이 만든 수업·퀴즈 열기**를 연결한다. 기존 문제·수업 참가·답·점수·진도를 재사용한다.
- 새 기능을 붙이기 전에 원본 배치와 기본 학생 시점의 실제 화면을 나란히 비교한다. 사진 전체를 배경으로 붙이거나 다른 서비스의 UI·이름·로고를 맵에 포함하지 않는다.

## 스크린샷도 실제 에셋으로 사용한다

사용자는 스크린샷의 가구 추출을 허용했다. 온전히 보이는 학생 책상·의자·교탁 등은 원본 영역을 표시하고 사물 윤곽에 맞춰 바닥을 제외해 사용한다. 개별 투명 PNG를 모두 새로 구해야 작업할 수 있다는 조건을 만들지 않는다.

원본 바이트와 파일 해시를 보존하고 소스 영역·윤곽·앵커·사용 위치를 기록한다. SVG는 **원본 픽셀을 표시·클리핑하는 용도**로 사용한다. 가려진 의자의 좌판, UI 뒤의 화면·문 등 보이지 않는 부분을 새 그림으로 추측해 채우지 않는다. 꼭 필요한 부분이 가려져 있거나 해상도가 부족할 때만 해당 종류·시점의 깨끗한 추가 자료를 바로 요청한다.

새 맵의 보이는 그래픽은 사용자 제공 에셋으로 구성한다. 임의 도형이나 새 AI 그림으로 가구·바닥·벽·물·지형을 대신하지 않는다. 기존 승인 원화는 보존하며 충돌·경로·상호작용 계산은 구현할 수 있다.

## 현재 단계와 다음 검수

교실의 원본 가구 배치, 방향키·클릭 이동, 충돌, 30개 의자 착석, 바닥 앉기, 버튼 인사, 칠판 수업·퀴즈 연결을 구현했다. 미술은 `school-room-scene.js`, 플레이는 `school-room-world.js`, 연결은 `index.html`의 `SCREENS.campus`다. 추출 영역은 `assets/classroom-library/extracted/`, 앉기 자료는 `assets/seating-library/`에 보관한다.

최신 검사 범위·결과·제한은 [교실-구현검수.md](교실-구현검수.md)에서 확인한다. 실제 30명 Firebase 동시 접속과 학교 기기 성능은 별도 미검증이며, 격리된 두 학생 검사나 30좌석 검사와 구분한다.

두 번째 공간인 운동장은 `운동장.zip`의 5장과 `운동장추가.zip`의 2장(100% 부분·50% 전체 조망)을 모두 [운동장 자료 보관함](assets/playground-library/README.md)에 원본 바이트·해시로 보존했다. 학교·계단·트랙·흙 필드·잔디 축구장·화단·울타리·벤치 15개를 원본으로 조합하며, 일부 가려진 벽과 아래쪽 울타리는 50% 조망의 실제 픽셀을 2배 표시한다. 새 그림이나 임의 지형으로 대신하지 않는다. 현재 좌표는 3714×1808이며 상세 원본 사용 내역과 검사는 [운동장-준비상태.md](운동장-준비상태.md)에 기록한다.

2026-10-02 최신 공용 조작은 **C 앉기·일어서기 / E 칠판 / 문 앞 F 텔레포트 / 문 밖 F는 동작 없음**다. 교실 문 `(2122, 298)`에서 F → 운동장 학교 문 `(1559, 676)`, 운동장에서는 학교 정문의 실제 문앞 `(1515, 620)`과 동쪽 주황 차양 문 `(2258, 410)`에서 F → 교실 문으로 즉시 이동한다. 도착 위치와 출입 판정 위치를 구분한다. 전환 때 좌석·모션·구독을 해제하고 공간별 위치·좌석·저장 위치를 쓴다. 기본 입장은 교실이고 지정 수업 링크 직접 입장은 유지한다. 걷기는225px/s이며 같은 방향키 두 번 누르고 유지하면337.5px/s로 달린다. 책상 30개는 모든 짝 사이 28px·쌍 사이 48px·줄 사이 27px 통로를 확보했다. 운동장 벤치는 배경 그림이며 전용 좌석·모션·자동 착석을 쓰지 않는다. 원하는 위치에서 C로 사용자가 보낸 예시의 아빠다리를 새 기준 몸에 적용한다. 기존 전체 착장의 전환은 후속 단계다. 교실 책상은 의자 착석 기능을 유지한다. 이후는 실내 옷 가게 → 숲 마을 순서다.
