## 다음 맵에 효율적으로 사용하는 순서

1. **장소부터 정합니다.** 숲·마을·농장·사원·해변·동굴처럼 테마를 고르고, 그 맵에 필요한 길·큰 볼거리·퀴즈 사물·주변 소품을 적습니다.
2. **같은 스타일의 묶음을 고릅니다.** 보관함에서 테마·카테고리·원근·그림 스타일을 보고 건물·나무·바닥·작은 소품을 선택합니다. 서로 다른 시트에서 아무 그림이나 섞기보다 빛·윤곽·재질이 맞는 자료를 중심으로 묶습니다.
3. **그대로 쓸 배경과 분리할 소품을 구분합니다.** 완성 풍경은 배경·장면 구성 자료로, 시트는 개별 건물·나무·울타리·작물 후보로 사용합니다. 게임 HUD가 포함된 자료와 캐릭터 자료는 맵 소품으로 분류하지 않습니다. 배경 그림만 놓은 것으로 탐험 맵의 길과 충돌이 완성되었다고 판단하지 않습니다.
4. **대표 구역 하나를 먼저 맞춥니다.** 건물 한 채·나무·길·퀴즈 사물을 실제 학생 시작 시점에 배치하고, 소스 영역·투명 처리·바닥 앵커·표시 배율·가림·충돌을 정리합니다. 원본 JPEG는 그대로 남기고 가공한 게임 자산과 메타데이터를 별도로 보관합니다.
5. **그 구역의 미술과 플레이를 함께 확인한 뒤 늘립니다.** 길이 보이는지, 사물에 다가갈 수 있는지, 문제창과 이름이 가리지 않는지, 정답 후 이동·점프·앉기가 맞는지 확인합니다. 같은 빛·원근·배율을 유지하며 나머지 구역으로 확장합니다.

추가 자료는 원하는 파일만 ZIP으로 묶어도 됩니다. 이름이 `다운로드 (숫자).jpg`여도 원본 이름을 보존하고 별도 고유 ID·이미지 내용·테마를 기록하므로, 사용자가 모든 파일 이름을 다시 정리할 필요는 없습니다.

## 이후 원본·소품을 등록할 때

1. 추가 JPG 원본 또는 이를 담은 ZIP을 작업 공간에 가져옵니다. 사용자 Windows 경로를 업로드 파일 ID로 대체해 사용하지 않습니다.
2. 원본 바이트를 그대로 `originals/<고유 ID>.jpg`에 보관합니다. 원래 파일 이름과 확인된 출처, 이미지 크기·형식·SHA-256을 목록에 기록합니다. `sourceStatus`는 파일 존재와 바이트 일치를 확인한 뒤 `original-stored`로 바꾸고 `imagePath`를 채웁니다.
3. 통합 시트와 실제 게임에 쓰는 개별 소품을 구분합니다. 소품마다 `sourceRect: [x,y,width,height]`, 바닥 접점인 `anchor: [x,y]`, `layer`, 원본 픽셀 크기와 게임 표시 크기, `collision`을 기록합니다. 앵커와 충돌 좌표는 소스 영역 안의 좌표로 명시합니다.
4. 회색 또는 체커 무늬가 보인다고 투명 PNG로 간주하지 않습니다. 실제 알파를 확인하고, JPG 원본과 나중에 제작하는 투명 게임 자산을 별도 파일로 보관합니다. 빈칸·문자·라벨·화살표가 스프라이트에 섞이지 않게 소스 영역을 확인합니다.
5. 지형·바닥은 바닥 층, 그림자는 사물 아래, 건물·큰 나무는 바닥 앵커를 기준으로 깊이를 정렬합니다. 잎·처마처럼 아바타 앞에 올 부분은 전경 층으로 구분합니다. 그림 전체를 충돌 사각형으로 잡지 않고 지면에 닿는 부분을 확인합니다.
6. 일러스트·도트·사원·농장처럼 원근·광원·윤곽이 다른 자료는 각각 묶어 보관합니다. 실제 맵에 적용할 때에는 해당 세계의 스타일과 표시 배율을 맞춥니다. 학생 시작 시점에서 크기·발과 땅의 접촉·길의 접근성·퀴즈 가림을 확인한 뒤 `runtime-ready`로 표시합니다.

원본 보관, 소품 분리, 런타임 연결, 실제 게임 화면 검수는 각각 다른 상태입니다. 이번에는 원본 29장 보관과 분류를 진행했으며, 모든 시트의 소품 분리·투명화·게임 적용까지 완료한 것은 아닙니다. 기존 런타임 원화와 경로를 바꾸는 작업은 이 보관함 등록에 포함하지 않았습니다.

## 실제 원본 영역 적용 — 최종 화면 검수 진행 중

사용자 [석조 유적 시트](./originals/reference-download-07.jpg), 735×490의 큰 자연 절벽 모듈 **[332,188,231,81]**을 village-scene.js의 originalCliffStrip에 직접 사용합니다. 원본의 불규칙 돌·풀 윗면·큰 바위가 함께 보이고, 정밀 SVG 외곽 클리핑으로 어두운 불투명 배경만 제외합니다. raw 표시 크기는 **230×80.65**, 간격210으로 겹쳐 놓고 좌우를 번갈아 반사합니다. WORLD_SCALE=1.5에서 표시 크기는 약345×121입니다.

큰 절벽 구역은 raw x280,y657,폭1210, 높은 정원 구역은 x340,y449,폭340이며 기존 지형 면의 clipPath에 맞춥니다. 작은 돌 면 [484,139,50,23]의 반복 패턴과 쓰이지 않는 코드 정의는 제거했습니다. 최종 절벽 표시는 큰 원본 자연 모듈만 사용합니다. 실제 화면에서 작고 흐린 반복으로 보였기에 원본보다 작게 표시하는 큰 자연 모듈로 교체했습니다.

원본 전체가 게임에 들어갔다는 뜻이 아니므로 catalog의 runtimeStatus는 **partial-region-integrated**, 실제 좌표·크기·외곽·사용 위치는 runtimeRegions에 기록합니다. 원본 바이트와 해시는 유지됩니다. **마지막 실제 화면의 반복·가림·축척·충돌·통행 검수는 진행 중입니다.**
