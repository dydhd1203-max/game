# 옷 그림 틀과 ChatGPT 프롬프트 (3단계 2판, 2026-10-09)

새 옷 그림은 **그림 틀 + ChatGPT**로 만든다(사용자 결정 2026-10-09). 사용자가 ChatGPT 이미지 생성으로 그림 틀의 두 아이에게 상품 옷을 입힌 시트를 만들어 올리면, 파이프라인이 고정된 기준 몸에 맞춰 바뀐 옷만 잘라 넣고 검사한다. 이 문서는 1판 `옷그림-프롬프트.md`를 대신한다. 1판의 프롬프트는 첫 실제 시트(`assets/garment-sources/top-shirt-10-chatgpt-2026-10-09.webp`, 여섯 그림이 0.6px 안에서 겹치고 윗옷만 바뀜)를 만들었으므로 2판은 그 문장을 그대로 두고 일반화했다. 1판 원문은 `tools/garment/prompts.json`의 `v1`에 남아 있다.

## 그림을 이렇게 만드는 이유

- **그림 틀에는 표시를 넣지 않는다.** 안내선·격자·글자·색칠한 구역을 넣으면 ChatGPT가 그것까지 다시 그려 옷 안에 남기거나 그림 위치가 밀린다. 바뀌지 않는 머리·팔·다리·신발이 맞춤 기준점이고, 지금 입은 기본 옷이 소매·밑단·깃·신발 높이의 자 역할을 한다. 한계는 작업자-안내도에만 그린다.
- **배경은 흰색만.** 투명 배경을 요청하지 않는다.
- **그림 2에는 몸을 넣지 않는다(기록).** 처음에는 지금 상점 모습(옛 아바타 몸)을 참고로 넣었는데, ChatGPT가 옛 몸의 어색한 팔과 내려간 바지를 따라 그렸다(2026-10-09 사용자 지적, 커밋 914c7ef). 그래서 상점 그림에서 옷만 꺼내 흰 바탕에 놓는다. `design-ref.cjs`는 체험 모드(`?demo=1`) 페이지에서 `QPClothes.surface`(상·하의)와 `QPShoes`의 발별 그림(신발)을 그대로 읽어, 1판 그림과 같은 배치(옷마다 너비 420px, 위 90·옆 60·사이 60·아래 30px, Pillow Lanczos)로 다시 만든다. 1판 `ref-shirt-10-design.png`는 이 도구로 **바이트까지 똑같이** 다시 만들어지므로 그대로 둔다.
- ChatGPT가 따라 하기 쉬운 이유: 그림 틀 자체가 ChatGPT 이미지 생성의 결과라 그림체·비율이 익숙하고, '이것만 바꾸기'라는 좁은 수정이며, 3:2 그림 틀이라 돌려받을 때 바뀌는 것은 전체 배율(1536/1629)뿐이고, 길이는 숫자가 아니라 지금 보이는 옷을 기준으로 말한다.

## 사용 순서 (약 2분)

1. 상품마다 ChatGPT **새 대화**를 연다.
2. `template-sheet.png`를 **먼저**, 상품의 그림 2를 **두 번째로** 첨부한다(`prompt.cjs`가 두 파일 이름을 알려 준다).
3. 프롬프트(한국어 또는 영어)를 붙여 넣는다.
4. 결과를 ChatGPT 내려받기 단추로 **원본 크기** 그대로 받는다(PNG가 좋고 WebP·JPEG도 받는다).
5. 작업 대화에 올린다. 얼굴·자세·위치가 크게 바뀌었거나 그림이 빠졌으면 같은 대화에 "옷 말고는 아무것도 바꾸지 말고 다시 그려 줘"라고 다시 요청한다. 파이프라인 검사에서 실패하면 보고서와 함께 받는 한 문장을 같은 대화에 붙여 넣는다. 상품마다 2~3번 시도를 예상한다.

작업자는 받은 그림을 바이트 그대로 `assets/garment-sources/<cat>-<shape>-<ci>-chatgpt-<날짜>.<확장자>`로 보존하고 `assets/garment-sources/README.md`에 sha256과 프롬프트 판을 적는다.

## 프롬프트 만들기

```
node tools/garment/prompt.cjs top:shirt:10            # 한국어·영어 프롬프트를 출력하고 그림 2를 상점 그림에서 다시 그림
node tools/garment/prompt.cjs bottom:cargo --no-image # 프롬프트만
node tools/garment/prompt.cjs shoes:dress --kit 폴더   # 1-그림틀.png, 2-옷참고-….png, 프롬프트 두 개를 한 폴더에
node tools/garment/prompt.cjs --v1                    # top:shirt:10을 1판과 줄마다 비교
node tools/garment/prompt.cjs --check                 # 모든 상품·분기, 1판 차이 기록, 이 문서의 인용이 최신인지
```

상품 ID는 `cat:shape` 또는 상점 ID `cat:shape:ci`다. 색 번호가 그 상품의 고정색 번호가 아니면 거절한다. 기본 옷(top:tee, bottom:shorts, shoes:sneaker)은 그림 틀이 이미 입고 있으므로 ChatGPT 시트가 필요 없다.

## 프롬프트 구성

1판의 문장을 그대로 두고 상품마다 바뀌는 부분만 채운다: 옷 이름, 그림 2의 배치(남녀 두 장 / 같은 옷 한 장 / 한 성별), 그림 2에서 참고할 것, 아이별 설명, 그대로 둘 부위, 종류별 길이 규칙(3번), 뒷모습 규칙(4번).

종류별 길이 규칙(3번 줄). 길이는 지금 입은 기본 옷 기준으로 말하고, 짧게 하는 쪽은 막는다. 기준 몸의 팔·다리 그림은 기본 옷 끝 위쪽이 복사한 피부이고, 다리 그림에는 옛 바짓단 선이 남아 있어 더 짧은 옷은 이음 자국·유령 선을 드러낸다(REDTEAM, 2026-10-09).

- 옷 원화의 그림틀은 **진한 피부 그림틀**(`template-sheet-dark.png`, 2026-10-16)이다. `node tools/garment/prompt.cjs <상품> --kit 폴더`가 상품의 `"base": "dark"`를 보고 이 틀과 '피부는 일부러 진한 갈색' 문장을 넣는다(없으면 묶음을 만들지 않음). 요청방법 파일에 '게임에서는 피부를 따로 그리므로 원화의 피부색은 상관없다'를 적는다.
- 다시 요청 묶음은 `receive.py` 요약(`검증/옷/<cat>-<shape>/받기-요약.md`)에 나온 실패를 **모든 모습**(남녀·앞옆뒤)에 대해 적는다(재킷 첫 다시 요청에 남자만 적어 한 번 더 고친 일).
