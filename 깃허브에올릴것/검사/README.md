# 검사 (테스트 하네스)

이 게임은 파일 하나(`index.html`)라 눈으로만 봐서는 무엇이 깨졌는지 알 수 없다.
그래서 **진짜 브라우저를 띄워 게임을 실제로 돌려 보고** 결과를 세는 검사를 모아 뒀다.
14차 기준 **506항목**이 있다.

## 처음 한 번만 — 준비

```bash
cd 검사
npm init -y && npm i three          # 게임이 쓰는 three.js (인터넷 막힌 교실에서도 돌게 로컬로)
# playwright 는 대부분의 환경에 이미 깔려 있다. 없으면:
#   npm i -D playwright && npx playwright install chromium
```

`serve2.mjs` 가 이 폴더의 `node_modules/three` 를 읽어서 `index.html` 에 끼워 넣는다
(원본은 unpkg 에서 받아 오는데, 검사 중에는 인터넷을 안 타는 편이 빠르고 안정적이다).

## 돌리는 법

```bash
node t16.mjs ../../클로드/index.html 9000   # <검사파일> <게임파일> <포트>

게임 파일을 안 주면 알아서 찾는다(`gamefile.mjs`). 폴더를 옮겨도 안 깨진다 —
예전엔 검사마다 절대 경로가 박혀 있어서, `클로드/` 아래로 옮긴 뒤 t3~t12 가 통째로 안 돌았다.
```

포트는 검사마다 다르게 준다 (동시에 돌릴 때 안 부딪히게).

전부 한 번에:

```bash
for t in t3 t4 t6 t7 t8 t9 t10 t11 t12 t13 t14 t15 t16; do
  printf "%-4s " $t
  node $t.mjs ../../클로드/index.html $((9000+RANDOM%500)) 2>&1 | tail -2 | head -1
done
```

## 도구

- `chk.sh <파일>` — `index.html` 안의 모듈 스크립트만 뽑아 문법 검사 (`node --check`). **고칠 때마다 이걸 먼저 돌린다.**
- `gamefile.mjs` — 게임 파일이 어디 있는지 찾아 준다. 검사에 경로를 박지 않기 위한 것이다.
- `serve.mjs` / `serve2.mjs` — 검사용 서버. `serve2` 가 알맹이고 `serve` 는 옛 이름이다.
  three 빌드 폴더를 통째로 내준다 — r160 이후의 three 는 `three.module.js` 안에서
  `./three.core.js` 를 다시 부르는데, 파일 하나만 내주면 그 요청이 HTML 로 떨어져
  페이지가 통째로 안 열린다.
- `shot14.mjs` — 14차에서 넣은 것들을 화면에 찍어 본다 (대장간·강화창·수치표·순위·친구 총·마지막 밤).
- `shot14b.mjs` — 상인·대장장이 모형과 '내가 든 총' 의 강화 빛을 찍어 본다.
  **HUD 를 잠깐 숨기는 스위치가 들어 있다** — 모형을 볼 때 가운데 안내판이 얼굴을 가려서
  세 번 헛수고했다. 모형을 평가할 때는 이걸 쓴다.
- `gm.mjs` — 손에 든 총 여섯 자루의 실제 크기를 잰다 (빛 조각 크기를 정할 때 썼다).
- `enh.mjs` — 강화 기대 시도 수와 기대 재료를 몬테카를로로 잰다.
- `rep.py` — 정확히 한 군데만 바꾸는 치환기. 여러 군데 걸리면 실패한다 (조용히 엉뚱한 곳을 고치는 사고 방지).

## 검사를 고칠 때의 원칙

**검사가 흔들리면 검사가 아니다.** 이 폴더에서 실제로 겪은 것들:

- 늑대 추격 검사가 *언덕 위*로 달리게 하고 있었다 → 높이차 2.2를 넘으면 늑대는 원래 안 쫓는다. '못 잡았다'가 아니라 '쫓을 수 없었다'였다.
- 같은 검사가 *나무·바위*가 있는 길을 쓰고 있었다 → 늑대가 막힌 것이었다.
- 같은 검사가 *수정 쪽*으로 달리게 하고 있었다 → 늑대는 수정이 코앞이면 양을 놓는 게 맞다.
- 크리티컬 검사가 콤보를 안 끊고 재고 있었다 → 2배가 아니라 2.1배가 나왔다.
- **값을 검사에 박아 뒀다** (14차) — `t4` 가 공사 시간 3.5초·8초를, `t10` 이 금 광맥 산출을,
  `t14` 가 만렙 10과 스텟 상한 5를 숫자로 들고 있었다. 밸런스를 고치자 여덟 항목이 한꺼번에 죽었다.
  게임이 틀린 게 아니라 검사가 값을 복사해 둔 게 틀린 것이다. 이제 `__workSec`·`__STATS` 처럼
  **게임에서 읽어서 관계를 본다** ("벽이 탑보다 튼튼한가", "스텟이 줄어든 값에서 더 줄이는가").
- **'순간 크기' 로 순서를 쟀다** (14차 손질) — 강화 빛은 숨쉬듯 커졌다 작아지는데,
  그 순간값으로 '단계가 오를수록 커지는가' 를 재니 재는 시점마다 결과가 뒤집혔다.
  흔들리지 않는 둘로 나눴다 — ① 표가 단계마다 커지는가 ② 그려진 크기가 안전한 띠 안인가.
- **경험치를 `XP.xp` 로 쟀다** (14차) — 레벨이 오르는 순간 그 값은 줄어든다.
  레벨 곡선을 눕히자 '강화하면 경험치를 준다' 가 −20 으로 나왔다. 합계로 재야 한다
  (`t15` 는 13차에 같은 이유로 이미 고쳤는데 `t14` 는 안 고쳐져 있었다).

무작위(자리·지형)에 기대는 검사는 조건을 **찾아서** 쓴다. 예: `t13` 은 평평한 원을 찾아 쓰고,
`t11` 은 지을 수 있는 칸을 찾아 선다.
