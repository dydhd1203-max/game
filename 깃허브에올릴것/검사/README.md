# 검사 (테스트 하네스)

이 게임은 파일 하나(`index.html`)라 눈으로만 봐서는 무엇이 깨졌는지 알 수 없다.
그래서 **진짜 브라우저를 띄워 게임을 실제로 돌려 보고** 결과를 세는 검사를 모아 뒀다.
15차 기준 **518항목**이 있다.

## 처음 한 번만 — 준비

```bash
cd 검사
npm init -y && npm i three          # 게임이 쓰는 three.js (인터넷 막힌 교실에서도 돌게 로컬로)
# playwright 는 대부분의 환경에 이미 깔려 있다. 없으면:
#   npm i -D playwright && npx playwright install chromium
```

`serve2.mjs` 가 이 폴더의 `node_modules/three` 를 읽어서 `index.html` 에 끼워 넣는다
(원본은 unpkg 에서 받아 오는데, 검사 중에는 인터넷을 안 타는 편이 빠르고 안정적이다).

## 돌리는 법

```bash
node t16.mjs ../../클로드/index.html 9000   # <검사파일> <게임파일> <포트>

게임 파일을 안 주면 알아서 찾는다(`gamefile.mjs`). 폴더를 옮겨도 안 깨진다 —
예전엔 검사마다 절대 경로가 박혀 있어서, `클로드/` 아래로 옮긴 뒤 t3~t12 가 통째로 안 돌았다.
```

포트는 검사마다 다르게 준다 (동시에 돌릴 때 안 부딪히게).

전부 한 번에:

```bash
for t in t3 t4 t6 t7 t8 t9 t10 t11 t12 t13 t14 t15 t16 t17 t18 t19; do
  printf "%-4s " $t
  node $t.mjs ../../클로드/index.html $((9000+RANDOM%500)) 2>&1 | tail -2 | head -1
done
```

## 도구

- `chk.sh <파일>` — `index.html` 안의 모듈 스크립트만 뽑아 문법 검사 (`node --check`). **고칠 때마다 이걸 먼저 돌린다.**
- `gamefile.mjs` — 게임 파일이 어디 있는지 찾아 준다. 검사에 경로를 박지 않기 위한 것이다.
- `serve.mjs` / `serve2.mjs` — 검사용 서버. `serve2` 가 알맹이고 `serve` 는 옛 이름이다.
  three 빌드 폴더를 통째로 내준다 — r160 이후의 three 는 `three.module.js` 안에서
  `./three.core.js` 를 다시 부르는데, 파일 하나만 내주면 그 요청이 HTML 로 떨어져
  페이지가 통째로 안 열린다.
- `shot14.mjs` — 14차에서 넣은 것들을 화면에 찍어 본다 (대장간·강화창·수치표·순위·친구 총·마지막 밤).
- `shot14b.mjs` — 상인·대장장이 모형과 '내가 든 총' 의 강화 빛을 찍어 본다.
  **HUD 를 잠깐 숨기는 스위치가 들어 있다** — 모형을 볼 때 가운데 안내판이 얼굴을 가려서
  세 번 헛수고했다. 모형을 평가할 때는 이걸 쓴다.
- `gm.mjs` — 손에 든 총 여섯 자루의 실제 크기를 잰다 (빛 조각 크기를 정할 때 썼다).
- `shake.mjs` — 강화 단계별로 손에 든 총이 실제로 얼마나 흔들리는지 잰다.
  정지 화면으로는 떨림을 볼 수 없다 — 여러 프레임의 자리를 모아 폭을 재야 한다.
- `enh.mjs` — 강화 기대 시도 수와 기대 재료를 몬테카를로로 잰다.
- `rep.py` — 정확히 한 군데만 바꾸는 치환기. 여러 군데 걸리면 실패한다 (조용히 엉뚱한 곳을 고치는 사고 방지).

## 검사를 고칠 때의 원칙

**검사가 흔들리면 검사가 아니다.** 이 폴더에서 실제로 겪은 것들:

- 늑대 추격 검사가 *언덕 위*로 달리게 하고 있었다 → 높이차 2.2를 넘으면 늑대는 원래 안 쫓는다. '못 잡았다'가 아니라 '쫓을 수 없었다'였다.
- 같은 검사가 *나무·바위*가 있는 길을 쓰고 있었다 → 늑대가 막힌 것이었다.
- 같은 검사가 *수정 쪽*으로 달리게 하고 있었다 → 늑대는 수정이 코앞이면 양을 놓는 게 맞다.
- 크리티컬 검사가 콤보를 안 끊고 재고 있었다 → 2배가 아니라 2.1배가 나왔다.
- **값을 검사에 박아 뒀다** (14차) — `t4` 가 공사 시간 3.5초·8초를, `t10` 이 금 광맥 산출을,
  `t14` 가 만렙 10과 스텟 상한 5를 숫자로 들고 있었다. 밸런스를 고치자 여덟 항목이 한꺼번에 죽었다.
  게임이 틀린 게 아니라 검사가 값을 복사해 둔 게 틀린 것이다. 이제 `__workSec`·`__STATS` 처럼
  **게임에서 읽어서 관계를 본다** ("벽이 탑보다 튼튼한가", "스텟이 줄어든 값에서 더 줄이는가").
- **떨림이 게임 시간(`tAcc`)을 쓰고 있었다** (14차 손질) — `updHeld` 를 직접 불러 재는
  검사에서는 그 시간이 안 흘러서, 240프레임을 돌려도 늘 같은 값이 나왔다(0 으로 쟀다).
  화면에서는 멀쩡한데 잴 수가 없으면 고쳤는지 확인할 방법이 없다.
  움직이는 것은 **자기 dt 시계**를 갖게 해야 검사에서도 실제와 똑같이 움직인다.
- **강화 확률을 숫자로 박아 뒀다** (15차) — 선생님이 교실에서 겪고 고치는 값이라
  바뀌자마자 죽었다. 값이 아니라 **의미**를 재야 한다:
  "40분 수업 안에 +6 이 나올 만한가(기대 20회 이하)" 가 이 값을 고치는 진짜 이유다.
- **'순간 크기' 로 순서를 쟀다** (14차 손질) — 강화 빛은 숨쉬듯 커졌다 작아지는데,
  그 순간값으로 '단계가 오를수록 커지는가' 를 재니 재는 시점마다 결과가 뒤집혔다.
  흔들리지 않는 둘로 나눴다 — ① 표가 단계마다 커지는가 ② 그려진 크기가 안전한 띠 안인가.
- **경험치를 `XP.xp` 로 쟀다** (14차) — 레벨이 오르는 순간 그 값은 줄어든다.
  레벨 곡선을 눕히자 '강화하면 경험치를 준다' 가 −20 으로 나왔다. 합계로 재야 한다
  (`t15` 는 13차에 같은 이유로 이미 고쳤는데 `t14` 는 안 고쳐져 있었다).

무작위(자리·지형)에 기대는 검사는 조건을 **찾아서** 쓴다. 예: `t13` 은 평평한 원을 찾아 쓰고,
`t11` 은 지을 수 있는 칸을 찾아 선다.

## 검사와 검사 사이에도 게임은 돈다 (16차)

`pg.evaluate` 하나는 한 턴에 다 돌지만, **evaluate 와 evaluate 사이에는 페이지의
제 루프가 돈다.** 그래서 `hostSim` 을 직접 돌려서 무언가를 재려면 그 전에

- `G.wolves.length = 0` — 남은 늑대
- `W.__spawnQ().length = 0` — **예약된 늑대**. 이걸 안 비우면 hostSim 을 부르는 순간
  오늘 밤 늑대가 통째로 쏟아진다
- `W.__PL.down = true` — **혼자 하기로 들어오면 내 양이 0모둠 산길 한가운데에 선다.**
  늑대가 재려던 짓 대신 내 양을 물어뜯는다

세 줄을 다 해야 한 마리를 깨끗하게 잴 수 있다. 그리고 재는 동안
`G.wolves.includes(w)` 로 내 늑대가 아직 살아 있는지 확인해야 한다 —
`G.wolves.length` 만 보면 남의 늑대가 있는 걸 못 알아챈다.

## 화면 찍을 때 카메라가 되돌아간다 (16차)

`W.__cam.position.set(...)` 로 카메라를 옮긴 뒤 `waitForTimeout` 을 주면,
그 사이 페이지의 `updPlayer` 가 **카메라를 PL 자리로 되돌린다.**
카메라는 반드시 `PL.x/PL.z/PL.yaw` 와 같이 옮겨야 한다.
그리고 `PL.down` 이면 쓰러진 몸이 화면 코앞에 그려지므로, 찍는 순간만 일으켜 세운다
(낮이면 메인 루프가 `hostSim` 을 안 부르므로 늑대는 그 사이 꼼짝 안 한다).

## 하네스도 게임 값을 베끼면 안 된다 (16차)

`bal5` 가 보스를 `w.k < 3` 으로 가리고 있었다. 늑대 표에 한 줄이 붙자
하네스가 엉뚱한 늑대를 보스로 겨눴다. `W.__isBoss(w.k)` 로 **게임에 물어보게** 바꿨다.

## 옛 기록의 숫자와 오늘 잰 숫자를 비교하지 않는다 (16차)

15차 기록의 "2/5" 와 오늘 잰 값을 비교해서 "밤이 쉬워졌다" 고 판단할 뻔했다.
**같은 자리에서 기준(그 기능을 끈 상태)을 다시 재 보니 기준 자체가 그 값이 아니었다.**
바꾼 것의 효과를 재려면 기준도 같은 판에서 같이 재야 한다.

## 검사가 게임 좌표를 손수 계산하면 안 된다 (17차)

`t3` · `t9` · `bal5` 가 통로 자리를 `d.dx*t - d.dz*pp` 로 **직접 계산**하고 있었다.
17차에 입구가 옆으로 밀리자(`DIRS[g].off`) 이 식이 산 한가운데를 가리켜서,
**게임은 멀쩡한데 검사만 빨개졌다.** 전부 게임의 `__gX/__gZ` 에 물어보게 바꿨다.

좌표 변환·구역 나누기·보스 판정처럼 **게임이 이미 답을 아는 것**은
검사에서 다시 만들지 말고 내보내서 쓴다.

## 하네스는 옛 판도 잴 수 있어야 한다 (17차)

"얼마나 바뀌었나" 를 말하려면 **같은 자로 두 판을 재야 한다.**
17차에 이걸 안 해서 한 번 헛 비교를 했다 — 옛 게임을 *옛 하네스* 로 재 놓고
"달라졌다" 고 할 뻔했다(하네스가 달라서 방어선 채 수부터 155 vs 84 로 달랐다).

`bal5` 에 옛 판 대비를 넣어 뒀다. 새 함수가 없으면 예전 식으로 떨어진다:

```js
const GX = (t,p)=> W.__gX ? W.__gX(g,t,p) : oldXf(g,t,p)[0];
```

비교할 때는 **게임 파일만 바꿔서** 돌린다:

```bash
git show origin/main:클로드/index.html > /tmp/old.html
node bal5.mjs /tmp/old.html      12120 10 1 2.0 3,5,7,10 1 0.50 early 1.1 1
node bal5.mjs ../../클로드/index.html 12121 10 1 2.0 3,5,7,10 1 0.50 early 1.1 1
```

## 검사 스스로 매달리게 만들지 않기 (17차)

```js
while(W.__XP.pts>0) W.__takeStat(1);     // ✗ 상한에 닿으면 영영 안 끝난다
for(let i=0; i<stat.max && W.__XP.pts>0; i++) W.__takeStat(1);   // ✓
```

상한이 있는 것을 "다 쓸 때까지" 돌리면 무한 루프가 된다. 10분 넘게 매달렸다.

## 검사와 검사 사이의 상태 (17차)

- `gain()` 은 `base`(모둠 창고)가 아니라 **`G.res`** 에 넣는다. `base` 를 보면 늘 0 이다.
- 앞 검사가 벽을 예순 채 넘게 지어 놓으면 `myPC` 의 '쓴 양' 이 쌓여서,
  창고를 0 으로 두고 재면 `res` 가 0 에 눌린 채 안 올라간다. 넉넉히 채워 놓고 잰다.
- 앞 검사가 `G.me.g` 를 바꿔 놓고 갈 수 있다. 재기 전에 내가 원하는 값으로 두자.

## 기준을 분포 가장자리에 걸지 않는다 (17차b)

`t18` 의 '늑대가 안 포개진다' 를 **0.01% 미만**으로 걸어 뒀는데,
여덟 번 재 보니 관측값이 0~5 라 기준(5.4)이 **분포 가장자리에 딱 걸려**
여덟 판에 한 번씩 빨개졌다. 게임은 멀쩡한데 검사만 흔들린 것이다.

**'얼마나 자주' 대신 '한때 몇 쌍이나' 로 바꿨다.** 밀어내기는 겹친 만큼을 몇 프레임에
걸쳐 푸는 물렁한 장치라, 뒤에서 밀린 늑대 한 쌍이 한순간 깊이 눌리는 건 물리지 버그가 아니다.
눈에 보이는 '무더기' 는 여러 쌍이 **동시에** 포개진 것이다 — 그걸 재야 뜻이 산다.

흔들리는 검사를 만나면 **기준을 느슨하게 하기 전에, 재는 대상이 맞는지부터 본다.**

## G.me.g 와 myPC.g 는 다른 것이다 (17차b)

`t18` 이 열 판에 한 판씩 "캐도 0" 으로 빨개졌다. 원인:

- 자재는 **`myPC.g`** 가 가리키는 모둠 창고로 들어간다 (`recomputeRes`)
- 그런데 검사는 **`G.me.g`** 의 창고를 읽고 있었다
- 이 둘은 페이지의 타이머가 `syncMyPC()` 를 부를 때만 맞춰진다

`G.me.g` 를 바꿨으면 **`W.__syncMyPC()` 를 바로 불러 줘야** 한다.
