## 성능을 위해 바꾼 것

- 정적 풍경과 소품은 기존 재질 버퍼에 합치고 가까운 구간만 그린다. 소품은 매 프레임 애니메이션이나 별도 그리기 호출을 추가하지 않는다.
- 고무 캡슐·회전봉 내부에 가려지는 반구 면을 제거했다. 외부 곡률의 분할 수는 그대로다.
- 원통과 반구 이음새를 동일한24각으로 맞춰 근접 화면의 하늘색 틈을 제거했다. 실제 렌더 변환으로 양 끝 꼭짓점을 비교하는 회귀 검사를 추가했다.
- 장애물 배열을 재사용하고 인스턴스 정원을 제한한다. 경주 재생성 시 인스턴스 GPU 버퍼를 명시적으로 해제한다.
- 빠른 점프와 미끄럼을 친구 보간 코드가 순간이동으로 오판하지 않도록 경주 중 속도 상한만 조정했다. 통신 주기·패킷 수는 늘리지 않았다.
- 보통 화질의 픽셀비율 .85, 그림자2048, AA2, 매 프레임 그림자 갱신을 유지한다. 재질3개·텍스처2개, 경주 전용 렌더 호출 최대12회다.

## 검증 범위의 한계

21명 표시는 로컬 플레이어와 원격 아바타20개를 사용하는 재현이다. 친구 보간 검사는 실제 함수를 6Hz 수신·지연 조건으로 실행하는 시뮬레이션이다. **LG gram의 실제 GPU FPS, 학생21대 실연결 수업, 어린이 체감 난이도는 이 환경에서 검증하지 못했다.** noRender 스크립트 시간을 실제 FPS로 환산하지 않는다.

상점·상점주인 리디자인은 앞선 경주 우선 요청으로 보류 중이며 이번 경주 개선에 포함하지 않는다.

## 다섯 모둠의 벽 방향

나무벽·돌벽 외형을 모든 위치에서 동일하게 그리던 것이 원인이었다. 설치한 성문 방향으로 회전시키고, 실제 위치를 기준으로 결정한다. 4모둠 방향은 보존한다. 벽 이어짓기는 줄의 축을 따르고, 설계도→완성→강화→같은 구역 이동에 방향을 유지한다. 다른 구역으로 이동하면 도착 구역 방향으로 맞춘다. 공동 공사 진행 막대도 벽과 함께 회전한다.

기존 건물/설계도 객체에만 정수 `r`(0..3)을 저장한다. 통신 빈도와 입력 명령은 늘리지 않는다. 예전 `r` 없는 데이터는 실제 위치에서 추론한다. 1×1 점유·비용·건물ID·탑 외형은 그대로다. 벽의 실제 기하를 고스트에서도 사용하고, 공유 기하는 복제한 것만 해제한다.

정적 검사는 다섯 입구×두 벽×일곱 레벨×네 테마(280형상)를 실제 기하로 확인했다. 협동 건설의 방향 보존·호스트 결정·늦은 수신 복원과 브라우저 미리보기/설계도/완성/강화/이동을 별도로 검사했다. 벽 사진은 성문 바깥에서 본 진단 카메라임을 명시한다.
