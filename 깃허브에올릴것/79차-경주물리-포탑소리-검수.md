## 실제 경주 검증

`t74-race-view.mjs --physics-only`는 숨김 Chromium에서 실제 게임의 `updPlayer`와 경주 상태를 실행했다. 물리의 내부 120Hz 하위 단계를 실제 게임과 동일하게 사용한다. 조망 사진이나 순간이동으로 완주를 대신하지 않는다.

- 씨앗 13·7919·740021 × 외부 프레임 30·60·120Hz, 총 9회 모두 실제 시작부터 결승까지 정상 입력으로 완주했다. 84.53~98.67초, 장애물 피격 5~10회, 추락 0~1회였다. 180초 제한 유지.
- 모든 경우 체크포인트 7개를 순서대로 등록했고 도넛 수동 도약을 4번 사용했다. 빙글 사탕이나 착지 장애물을 무효화하지 않았다.
- 이동 원판 탑승 63건, 도넛/마지막 발사 45건, 점프 존 밖 발사 36건, 중앙 위험 착지 9건, 21명 근접 밀치기 9건, 경사·부스터·미끄럼 조향·관성 출구 검사 통과.
- 첫 경로 검사에서는 속도가 절반으로 돌아온 뒤 자동 검사 조종기의 점프 시점이 너무 일러 30Hz 두 경우에서 같은 사탕에 반복해서 맞았다. 검사 조종기의 점프 시점과 다음 막대 선택을 수정했다. 이 문제를 피하려고 실제 충돌이나 충격을 약하게 만들지 않았다.

증거: `artifacts/race79/route-second.log`, `artifacts/race79/physics-static/results.json`, `artifacts/race79/tower-audio/static-results.json`. `t74`의 기본 산출물 폴더는 실행 당시 게임 버전 번호를 따르므로, 버전 승격 전 검사의 전체 JSON은 `artifacts/race78/race78.json`에도 기록되었다.

소스 검사: `t54-race-static` 41/41, `t77-race-continuity-static` 9/9, `t79-race-physics-static` 9/9, `t56-building-combat-static` 25/25, `t79-tower-audio-static` 7/7. 도넛 아트의 인스턴스 은행 변경 후에는 통합 검사를 다시 적용한다.

## 한계와 남은 확인

실제 어린이 21명의 서로 다른 네트워크 접속, 그램 하드웨어 FPS, 교실 스피커에서 느끼는 음색·음량은 이 자동 검사로 확인할 수 없다. 경로 재생 성공은 초등학생이 바로 성공한다는 뜻이 아니다. 아트의 최종 실물 화면·동일 화질 성능 비교·GitHub 및 바탕화면 일치는 전체 79차 배포 검수에서 별도로 확인한다.

포탑 실제 WebAudio `OfflineAudioContext` 렌더도 8/8 통과했다. 열 가지 소리 모두 파형이 생겼고, 최대 절대 진폭은 0.034~0.127(클리핑 기준 1보다 낮음), 각 3~4개 소스가 종료 후 모두 정리되었으며 0.5초 이후 잔여 파형이 없었다. 기록은 `artifacts/race79/tower-audio/render-results.json`, 1초 간격 시청용 소리는 `artifacts/race79/tower-audio/tower-voices.wav`다. 파형 검사를 음색에 대한 실제 청취 평가로 대신하지 않는다. 이 파일은 운영체제 스피커를 재생하지 않고 오프라인 합성했다.

## 추가 요청: 총 재장전 ‘철컥’

기존 `g68rlOut/In/Rack` 세 박의 소리만 교체했다. `rlTick`, `heldMotion`, `GUN_CYCLE`의 호출 시각, 탄약 소모·보충, 손 모션, 통신 구조는 유지했다. 실제 게임에 있는 11개 장전 방식(탄창·드럼·탄띠·펌프·레버·클립·수정·탱크·가죽·화승·활)을 구분하며, 활과 가죽에는 금속 소리를 넣지 않았다.

첫 시안 `reload-mechanisms.wav`는 자동 검사 9/9였으나, 사용자가 직접 듣고 **“이상한 악기 소리”라고 거절했다**. 이 시안의 삼각파 몸통을 제거했다. 두 번째 시안은 짧고 마른 비주기 접촉음, 낮은 걸쇠 충격, 노리쇠 레일 마찰로 재구성했다. 일반 금속 장전 6종과 화승총은 발진기 0개다. 펌프는 145ms 간격의 이중 충격, 드럼은 낮고 단단한 잠금, 클립/노리쇠는 마찰 뒤 걸쇠가 닫히는 소리를 사용한다. 영상이나 원음 파일을 복사하지 않았다.

사용자가 제공한 [재장전 참고 영상](https://www.youtube.com/watch?v=66NuEUQbPy8)의 영상 분석 도구 결과는 권총의 탄창 삽입/슬라이드, 소총의 묵직한 결합/노리쇠, 펌프의 낮은 이중 충격, 긴 저격 노리쇠, 드럼 잠금/핸들의 분리된 타이밍을 강조했다. 이는 영상 분석 도구 결과이며 담당자의 직접 청취를 주장하지 않는다. 새 시안 역시 **사용자 음색 평가를 아직 받지 않았다**. 자동 파형 검사는 음색 승인과 구별한다.

- 단계당 최대 4개 소스로 제한했다. 산탄총 재장전의 마지막 박은 기존 8개에서 4개로 줄었다. 두 번째 시안의 잡음 조각 원음 게인은 최대 0.12이며, 주기 발진기로 보충하지 않는다. 기존 공유 잡음 한 장·56개 동시 소스 상한·종료 후 정리·효과음 볼륨·음소거를 그대로 사용한다.
- 한 발마다 작게 들리는 장전은 11종 모두 정확히 절반 게인을 적용한다. 기존 펌프·레버에서 이 절반 세기가 빠지던 부분도 함께 고쳤다. 원래 발사 동작의 펌프·레버 소리는 건드리지 않았다.
- 친구의 추정 재장전은 계속 조용하며 새 오디오 이벤트를 중복 호출하지 않는다. 포탑 거리 감쇠와 전역 소리 예산에는 변경이 없다.
- 두 번째 시안 `t79-reload-audio-static.mjs` 8/8: 33개 소리, 금속 7종의 발진기 없음, 종류별 차이, 절반 게인, 실제 `rlTick`을 실행한 45개 장전(15종 × 30/60/120Hz)의 정확한 세 박과 중도 취소 검증. 기존 `t68-reload-static` 19/19, `t66-sound-static` 63/63 재통과.
- 두 번째 시안 `--render` 12/12 통과. 금속 장전 7종의 실제 발진기 0개, 11종 최대 진폭 0.0244~0.0699, 모든 소스 종료, 건조한 본음의 1.5초 이후 잔여 파형 0. 기존 엄격한 절반 피크 기준(0.5±0.025), 효과음 버스 0/25%, 음소거 소스 0, 56개 소스 상한을 유지했다. 새 `reload-metal-v2.wav`는 **실제 소총→펌프→드럼, 각 2초**이며 실제 무기의 세 박 시간과 전체 게임 버스/압축기/공통 잔향/기본 효과음 100%를 사용한다. 정규화하지 않았고 최종 파일 피크는 0.04113, 소스 30/30 종료였다. 이전의 거절된 `reload-mechanisms.wav`와 구별한다.
- 이 과정에서 실제 단일 샘플 클릭을 발견했다. `puff`의 예약 시각 `.5700000000000001`이 오디오 샘플 `.57`로 반올림될 때 GainNode 기본값 1이 첫 샘플에 적용돼, 절반 소리에서도 같은 0.036030 샘플이 새었다. 생성 즉시 `gain.value=.0001`로 초기화해 원래 envelope 시작값을 적용했다. 그 결과 펌프 절반 피크가 0.024140, 전체 0.047081의 51.27%로 돌아왔다. 검사 기준을 완화하지 않았다.
- 샘플의 마지막 드럼 본음은 약 5.401초까지이고 기존 공통 잔향의 지연은 0.117초·되먹임 0.24다. 처음의 5.5초 꼬리 검사에는 정상 첫 반사가 들어갔다. 잔향 이후 마지막 5.9~6.0초 구간을 검사해 에너지 1.52×10⁻⁸을 확인했다. 이 변경은 실제 버스 잔향을 고려한 검사 수정이며 소리의 잔향이나 크기를 바꾸지 않았다. 결과는 `artifacts/race79/reload-audio/render-results.json`에 기록했다.

## 추가 요청: 낮과 밤 배경음악

낮 세 곡을 C장조 목관·E장조 마림바·D장조 목관 응답의 밝은 8마디 모험곡으로 편곡했다. 같은 리듬의 질문과 대답이 반복되고 후반은 으뜸음으로 돌아온다. 근음/5도 베이스와 작은 킥·나무 타악기로 박자를 만들며 빠른 무작위 음을 넣지 않았다. 일반 밤과 보스 밤은 D단조의 낮은 현악 반복, 절반 정도 쉼표가 있는 선율, 짧은 맥박 북을 사용한다. 위험할수록 박자가 조금 촘촘해지지만 갑자기 커지는 효과는 넣지 않았다. 외부 음원 없이 모두 기존 합성기로 만든 오리지널 음형이다.

대기실·여명·해질녘·승리·경주·서바이벌 곡과 공통 스케줄러는 유지했다. 장면 전환 1.5초, 총성 때 배경음 숙임, 선생님 일시정지, 숨긴 탭 정지, 설정 음량과 음소거는 기존 경로 그대로다. `t66-sound-static` 63/63을 다시 통과했다. `t79-bgm-static` 5/5는 다섯 편곡을 네 바퀴/변주까지 실행해 동시 BGM 소스 14~16개(기존 상한 28), 누락 0·미정리 0을 확인했다.

실제 `t79-bgm-static --render` 7/7도 통과했다. 공유 `puff` 초기화 수정 후 최종 소스로 다시 렌더했다. 기존 전체 소리 버스/압축기를 통과한 각 8마디를 22,050Hz로 렌더했다. 최대 절대 진폭은 낮 세 곡 0.0221~0.0239, 일반 밤 0.0270, 보스 밤 0.0312다. 소스 168~306개가 모두 종료됐으며 누락 0, 끝난 뒤 잔여 파형은 사실상 0이다. 음악 음소거에서는 소스 0개다. [최종 결과](계획/79차/bgm-render.json)와 로컬 `artifacts/race79/bgm/`의 다섯 WAV를 보관한다. 운영체제 스피커는 재생하지 않았으며 실제 사용자의 음악 취향 평가는 별도다.

## 추가 요청: R 재장전 · T 수리

`manualReload79`는 총을 든 상태에서 R을 누르면 원래 `rlStart/rlTick` 시간·모션·세 박 소리를 사용해 부분 탄창을 채운다. 이미 장전 중이면 새로 누르거나 길게 눌러도 타이머가 재시작되지 않는다. 탄창이 가득 찼거나 채울 여분 탄약이 없거나 한 발 무기이거나 총을 숨겼으면 아무것도 바꾸지 않는다. 기존 마지막 발 이후 자동 장전, 탄약 계산·무기 교환 취소·통신 규칙은 유지했다.

T는 수리 도구를 선택하며 총을 들고 있었다면 넣는다. 다시 T를 눌러도 총을 꺼내지 않으며, 총 들기/넣기는 우클릭과 총 칸을 사용한다. 도구 줄·도움말·위험 건물 안내·CLAUDE 현재 조작표를 같은 키로 정리했다. 두 키는 입력칸과 중첩 편집 영역, IME 조합, Ctrl/Alt/Meta 조합, 반복 keydown, 이미 소비된 이벤트, 일시정지·쓰러짐·관전·팝업·대기실/도입/미니게임/종료 상태에서 작동하지 않는다.
