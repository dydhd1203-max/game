# 106차 — 후반 건축물 성능 검수

2026-10-13. 사용자 요청은 첨부된 105차·21명 수업 측정을 바탕으로 좀비의 밤을 더 최적화하는 것이다. 퀴즈나라와 전투 수치·모델·재질·해상도·MSAA는 변경하지 않는다. 기준은 병합된 105차(`19749c2`, 게임 파일은 `9ca01fa`와 동일)이다.

## 측정 해석과 구현

| 요청/근거 | 구현 | 확인 범위 |
|---|---|---|
| 후반에 타워가 쌓이며 느려짐 | `rebuildStru`, `struRenderBuild`, `struRenderSync`: CPU 원본을 16칸 구역으로 나누고, 화면에 필요한 부품만 기존 타일·모둠·모양별 GPU 묶음에 압축 | 같은 부품 수·행렬·색·인스턴스 순서. 호출 수를 늘리지 않고 화면 밖 기하 제출을 줄임 |
| 화질 유지 | 정렬 중심 유지, `struGunBounds`로 포신 전체 회전·반동 경계 확보 | 기본 시점, 반대 방향, 동쪽 입구, 구역 경계의 맞붙은 벽, 조망, 선택적 실시간 그림자 비교 |
| 불필요한 JS/업로드 억제 | 재사용 typed-array 뷰와 버전 비교, 바뀐 모둠만 재생성 | 정지 시 업로드 없음, 숨은 건물 갱신·복귀, 다른 모둠의 회전 중인 포탑 상태 유지 |
| 다음 교실 측정에서 원인 구분 | `recTick`에 건물·타워(병영 포함) 수와 시작 시 호스트 여부 추가 | 기존 `nightRec102`의 12열 기록 유지, 신규 14열·최근 3밤 저장 검사 |

첨부 기록의 2~3일차는 평균 57fps, GPU 약 8ms, JS 약 5ms이고, 15일차는 45fps, GPU 16.9ms, JS 11.2ms다. 15일차 시작은 좀비 1마리인데도 삼각형 약 688만, GPU 18ms였다. 후반 렌더링 누적 비용을 줄일 근거지만, 당시 타워 수와 카메라 위치가 없어 타워만이 원인이라고 단정하지 않는다.

기존 ‘브라우저’ 값은 이전 rAF 콜백 종료부터 다음 시작까지의 시간으로, 화면 주기 대기·GPU·합성·스케줄링 등을 포함한다. 4일차의 5,103.3ms/621.7ms 이상치를 HUD 비용으로 해석하지 않는다. `recText`에서 이를 ‘대기’로 설명하고 JS/GPU를 합산하지 않도록 안내한다. 평균·최저·55 이상 비율은 약 5초 간격 표본 기준이며 1% low가 아니다. 첨부된 친구 수 22~23을 임의로 21로 바꾸지 않는다.

7시점 모두 105차↔106차, 106차 컬링↔전체 제출 간 픽셀 차이 0. 부품 6,372개의 행렬·색 484,272바이트 SHA-256도 시점별로 일치했다. 기본/인접 벽 캡처를 직접 열어 장면과 접면을 확인했다. 이 비교는 게임 캔버스를 검사하며 DOM HUD 전체 스크린샷 비교는 아니다.

Chromium/SwiftShader의 고정 장면 제출량·픽셀 비교다. 실제 LG gram의 FPS·GPU 시간·21대 네트워크 또는 수업 지속 시간에 따른 발열 개선은 아직 측정하지 않았다. `?p81off=struCull`로 새 건물 컬링만 끌 수 있고, 기존 `?nocull=1`도 전체 제출을 유지한다.

브라우저는 저장소의 `pw.mjs`를 사용하며 숨김 실행과 커서 잠금 차단을 유지한다. Firebase는 로컬 모의 연결을 사용한다. `PW_MODULE`/`PW_EXECUTABLE_PATH`는 실행 환경에 설치된 Playwright/Chromium에 맞출 수 있다.

- `t106-structure-cull.mjs`: 22개 검사 통과. 건물 280조합, 포탑 112조합×32자세, 정점 8,928,000회 포함. 카메라 왕복, 숨은 건물 변경 후 복귀, 행렬/색 개별 갱신, 이동/철거, 부분 모둠 갱신, 그림자와 진단 옵션 검사.
- `t106-night-record.mjs`: 9개 검사 통과. 이전 기록 호환성, 샘플 간격, 건설 변화, 호스트/손님, 최근 3밤 유지, 저장소 사용 불가 처리.
- `check-current.mjs`: 최종 원본 74/74 검사 파일 통과. 검사 전후 원본 SHA-256 동일.
- `t106-structure-view.mjs`: 최종 원본 7시점 모두 통과. 고정 기본 시점 `drawFrame` 제출 시간은 순서를 번갈아 7회×3프레임씩 잰 참고 중앙값 3.9→3.8ms다. 소프트웨어 렌더러·고정 장면 수치이므로 전체 CPU 또는 FPS 개선율로 해석하지 않는다.
- `check-release.mjs`: 원본과 배포용 106차 바이트 일치. SHA-256 `91c2c21654161390e37d84b70c96d5736f56f07de0add7fea950a0ab15d1173f`.
