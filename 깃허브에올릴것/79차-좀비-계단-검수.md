# 79차 좀비 계단 발치 경로

사용자 제보: 좀비가 성문 계단 끝 기둥에 계속 모이고 끼는 현상.

## 원인과 변경

- 실제 몸 검사 `zMoveOk`는 지상 좀비에게 첫 디딤도 막지만, 흐름장 `RAMP_FLOW`는 높이 1을 넘는 디딤만 막다른 칸으로 등록했다. 첫 줄을 가로지르는 불가능한 지름길이 남아 있었다. 이제 모든 디딤에 같은 규칙을 적용한다.
- 칸 중심 또는 아이에게 직진할 때 발치 기둥 모서리에 팔 폭이 걸렸다. `zStairRoute79`가 실제 기둥 앞면과 개체 반지름을 읽어 앞 모서리 두 점을 돌아가게 한다. 목표가 계단 반대쪽이면 앞을 가로질러 돌아서며, 통로 쪽으로 무조건 밀지 않는다.
- 정상 성벽 추격 `climbApproach`도 기둥 앞에서 가운데에 정렬한 뒤 첫 디딤으로 들어간다. 예전 두 점은 정렬 중 대각선으로 기둥을 잘랐다.
- 실제 걸음/밀치기 `zStep`, 좀비 수치, 추격 거리/시간, 계단 정원, 성벽 추격 조건은 유지한다. 지상 이동의 목표점만 바꾼다.
- 일반 마당은 기존 공간 표 `ZGB`에서 즉시 종료한다. 계단 근처에서만 고정된 10개 계단의 직사각형 교차를 검사한다. 매 좀비 전체 지도 탐색, 새 렌더 메시, 새 통신은 없다.

## 검증

- `t79-zombie-stairs-static.mjs`: 실제 `genTerrain`, `gateLayout`, `castleLayout`, `buildFlow`, `zMoveOk`, `zStep`, `climbApproach`를 VM에서 추출해 실행한다. 새 공식으로 대체한 가짜 충돌 지도는 쓰지 않는다.
- 일반/날쌘/전체 보스, 열 계단 양쪽, 수정 방향/지상 아이/계단 건너편 아이, 30·60·120Hz: **1,260경로 모두 도착, 기둥·계단 관통 0, 지상 높이 이탈 0**.
- 오를 수 있는 네 종류의 양쪽 계단 접근 **80개 모두 성공**. 가장 오래 걸린 경우 약 1.09초. 아이가 지상으로 돌아오면 열 계단 모두 접근 취소.
- 옛 위치·밀림으로 발치 기둥 안에 들어간 **20자리**에서 기존 작은 충돌 복구 걸음으로 탈출한 뒤 계속 이동. 한 프레임 이동 상한 0.12, 7프레임 이내 안전한 위치로 복귀.
- 동일 검사에 수정 전 `baseline78.html`을 넣으면 지상 **528/1,260 경로 실패**, 기둥 옆 성벽 접근 **80/80 실패**가 재현된다. 수정 전/후 결과는 `artifacts/race79/zombie-stairs/`에 각각 보존한다.
- 기존 `t67-castle-static.mjs` **85/85**, `t59-zombie-shape-static.mjs` **18/18** 통과.
- 숨김 브라우저 `t79-zombie-stairs-view.mjs`에서 실제 `hostSim` 실행: 일반 좀비/좀비왕의 지상 경로 **120/120**, 정상 성벽 오르기 **20/20**, 앞 우회점에 플레이어 돌벽을 추가한 충돌 검사 **10/10** 통과. 지상 아이는 기존 12칸 추격 범위 안에 두며, 수정까지 가는 장면도 따로 잰다. 충돌 유효성·지상 유지·실제 도착을 프레임마다 확인했다.
- 기존 `t67-castle-zombie.mjs`: **16/17 통과, 기존 수동 하네스 1개 WAIT**. 계단별/전체/아이별 정원, 놓친 목표 취소, 12·15초 성벽 시간 제한, 금지 종류, 지붕 아래 아이, 새벽 귀환, 손님 높이 비트, 성벽 위 사망/보상까지 유지했다. 수동 `bal36` 균형 실험은 이번에 실행하지 않았으며 통과 개수에 포함하지 않는다.
