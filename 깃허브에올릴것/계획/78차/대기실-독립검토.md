# 78차 대기실·도입 독립 검토

2026-09-27. 좀비 담당이 대기실 구현을 독립 검토했다. 처음 발견한 3건은 통합 담당이 수정했고, 마지막 체력·동일 단계 재시작 2건은 통합 담당의 요청에 따라 해당 함수와 callback에만 작은 패치를 적용했다.

## 발견과 조치

| 문제 | 실제 경로와 영향 | 조치/회귀 |
|---|---|---|
| 재시작 뒤 손님의 결과창 상태 잔존 | `showEnd`가 `endShown=true`와 `popEnd.on`을 남긴다. 새 sid 수신과 로비 진입이 이를 지우지 않으면 이전 결과창이 로비를 가리고 다음 종료 화면도 생략된다. | 새 sid callback과 `lobbyEnter78`에서 결과 플래그와 열린 팝업 초기화. 실제 `joinRoom` meta callback→로비→두번째 `showEnd` 회귀 통과. |
| 미니게임 중 새 수업에서 이전 무기 복원 | 교사 리셋이 `kitReset` 후 `lobbyReset78`을 부른다. 그 안의 `miniLeave`가 `miniBack.wpn/ammo`를 다시 쓰므로 새 수업에 이전 총과 탄약이 남는다. | 미니게임을 나간 뒤 다시 장비 초기화. 이전 무기18/탄약777로 실제 `miniLeave`→`lobbyReset78`를 실행해 0/0 확인. |
| 로비 친구가 계속 공중으로 판정 | 원격 사람의 `q.air`가 마을의 `groundUnder`를 썼다. 별도 홀은 `GY+64`이므로 서 있는 친구도 공중 자세가 된다. 로컬은 `PL.ground`라 단독 검수에서는 정상이다. | 로비에서는 `LOBBY78.y`를 발판 기준으로 사용. 로비 정지=false/실제 점프=true/쓰러짐=false/마을 지면 유지 회귀 통과. |
| 교사 새 수업에서 체력 0 유지 | 미니게임 밖에서 `tReset`을 누르면 손님은 새 sid에서 회복되지만 host는 `lobbyEnter78`의 `down=false`만 적용되어 HP 0인 채 서 있었다. | `lobbyReset78`에서 최대 체력과 쓰러짐·피격 타이머 초기화. 실제 교사 단추 callback의 수정 전 0 HP 실패와 수정 후 100 HP 통과를 확인했다. |
| 로비에서 새 수업을 누르면 손님이 홀 아래로 이동 | 로비→로비 새 sid 수신이 `placePlayer`로 마을 좌표에 놓지만 단계가 같아 `onPhaseChange`가 생략되었다. | 같은 로비 단계의 새 sid에 한해서 `lobbyEnter78` 호출. 수정 전 마을 높이10과 기대 홀 높이74 불일치를 재현했고 수정 후 홀 복귀를 확인했다. 같은 sid의 보통 meta 갱신에서는 이동 중인 위치가 그대로 유지된다. |

## 추가로 검토한 경로

- 도입 중 `updPlayer`는 이동을 막고, `fireWeapon`/`doAction`/총 전환은 `pregame78`에서 막는다. 로비의 이동·점프·꾸미기만 별도 경로로 허용한다.
- 늦은 입장은 첫 meta에서 phase/time/settings를 먼저 적용한다. `startGame`은 로비·도입·진행 중 수업을 각각 구분하고 도입은 `5-G.t`부터 시작한다. 서버 시계의 최종 전환은 host가 소유한다.
- 도입 자막은 `G.set.goalDay`를 사용한다. 18일 설정에서 실제 마지막 자막이 18일로 나오는 것을 검사했다.
- `storyTick78`은 shot 변경 때만 효과음을 호출한다. 600회(6초) 실행에서 `dusk`, `stomp`, `up` 각1회만 나왔고 표시 경과는 5초에서 멈췄다.
- 좀비9마리는 표시용 배열이고 실제 적/보상 목록에 들어가지 않는다. 별도 좀비 정적 검사에서 재사용·시간 되감기·전진을 확인했다.

회귀 파일: `검사/t78-lobby-reset-static.mjs` — 위 수정5건과 도입 소리/목표 일차를 실제 함수·callback으로 검사해 6/6 통과했다. `check-current.mjs`에 등록했다. DOM/네트워크 저장소는 이 검사에서 작은 fixture이며, 실제 두 탭 간 전달·최종 화면은 네트워크 담당의 별도 브라우저 검수가 맡는다.

네트워크 담당은 실제 두 탭 검사 25/25에서 원격 정지 `air=false`, 결과창→다시하기→새 sid→로비→5초 도입→두 번째 승리창, 교사 리셋의 장비0/탄약0을 확인했다. 이후 최종 배포용 SHA-256 `f7a7bef3505d59a3105ed15c51fe45c139e29600951a74eceb784f0d05ed6106`에서 마지막 체력·로비 동일 단계 재시작까지 포함한27/27 브라우저 검사를 통과했다. 증거는 `네트워크/results.json`이다. 추가 읽기 검토 범위에서 미해결 중대 문제는 발견하지 못했다.
