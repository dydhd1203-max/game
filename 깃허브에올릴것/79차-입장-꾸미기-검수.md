# 79차 입장 화면과 집결소 꾸미기

## 구현

- 첫 화면은 달빛 성곽·수정·성문 밖 좀비를 그린 정적인 밤 풍경과 수비대 등록 카드다. 최초 SVG 안은 후속 피드백으로 더 무서운 WebP 일러스트 배경으로 교체했다. 이름, 접속 코드, 모둠만 입력한다. 선생님 방 만들기와 혼자 연습은 별도 보조 버튼이며 화면·소리·조작 안내는 접어서 열 수 있다. 버전/패치 내역은 표시하지 않는다.
- 이전 시작 화면의 모자·얼굴·피부·옷 선택과 실제 정면 3D 아바타를 집결소의 **내 아바타 꾸미기** 창으로 옮겼다. 모둠 선택도 이 창에서 가능하다. 실시간 네트워크 꾸미기 키와 저장 ID는 그대로다.
- 정면 미리보기는 기존 `mkPvw`/`pvwSet`을 처음 창을 열 때만 만든다. 같은 미리보기·WebGLRenderer를 재사용하며 닫힌 창과 도입/게임 중에는 그리지 않는다. 첫 입장 화면에는 미리보기 렌더러를 만들지 않는다.
- 작은 화면에서도 앞모습을 보며 옷을 고르도록 미리보기를 스크롤 상단에 고정했다. 아래 **꾸미기 끝** 버튼은 스크롤과 분리했다.
- 교사 암호 확인, 교사만 시작, 학생 시작 거부, 늦게 합류하는 동작은 유지한다.

## 직접 확인

`t79-entry-view.mjs`는 실제 게임을 숨김 브라우저 하나에서 열었다. `t55-wardrobe-static.mjs` 30/30 및 모듈 구문 검사도 통과했다.

## 범위

이 기록은 입장/꾸미기 작업의 검수다. 실제 교실 21대 네트워크 및 그램 FPS 측정은 아니다. 최종 GitHub/바탕화면 배포 여부는 별도의 통합 배포 검사에서 확인한다.

## 꾸미기 9종 추가와 기존 의상 다듬기

- 모자 14~16: 별빛 베레모, 아기 오리 모자, 데이지 머리핀.
- 얼굴 9~11: 살금 고양이 수염, 반짝 별 볼터치, 하트 스티커.
- 옷 11~13: 구름 세일러 가디건, 딸기 크림 후디, 오리 멜빵옷.
- 기존 고양이/토끼 귀, 곰 모자, 딸기 리본, 화관, 나비핀은 둥근 귀·꽃잎·하트 곡면으로 변경했다. 파자마와 목도리에는 접단과 자수·별·단추를 다듬었다. 몸판을 겹치지 않고 기존 몸통 색으로 옷 바탕을 표현한다.
- 저장 ID는 재배열하지 않고 배열 뒤에 추가했다. `COSMETIC_GEO` 다섯 종류와 `P_cosParts` 다섯 인스턴스 묶음을 공유한다. 학생마다 새 지오메트리·재질·draw call을 만들지 않는다. 40명 최다 조합 용량은 기하별 카탈로그 최대값으로 산정한다. 그림자 중복/표면 번쩍임 방지 규칙을 유지한다.
- `r6rows`의 문자열 `shape`로 실제 게임·정면 미리보기·선택 아이콘이 같은 곡면 기하를 사용한다. 직업 표의 숫자 머리 플래그와 혼용하지 않는다. 전직 의상은 기존처럼 꾸미기 모자/옷을 대체하고 얼굴 장식은 유지한다.

`t79-cosmetic-view.mjs`에서 새 9개를 실제 버튼으로 선택해 송신 패킷에 같은 ID가 담기는지 확인했다. 모든 기존/신규 선택의 미리보기/아이콘 기하 동일성, 21명 네 조합의 인스턴스 개수·유한 행렬·빈 장면 정리, 페이지/셰이더 오류 0을 확인했다. [꾸미기 갤러리](계획/79차/cosmetic-gallery.png), [꾸미기 창](계획/79차/wardrobe-desktop.png), [전직 갤러리](계획/79차/jobs-gallery.png)를 직접 열어 확인했다. 직업 갤러리는 함께 적용한 1·2차 전직 여섯 벌의 실제 미리보기다. [꾸미기 검수 수치](계획/79차/cosmetic-results.json)는 같은 실행의 결과다.

`t61-avatar-clearance-static.mjs`는 새로운 곡면 묶음을 포함하도록 확장했다. 11개 옷 선택 4,224 보행 자세, 6직업 2,304 자세, 도넛 상승/정점/낙하/착지 10,710프레임에서 옷·팔 겹침 0을 확인했다. 모자/머리, 총/몸 관통까지 **17/17 통과**했다. 최초 전직 2차 견장의 팔 겹침을 검출해 견장 위치를 수정한 후 다시 통과했다.

## 건설 후 끼임과 설계도 자동 취소

- `t79-build-unstick-view.mjs`: 실제 `addStru`/`applyNetworkBuilding` 후 `updPlayer` 경로로 검사했다. 나무벽/돌벽/얼음탑/나무탑/병영 × 중앙/옆/모서리, 인접 9벽, 고체가 막은 가장자리, 건물 옥상 유지, 손님에게 건물 수신, 탈출 후 이동, 집결소/도입/미니게임 제외 **25/25 통과**. 옥상 높이는 Float32 셀 저장 오차를 고려해 0.00001m 오차 이내를 허용한다.
- `t79-build-idle-static.mjs`: 실제 호스트/손님 함수를 메모리 통신으로 연결했다. 2,999ms 유지/3,000ms 취소, 늦은 첫 작업자, 작업 중 유지, 멈춘 뒤 3초, 끊긴 작업자, 손님 권한/호스트 취소 동기화와 무과금을 검사해 **6/6 통과**했다.
- 결과: [건설 끼임 25개 사례](계획/79차/build-unstick-results.json), [설계도 취소 6개 사례](계획/79차/build-idle-results.json). 실제 교실 네트워크 지연·그램 하드웨어 FPS를 측정한 결과는 아니다.

저장소 증거 파일은 실제 검사 산출물을 `Copy-Item`으로 복사했고 각 원본/사본의 SHA-256 일치를 확인했다. 이미지 변환·덧그리기는 하지 않았다. 입장 배경과 대비를 추가 수정하면 최종 브라우저 검사 뒤 해당 캡처/JSON을 다시 복사해야 한다.
