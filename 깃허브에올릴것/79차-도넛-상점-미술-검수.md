# 79차 도넛 장애물·상점 미술 검수

## 실제 변경

- 통통 도넛섬의 착지 원판은 그대로 유지하고, 원판 위 캡슐 장애물만 초콜릿·딸기·민트 도넛으로 바꿨다. 구멍은 실제로 뚫려 있으며, 반죽·코팅·아이싱·스프링클이 모두 입체 기하다. 크기와 방향은 물리 담당의 `h.r`, `h.ry`, `h.rz`, `flavor79`를 그대로 따른다.
- 도넛은 로컬 XY 평면의 중심 반지름 0.66, 반죽 반지름 0.34인 고리다. 실제 충돌도 같은 고리와 구멍을 사용한다. 코팅과 설탕의 작은 돌출은 장식이다. 기존 원판 어디에서나 Space로 도약하며, 작은 노란 전용 발사 표적은 제거했다.
- 무기상점에는 곡면 줄무늬 천막, 처짐과 물결 모양 천 끝, 가공한 목재 기둥·버팀대·널판, 방패 간판을 넣었다. 기존 무기·물약·갑옷 진열 위치는 유지했다.
- 동물상점에는 세이지색 박공 천막, 발바닥 간판, 속이 빈 손잡이 바구니와 둥근 병아리, 사료 자루를 넣었다.
- 대장간에는 겹친 슬레이트 지붕, 실제로 안쪽이 들어간 돌 아치 화덕, 돌 굴뚝과 목재 골조를 넣었다. 모루·망치·달군 쇠·굴뚝 연기 위치는 유지했다.
- 상점 배치는 `SHOP_A=DIRS[0].a+.92`, `SHOP_R=9.2`, `VET_OFF=4.1`, `FORGE_A=DIRS[2].a+.92`, `FORGE_R=9.6`이다. 실제 외형은 기존 설치 제한 반경 안에 들어가며, 가장 크게 자란 농장 영역과도 겹치지 않는다.
- 경주와 대기실에서는 마을 상인의 6개 인스턴스 뱅크와 그림자를 숨기고, 망치 불티·소리 생성도 건너뛴다. 도입 영상의 마을에서는 보이며, 마을 복귀 시 모두 복원한다.

## 실제 화면 확인

`t79-world-art-view.mjs`로 일반 플레이 카메라와 명시적인 세부 확인용 카메라를 따로 촬영했다. 아래 PNG는 파일을 직접 열어 외형·구멍·상점 배치·NPC와 가구의 관계를 확인했다.

선별한 원본 PNG 및 결과 JSON을 저장소의 `계획/79차/world-*`에도 그대로 복사했다. [도넛 일반 화면](계획/79차/world-after-donut-player.png), [도약](계획/79차/world-after-donut-flight.png), [도넛 근접](계획/79차/world-after-donut-pastries-detail.png), [캔디 충격](계획/79차/world-after-candy-impact.png), [무기상점](계획/79차/world-after-shop-player.png), [동물상점](계획/79차/world-after-vet-player.png), [대장간](계획/79차/world-after-forge-player.png)을 확인할 수 있다. 이미지는 보정하거나 합성하지 않았다.

- `artifacts/race79/world-art/after-donut-player.png`: 21명 장면에서 고리와 세 가지 코팅 확인.
- `artifacts/race79/world-art/after-donut-pastries-detail.png`: 별도의 근접 미술 확인 장면. 구멍, 반죽 두께, 입체 아이싱과 스프링클 확인.
- `artifacts/race79/world-art/after-donut-flight.png`: 실제 Space 입력 뒤 충분히 높아진 공중 상태를 검증하고 촬영. 착지 원판이 어긋나 배치되어 있음도 확인.
- `artifacts/race79/world-art/after-candy-impact.png`: 실제 막대 충돌과 위쪽 충격을 검사한 뒤 9프레임 후 촬영. 아바타가 막대 바깥의 공중에 있음 확인.
- `artifacts/race79/world-art/after-shop-player.png`, `after-vet-player.png`, `after-forge-player.png`: 일반 플레이 카메라에서 실제 상점 확인. 각 `*-detail.png`는 보조 근접 장면이다.
- `artifacts/race79/npc-cull/donut-budget.png`, `village-return.png`: 상인 렌더링 생략 뒤 경주와 마을 복귀 화면 직접 확인.

초기 도약 촬영은 잘못된 키 이름으로 실제로 뛰지 않은 장면이었다. 이를 완료 근거로 사용하지 않았다. 검사를 실제 공백 키 및 `__wantJump()` 입력으로 고치고, 공중 높이가 12보다 커야 저장하도록 제한한 뒤 유효한 화면으로 다시 촬영했다.

## 성능 비교

78차 배포본과 79차 소스에서 같은 그래픽 설정·조명·카메라·21명 조건을 사용했다. 화질을 낮추거나 새 조명을 추가하지 않았다. 테스트 브라우저는 SwiftShader이므로 이 수치는 렌더 작업량 비교이며 그램 실기기의 FPS 보장은 아니다.

| 장면 | 78차 그리기 호출 | 79차 최종 그리기 호출 | 78차 삼각형 | 79차 최종 삼각형 |
| --- | ---: | ---: | ---: | ---: |
| 마을 고정 카메라 | 507 | 540 | 3,375,234 | 3,437,694 |
| 도넛섬 고정 카메라 | 64 | 71 | 762,810 | 778,526 |

마을 전체 삼각형 증가는 1.85%, 경주는 2.06%다. 마을 텍스처 23개, 경주 텍스처 25개로 기존과 같다. 경주 미술 자체는 재질 3개·텍스처 2개를 유지하며, 그리기 호출 11→14, 삼각형 226,662→250,400이다.

도넛은 최초 4,238~4,886삼각형에서 초콜릿 2,672, 딸기 2,680, 민트 2,696삼각형으로 줄였다. 세 종류의 공유 기하만 사용하며 장애물마다 새 재질이나 조명을 만들지 않는다. 36개 스프링클, 7줄 입체 아이싱, 실제 구멍과 볼록한 반죽은 유지했다. 줄인 뒤 다시 직접 화면을 확인했다.

같은 프레임에서 상인 뱅크만 일시적으로 복원하는 독립 비교로 생략 효과를 확인했다. 83→71호출, 832,246→778,526삼각형으로, 보이지 않는 상인 및 그 그림자에서 12호출·53,720삼각형을 줄인다. 마을 복귀 상태의 호출 수는 인물 위치와 효과 상태가 달라 위 고정 조건 표와 혼용하지 않았다.

저장소에 포함한 [최종 경주 성능·복귀 결과](계획/79차/world-npc-cull-results.json)와 [전체 미술·기준 비교 메타데이터](계획/79차/world-art-view.json)를 함께 읽는다. 전체 미술 파일은 상인 숨김을 추가하기 전의 83호출 값을 담고 있고, 최종 경주 값 71호출은 최종 경주 성능 파일에 기록되어 있다.

## 검증

- `t79-donut-art-static.mjs`: 9/9. 세 종류 각각 3,000삼각형 미만, 유한한 기하·노멀·색, 실제 중심 구멍 유지. 9가지 방향에서 구멍 관통 및 반죽 216개 광선 검사 통과.
- `t79-market-art-static.mjs`: 실제 천막·바구니·목재·화덕 기하의 유효성, 건물 반경, 농장 이격, 깊은 화덕 입구, 모루/연기 위치 검사 통과.
- `t79-world-art-view.mjs`: 브라우저 오류 없음. 도약·캔디 충격은 실제 입력/물리 결과 조건을 만족해야 촬영된다. 수치와 카메라/조명/화질 메타데이터는 `artifacts/race79/world-art/view.json`.
- `t79-npc-cull-view.mjs`: 대기실/경주에서 6개 뱅크 숨김·개수0·망치 불티0, 도입 영상에서 표시, 마을 복귀 후 원래 인스턴스 개수 `[113,8,3,30,3,5]` 복원 통과. 오류 없음. 결과는 `artifacts/race79/npc-cull/results.json`.

물리 난이도·완주 가능성·멀티플레이 검사는 별도의 경주 물리 및 최종 릴리스 검수 결과를 참조한다.
