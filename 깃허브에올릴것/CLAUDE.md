# 양들의 밤 — 수정을 지켜라

초등학교 3학년 21명이 한 교실에서 같이 하는 브라우저 3D 게임.
다섯 모둠이 각자 산길 입구 하나씩을 맡아, 밤마다 오는 늑대에게서 가운데 수정을 지킨다.

## 어디에 무엇이 있나

| | |
|---|---|
| `index.html` | **게임 전부.** 파일 하나에 다 들어 있다 (약 500KB) |
| `배포용/` | 넷리파이에 올리는 것 — `index.html` + `_headers`. `index.html` 과 **똑같이 맞춰 둔다** |
| `진행상황.md` | 1차~14차 작업 기록. **무엇을 왜 그렇게 했는지**가 다 적혀 있다 |
| `검사/` | 테스트 하네스 586항목. 고칠 때마다 돌린다 (`검사/README.md` 참고) |
| `개발환경.md` | 교실 기기·배포 환경 |

## 파일 하나 원칙

교실 크롬북은 인터넷이 자주 막히고, 선생님이 파일 하나만 옮기면 되게 해야 한다.
그래서 **빌드 도구도, 번들러도, 프레임워크도 안 쓴다.** three.js 만 CDN 에서 읽는다.

라이브러리를 하나 더 붙이고 싶어지면 그 자리에서 직접 짜는 쪽을 먼저 생각한다
(예: 손에 든 모형을 합치는 코드는 three 의 BufferGeometryUtils 대신 직접 짰다).

## 고치기 전에 알아야 할 것

**성능** — 교실 크롬북(Mali-G72 MP3)은 **드로우콜 하나가 약 60마이크로초**다.
삼각형보다 그리는 횟수가 훨씬 비싸다. 그래서:
- 같은 것이 여러 개면 인스턴스 메시로 묶는다
- 손에 든 모형처럼 안 움직이는 조각은 재질끼리 미리 합쳐 굽는다
- 뱅크(bpush) 하나는 **첫 번째로 넣은 모양으로 고정**된다 — 한 열쇠에 여러 모양을 섞으면 나머지가 다 첫 모양으로 그려진다

**HUD** — `paintHUD` 는 초당 8번 돈다. `setTxt`/`setSty` 는 **값이 바뀔 때만** DOM 을 건드린다.
이 버릇을 깨면 크롬북에서 바로 티가 난다 (`검사/hud2.mjs` 가 지킨다).

**화면 배치** — 손으로 `top`/`bottom` 숫자를 잡지 않는다. 세로 flex 로 묶거나 JS 로 재서 잡는다.
(그 숫자 때문에 세 번 겹쳤다.) 짧은 화면에서 겹치는지는 `검사/t13.mjs` 가 10가지 크기로 본다.
CSS 미디어 쿼리는 **같은 힘이면 나중에 쓴 것이 이긴다** — 더 좁은 조건을 뒤에 둔다.

**늑대 길찾기** — `walkable()` 은 `terrH`(지형)만 본다. `bldH`(건물)는 안 본다.
그래서 망루 위는 늑대 눈에 안 보인다. 높이차 `SHEEP_REACH_Y = 2.2` 를 넘으면 쫓지도 물지도 않는다.

**통신** — 자리(위치)는 초당 13번 나가는 통로다. 여기에 칸을 더하지 않는다.
레벨처럼 가끔 바뀌는 것은 `pc` 통로(초당 1회 남짓)에 얹는다.

## 고칠 때의 순서

1. `bash 검사/chk.sh <게임파일>` — 문법부터 (한 줄 잘못 넣고 30분 헤맨다)
2. 고친다
3. 관련 검사를 돌린다 (`node 검사/t16.mjs 클로드/index.html 9000`)
4. **화면에 찍어 본다** — 코드가 맞아 보여도 화면은 다를 수 있다.
   거꾸로 달린 총, 안 보이던 체력바, 얼굴에서 터진 축포를 다 스크린샷이 잡았다
5. `cp index.html 배포용/index.html` 로 맞춘다
6. `진행상황.md` 에 **무엇을 왜** 했는지 적는다

## 검사가 흔들리면 검사가 아니다

무작위(지형·자리)에 기대는 검사는 조건을 **찾아서** 쓴다.
빨간불이 떴을 때 게임이 아니라 검사가 틀린 경우가 여러 번 있었다 — `검사/README.md` 에 사례가 있다.

## 잘하는 방법이 여러 갈래로 보여야 한다

이 게임이 소리 내어 칭찬하는 것이 오랫동안 전부 '쏘기' 였다 —
처치 알림 · 연속 명중 · 강화 무기 빛 · 보스 막대 · 레벨 순위.
**밤새 벽을 고치고 자원을 캐 온 아이는 아무 흔적도 안 남았다.**

순위판은 일곱 갈래(레벨·캐기·짓기·수리·도움·명중·농장)를 5초씩 돌린다.
**갈래 개수를 검사에 박지 않는다** — 17차d에 농장 갈래를 더하자 게임은 멀쩡한데
검사만 빨개졌다. 세어야 할 것은 개수가 아니라 '길이 여러 갈래로 남는가' 다.
새 장치를 넣을 때는 **"이걸 잘한 아이의 이름이 어디에 남는가"** 를 같이 정한다.

## 맵 좌표는 한 곳에서만 만든다

입구마다 방향(`dx,dz`)과 **옆으로 밀린 정도(`off`)** 가 있다.
이걸 여기저기서 손으로 더하고 빼면 반드시 어긋난다. 변환은 네 줄로 못 박혀 있다 —
`gT` · `gPP` · `gX` · `gZ`. **게임도 검사도 하네스도 전부 이걸 거친다.**

같은 이유로 **구역 나누기는 각도로 하지 않는다.** 아래쪽 두 입구는 방향이 똑같고
옆으로만 갈라져 있어서 각도로는 구분이 안 된다 — `sectorOf` 는 '어귀에서 제일 가까운 곳' 을 본다.

## 마을 경계는 네모, 세상 끝은 원

칸이 정사각형이라 **완전한 직선은 가로·세로뿐**이다. 그래서 마당 경계는
모서리만 깎은 네모(`oct`)다 — 다섯 입구 어귀가 전부 직선이라야
아이들이 벽을 한 줄로 긋고 그 끝이 산에 맞물린다.
세상 끝(`FIELD_R`)은 그대로 원이라, 위에서 보면 둥근 산 안에 네모난 마당이다.

## 종류를 번호로 가리지 않는다

늑대 종류(`WOLF_T`)·건물 종류처럼 **표에 줄이 늘어날 수 있는 것**을
`k >= 3` 같은 번호로 가리면, 표에 한 줄 붙이는 순간 열 군데가 조용히 틀어진다.
표의 칸을 보게 한다 — `isBoss(k)` 는 `WOLF_T[k].boss` 를 읽는다.

같은 이유로, **종류 번호로 색인하는 배열은 표와 길이가 같아야 한다.**
`SHEEP_BITE[w.k] || 10` 은 표가 밀렸을 때 오류를 내는 대신
**조용히 기본값으로 떨어진다** — 14차에 늑대왕이 이렇게 제일 약해졌고
16차에야 발견됐다. 검사에 "종류마다 빠짐없이 값이 있나" 를 넣어 둔다.

## 어두운 색을 칠하면 검은 상자가 된다

색은 텍스처에 **곱해진다** — 밝게는 못 하고 어둡게만 된다.
4차에 바위, 8차에 대장간, 17차d에 우리 바닥 자국까지 **세 번** 같은 데 빠졌다.
"흙색이니까 진갈색" 하고 `0x4a3a24` 를 주면 화면에는 새까만 상자가 놓인다.
바탕보다 **조금** 어두운 정도로 잡고, 반드시 찍어 본다.

## 인스턴스 칸은 제일 많이 쓰는 종류로 잡는다

`imesh(geo, mat, N, 1)` 의 N 이 모자라면 **오류가 안 난다 — 조용히 잘린다.**
17차d에 꾸밈 조각을 마리당 3칸으로 잡았는데 닭 한 마리가 넷을 썼다(볏 셋 + 부리).
우리를 닭으로 채웠을 때만 티가 났다.
'평균' 이 아니라 **제일 많이 쓰는 종류로 꽉 채웠을 때**를 기준으로 잡고,
검사에 `count <= instanceMatrix.count` 를 넣어 둔다.

## 밸런스는 재서 정한다

느낌으로 숫자를 고치지 않는다. `검사/bal5.mjs` 로 밤을 다섯 판씩 돌려 보고,
`검사/lvsim.mjs` 로 며칠에 만렙이 되는지 계산한다.
`진행상황.md` 에 지금까지 잰 표가 다 있다.

**기준도 같은 판에서 같이 잰다.** 옛 기록의 숫자와 오늘 잰 숫자를 비교하면 안 된다 —
16차에 15차 기록의 "2/5" 와 비교해서 "쉬워졌다" 고 판단할 뻔했는데,
같은 자리에서 기능을 끄고 다시 재 보니 기준 자체가 그 값이 아니었다.

## 선생님 설정

`index.html` 맨 위 `window.DEFAULTS` 에 낮/밤 길이, 목표 날짜, 수정 체력, **늑대 세기**가 있다.
반이 너무 쉬워하거나 어려워하면 `wolfPower` 를 만진다 (0.7 쉬움 / 1.0 보통 / 1.4 어려움).
