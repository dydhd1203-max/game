# 좀비의 밤 — 현재 개발 안내

초등학교 3학년 21명이 다섯 모둠으로 협동해 수정을 지키는 Three.js 브라우저 게임이다.
이 문서는 현재 기준만 담는다. 과거 수정의 이유가 필요할 때만 `기록/개발규칙-53차까지.md`와
`../클로드/진행상황.md`에서 관련 항목을 검색한다. 전체 이력을 매번 읽지 않는다.

## 사용자에게 확인한 방향

- 중심 재미는 친구들과 협동해 좀비를 막고 성장하는 것이다. 기존 보스 시스템은 유지한다.
- 사람은 둥글고 귀여운 블록 비율, 원통 머리, 얇은 웃는 얼굴, 실제 구멍이 열린 C자 손이다.
- 동물옷·잠옷·파스텔 꾸미기를 모자/얼굴 장식/옷별로 자유 조합한다. 꾸미기는 입장 전에만 가능하다.
- 1차→2차는 전투 카우보이→황금 보안관, 건설 발명가→천재 발명가, 자원 탐험가→보물 탐험가다. 이와 겹치는 챙 넓은 모자·고글형 안경은 시작 꾸미기에서 제외하고, 저장된 삭제 안경은 해제한다.
- 전직 후에는 직업 모자·의상을 우선 표시한다. 입장 전 꾸미기 저장값은 유지하며 얼굴 볼터치는 함께 표시한다. 실제 게임·미리보기·직업 아이콘은 같은 전용 곡면 기하를 사용한다.
- 전직해도 몸 크기는 그대로 유지한다. 직업별 의상·소품·날개를 바꾸며, 땅에서는 날개를 접고 활공 때 펼친다.
- 날개는 1차 .459·2차 .612 배율이다(66차 — 선생님 "날개를 좀 더 크고 멋있고 실제같은 모션으로": 63차 .3672·.4896 에서 같은 비율 +25%). 실제 새 날개처럼 손목에서 칼깃이 부챗살로 펼쳐지고 팔 아래 둘째날개깃·위 덮깃이 겹친다.
  점프 공중에서는 어깨 부착점을 고정한 채 분명하게 펄럭이되, 꼭짓점 셰이더(`WMAT_W`·JS 짝 `wingBend`)가 **팔꿈치·손목에서 굽혀** 깃 끝이 어깨보다 늦게 따라오고(위상 차) 올릴 때는 손을 뒤로 접고 칼깃을 모은다. 활공은 활짝 편 채 천천히 오르내리며 깃 끝만 떤다. 땅·조준·쓰러짐에서는 굽힘이 0 이라 CPU 관통 검사가 그대로 맞고, 조준·착지 때는 부드럽게 접는다.
- 게임 중 가방에는 무기·방어구·물약만 둔다. 기존 저장 아이템 ID를 무단 재정렬하지 않는다.
- UI는 밝은 크림/하늘/민트, 남색 본문, 읽기 쉬운 Noto Sans KR 400~600이다.
  **예외: 상점 창(`#popShop`)** 은 선생님이 준 참고 그림대로 짙은 나무 진열대 바탕·밝은 글씨·주황 구매 단추다(65차). 다른 창은 밝은 UI 그대로다.
- 좀비는 좁은 턱·둥근 두개골·굽은 등·가늘어지는 팔다리로 사람의 네모 몸과 구별한다. 밤 테마별 의상과 먹이 발견 후 달려드는 동작을 사용한다. 말라붙은 상처는 있고, 튀는 피·흐르는 피·내장·잘린 몸은 없다.
- 65차 좀비: 한쪽 다리를 저는 비틀걸음(좋은 다리 오래 딛고 저는 발은 끌며 휘돌림, 딛은 발은 땅에 고정), 무릎은 두 토막으로 실제로 굽는다. 손가락은 굽은 마디 한 조각(`ZOMBIE_GEO.digit`), 소매·바짓단·셔츠 자락은 톱니처럼 찢어진 가장자리(`ZOMBIE_GEO.tatter`), (66차에 살빛·눈매는 아래처럼 바뀌었다). 맞으면 흰 번쩍·움찔·불티·흙먼지, 죽으면 흙먼지·빛가루 — 피 파편은 없다.
- 66차 좀비(선생님: "더 무섭게 — 애들이 밤을 더 대비하고 싶게", "상처는 있어도 돼", "무서움 단계는 필요 없어" → 단계 설정 없이 한 모습): 잿빛 회청 시체색, 앞으로 빠진 목·낮은 머리(10% 작게)·무릎 아래까지 오는 긴 팔, 깊게 꺼진 눈두덩 위로 내리깐 눈두덩에 종류별 색으로 빛나는 눈(가까이선 동공 점, 밤엔 멀수록 커지고 안개를 덜 먹는다 — `eyeMat` 셰이더), 더 벌어진 턱·가늘고 누런 이, 공포 좀비는 크게 벌린 검은 입. **상처는 살 재질 셰이더(`zombieWoundSkin`)에 그린다** — 꿰맨 상처·검붉게 말라붙은 틈(몇 마리는 뼈가 희미하게)·긁힌 자국·멍·얼룩 살, 조각·행렬 0개, 움직이거나 흐르지 않는다. 바지 허벅지는 인스턴스 색 빨강을 음수로 적어(`zombieNoWound`) 상처를 빼고, 흰 번쩍에도 지운다. 동작: 몇 마리만(씨앗) 고개가 홱 꺾여 멈칫하는 경련·팔 떨림, 더 큰 휘청임·늦게 따라오는 머리, 날쌘·새끼 좀비는 낮게 기듯(`ZOMBIE_STYLE.crawl`), 협곡에서 나타날 때 땅에서 기어오름(`w.rise` 0.8초, `zombieRiseAt` — 호스트·손님 같은 규칙, 보스 제외), 쓰러진 뒤 누운 채 떨다 사라짐(`w.lieT` 0.75초). 전부 표시만 하고 위치·속도·판정·통신은 그대로다. 소리: `zombieVoices`(dreadTick)가 가장 가까운 넷만 신음(개체별 높이)·발견 비명(쉰 소리)·끄는 발·이빨·공포 좀비 숨을 `sfxAt` 로 낸다. 새 소리와 여러 목소리 울음(`howl`)·으르렁(`growl`)은 SFX 표 밖 `Object.assign(SFX, …)` 한 덩어리다. 세기는 65차 가장 큰 소리(kill) 아래.
- 레이싱은 넓은 코스와 속도감을 주되, 서로 부딪히면 조금 밀리는 물리 느낌을 유지한다.
- 넓어진 경주의 진자·바위는 기존 크기/속도의 2배다. 마지막 여섯 발판은 틈 5칸·높낮이 0.15칸이며, 점프 없이 통과할 수 없고 Shift 없이 한 번 점프로 건너도록 검사한다.
- Unity 이식이 아니라 기존 브라우저 게임 개선이다. Roblox풍은 디자인 방향이며 공식 모델 복제라고 설명하지 않는다.

## 성능 — 교실 노트북

**성능 이야기는 반드시 여기서 시작한다. 다른 문서의 옛 수치를 인용하지 않는다.**

교실 기기는 **LG gram · i7-1260P · Iris Xe 96EU · 8GB · 2560×1600(배율 150%) 스물한 대**다.
25차에 크롬북에서 바뀌었다. `클로드/index.html` 44줄(선생님 설정 구역)에도 적혀 있다.

교실에서 실제로 잰 값(`?diag=1` + Shift+9 — "끄면 얼마나 빨라지나"):

| 껐을 때 | 이득 |
|---|---|
| **화면 그리기** | **+31.5** (28 → 60fps) |
| 빛 번짐(bloom) | +12 |
| 그림자 | +4 |
| HUD | +2.5 |
| 게임 로직 통째로 | **−2** (잡음) |

33차: '선명' 40fps · 화면 그리기 끔 +21 · **해상도를 원본으로 올리면 −17**.

**병목은 픽셀(채움률)이다.** 재질이 `MeshLambertMaterial`(픽셀 단위 조명) + Fog 라
410만 픽셀마다 텍스처를 읽고 그림자 표본을 뜬다. **삼각형 수는 이 규모에선 공짜다.**

그래서:
- **불투명한 상자·인스턴스는 마음껏 늘려도 된다.** 장식 수천 개, 지도 확대 — 픽셀이 안 는다.
- **비싼 것은 픽셀을 겹쳐 칠하는 것**이다 — 투명·반투명 재질, 빛무리, 입자 구름, 빛 번짐.
  유리창을 투명 재질로 만들지 마라. `EMITC_F` 로 **불투명한 빛나는 판**을 쓰면 밤낮 처리도 공짜다(18358줄).
- 제일 센 손잡이는 해상도 배율(`pr`)이다. 기본은 '보통'(pr 0.85 · 그림자 2048 · MSAA2).
- `t32` 의 "재질 여덟 이하" 는 성능이 아니라 **그림체 통일** 규칙이다.
- **검사기는 소프트웨어 렌더링이라 GPU·MSAA 비용을 못 잰다.** 교실에서 재기 전에는
  "빠르다/느리다" 를 적지 않는다. 검사기가 말해 주는 것은 "돌아간다 · 모양이 맞다" 까지다.

⚠️ `기록/개발규칙-53차까지.md` 에 있던 "GPU 는 범인이 아니다 · 병목은 CPU·DOM" 표는
**24차 이전 크롬북 값**이라 63차에 지웠다. 지금과 정반대이니 어디서 마주쳐도 인용하지 않는다.

## 유지할 구현 규칙

- **그림체 원칙(67차, 선생님)**: "캐릭터만 아이들이 좋아하는 로블록스풍이었으면 좋겠어. 그 외 것들은 사실적이고."
  - 아이 캐릭터(사람 아바타)만 로블록스풍으로 둔다 — 상자 몸, 원색, 매끈한 면.
  - 그 밖의 것(성곽·건물·소품·조명·무기·자연·좀비 등)은 사실적으로 만든다. 좀비는 65~66차에 이미 사실 방향이다.
  - 노트북(gram, Iris Xe) 성능이 허락하는 안에서 최대한 사실적으로 — 아이템(총·도구·물약·자원·떨어진 금·상자)도 포함한다(67차에는 성곽 안팎과 성곽 보물 상자·금화 더미·반짝 주머니만, 68차에 아이템 전체).
  - 68차 아이템: 디테일은 **1인칭 손에 든 것에 가장 많이**(총열·방아쇠와 울·개머리 나무결·나사·가늠자/가늠쇠·탄창·손잡이 홈 / 자루 결·감은 가죽·쇠 테·쐐기·닳아 밝은 날 끝), 멀리 보이는 것은 실루엣만 또렷하게(광맥·동전 깃발·상자 한 인스턴스). 반투명 대신 불투명 색 단계(물약 병 = 액체 색 + 옅은 유리).
  - 68차 2단계: 특수 총 열 자루(수정 광선총·흑요석·황금 연발총·목장 장총·천둥·화염 대포·기관총·클로버·매의 눈·용의 숨결)도 같은 부품(hX·gL·gBand·gTube·ridgeProf·gScale)으로 다시 깎았다 — 재료색(구리·사기·법랑·가죽)은 꼭짓점 색, 새 재질 0. 1인칭 카메라는 총의 **오른쪽(−x) 옆면**을 보므로 압력계·장전 문·탄약통 같은 눈에 띄는 부품은 −x 쪽에 둔다. 옮기기(V)는 쇠 지렛대(`mkCrowbar`, `HELD.move`)를 든다. 3인칭 `TPGUN` 도 같은 실루엣·재료색으로 맞췄다(조각 ≤14 · 빛 ≤4).
    고침: 1인칭에서 가장 크게 보이는 개머리 끝은 `STOCK_BEV`(두께 쪽 모따기 ≈ 폭의 1/3 → 뒤에서 단면이 타원)와 `gButt`(개머리 뒷선을 따라 굽은 받침판 — 쇠·법랑 'cap', 목장 장총 초승달 'cres', 고무 'pad' 가로 홈)로 깎는다. 네모 받침판을 다시 쓰지 않는다.
    빛 재질(matGlow 등)은 어느 도우미로 붙이든 수정 타일(`glowy(m) ? T.crystal : T.cloth`) 위에 얹는다 — 천 타일에 얹으면 새 평면 재질이 생기고 같은 총 안에서 빛 색이 둘로 갈린다(gBand·gRing·gScale 도 맞췄다).
    3인칭 둥근 조각(aRnd 1)은 단면(폭·높이)이 원이 된다 — 옆에서 둥글게 보여야 하는 드럼은 r[10] = π/2 로 눕혀 원 면이 옆을 보게 한다.
    쇠 지렛대(`mkCrowbar`)의 거위목은 작게(반지름 0.047 · 막대 0.6 의 1/13) 굽혀 끝이 막대 쪽으로 돌아오게 한다 — 크게 굽히면 지팡이로 읽힌다. 발톱은 V 홈 판 넓고 얇은 쐐기, 굽은 면은 막대 축으로 60° 돌려(육각이라 이음이 맞음) 1인칭에서 쐐기 면이 보이게.
  - 상자(BoxGeometry)를 쌓아서 만들지 않는다. 물건마다 알맞은 새 기하를 만든다. 둥근 것(횃불·초·통·우물·종·방패·사슬 등)은 Cylinder·Lathe·Torus·Extrude 로 만든다(여러 부품은 `geoMerge` 로 꼭짓점 색 기하 하나에 굽는다 — 소품 하나 = 인스턴스 하나).
  - 원래 네모인 것(마름돌·판석·궤짝 몸통)도 모따기를 하고 크기와 색을 흔든다.
  - 성능 방식은 유지한다: 모양 하나 = 뱅크 열쇠 하나, 인스턴스, 새 재질 0, 투명 0, PointLight 0.
- 파일 하나를 옮겨 열 수 있어야 한다. 현재 의존성은 CDN의 Three.js 0.160.0이다. 새 프레임워크/빌드 체계를 불필요하게 추가하지 않는다.
- Codex와 Claude가 병행 작업 중이다. 올리기 전 `origin/main`을 가져와 양쪽 변경을 함께 보존하고, 같은 모션 함수의 충돌은 관절·접지·겹침 검사를 함께 돌려 해결한다.
- 수치·물리·공격 타이밍은 실제 게임 함수를 실행해 검사한다. 테스트에 계산식을 복사해 같은 답을 만드는 방식은 피한다.
- 화면은 실제 DOM 경계와 렌더 결과를 확인한다. 짧은 화면에서도 설명·가격·구매 버튼을 읽고 누를 수 있어야 한다.
- 실제 동작을 바꾼 뒤에만 검사를 갱신한다. 코드 정리만 하는 경우 실행 구조가 같음을 확인한다.
- `imesh`의 최대 인스턴스 수를 최악 조합으로 검사한다. 칸이 부족해도 오류 없이 그림이 잘릴 수 있다.
- **움직이는 것이 들어가는 패스를 본 패스보다 드물게 갱신하지 않는다.** 그림자 지도를 15Hz 로
  줄였더니(34차) 캐릭터는 60fps 로 가는데 그 그림자만 네 프레임에 한 번 따라와, 화면에서
  캐릭터가 잔상처럼 깜빡였다. 걷기 5.94칸/초면 66ms 에 0.39칸 — 다리 두께(0.21칸)보다 크다.
  성능을 재보니 몰아 그리는 쪽이 오히려 프레임 턱을 만들어 더 느렸다(평균 13.55ms·최악 26.6ms
  → 매 프레임 13.33ms·최악 13.5ms). 지금은 `GFX_PRESET`의 `shHz`가 그 손잡이다(0 = 매 프레임).
- **"화면이 깜빡이는데 스크린샷에는 안 찍힌다" 는 기하를 재도 안 나온다.** 인스턴스 행렬을
  84개 메시 × 전 이동 조건으로 다 떠도 전부 매끄러웠다 — 그림자는 **별도 렌더 패스**라 거기
  안 잡히기 때문이다. 이런 증상은 **증상이 사라지는 설정을 먼저 찾고**(`?gfx=low`, 다른 기기),
  그 설정이 바꾸는 것만 대조하라. 자세한 순서와 이미 기각된 가설은
  [깜빡임 진단](기록/깜빡임-진단.md)에 있다. 고치기 전에 먼저 읽는다.
- 같은 `bpush` 키에 서로 다른 기하를 섞지 않는다. HUD의 `setTxt`/`setSty` 변경 감지를 유지한다.
- 사람 머리·눈·입·장식에는 같은 변환을 적용한다. 오른손은 모델의 -X 쪽이다. 화면 좌우와 혼동하지 않는다.
- 사람 전용 `R6_*_GEO`를 고칠 때 공용 `RB`/`CYL`까지 바꾸지 않는다. 얼굴 표면 계산은 `R6_HEAD_SEG`와 같아야 한다. 옷 좌표와 저장된 꾸미기 ID는 유지한다.
- 팔꿈치·무릎·신발과 손에 든 장비는 실제 관절 끝에 맞춘다. 접촉 그림자는 몸통 흔들림이 아닌 바닥 높이를 사용하며, 레이싱 빈 공간에는 그리지 않는다.
- 사선 이동에서 팔은 몸통 바깥으로 흔들고 두 발은 서로를 통과하지 않는다. 사람의 얇은 옷·얼굴 장식은 그림자를 주고받지 않으며, 몸은 바닥에 그림자만 드리운다. 직업 모자 챙은 머리 윗면과 간격을 유지한다.
- 잠옷 색은 `CLOTH_BODY`로 몸통 자체에 입힌다. 팔 안쪽에 겹치는 몸판을 다시 쌓지 않으며, 직업 허리 주머니·어깨 장식도 팔이 흔들리는 경로 밖에 둔다. 게임·대기실·옷 아이콘의 색을 함께 맞춘다. 기하 검사는 `CLOTHES`의 첫 선언뿐 아니라 현재 꾸미기 표를 만드는 후속 변경도 실행한다.
- 사람의 표시용 걸음은 걷기 최대 초당 1.6회·달리기 2회로 제한한다. 발을 세계 좌표에 고정했다가 관절 길이 한계에서 풀지 않고, 접지와 들림의 위치·속도가 이어지는 곡선을 사용한다. 물리 이동 속도와 통신은 그대로 유지한다.
- 닫힌 직업 모자는 머리 윗부분을 실제로 감싸야 한다. 모자 챙만 올려 머리와 모자가 따로 놀게 하지 않으며, 띠의 윤곽과 앞 장식도 모자 표면에 맞춘다.
- 양손 총은 손잡이·부품·강화 효과가 같은 반동 축을 쓴다. 긴 총열은 고정된 뒤끝에서 앞쪽으로만 늘려 몸통을 관통하지 않게 한다.
- 걷기·달리기는 로블록스 R6처럼 거의 편 팔다리를 흔드는 진자다. 관절은 남기되 깊게 접지 않는다.
  엉덩이 낙차는 상수가 아니라 보폭에서 구한다(`stanceDip`). 유각의 수직 들림을 키우면 코사인 법칙상
  무릎이 강제로 접히므로 올리지 않는다. 팔은 발 곡선을 물려쓰지 말고 순수 코사인을 쓴다.
  이동 중 무릎이 최대 길이에 닿는 구간은 `sheepJoint`의 완만한 거리 제한으로 잇는다. 정지·공중 자세에는 적용하지 않는다.
  **팔은 다르다 — 무릎처럼 `soft` 를 주면 안 된다.** 팔은 걸음 내내 거의 완전히 펴져 있어
  어깨-손 거리가 `0.35999~0.36111` 로 **0.0011 밖에 안 움직인다.** `soft` 는 그보다 훨씬 커서
  그 구간을 통째로 뭉개고, `t57-motion-static` 의 'Elbows keep breathing' 검사를 깬다.
  `bend` 에 하한을 두는 것도 같은 이유로 안 된다. **둘 다 실제로 CI 에서 실패했다.**
  대신 `armSwing` 을 `dirF` 로만 만들지 마라 — 옆으로 걸으면 `dirF≈0` 이라 0 이 되어 `bend` 가
  최솟값에 **고정**되고, 걸음 주기 내내 IK 특이점에 눌러앉아 팔꿈치가 떨림을 15배 넘게 증폭한다.
  이동 방향 전체 크기(`hypot(dirF,dirS)`)를 써서 옆걸음에서도 앞걸음처럼 흔들리게 한다.
  팔 떨림을 고칠 때는 상수를 눈으로 맞추지 말고 **증폭률을 재라**(1.0 이면 정상, 5 이상이면 보인다).
  측정법·실패한 시도·남은 문제는 [팔 떨림 진단](기록/팔-떨림-진단.md)에 있다. 먼저 읽는다.
  측정 방법·숫자·이미 기각된 가설은 [팔 떨림 진단](기록/팔-떨림-진단.md)에 있다. 이 버그는 검사가 못 잡아서
  여러 번 되돌아왔다 — 고치기 전에 그 문서를 먼저 읽는다.
- 카메라는 점프 중 실제 사람 높이를 따른다. 숨김/복귀 문턱을 분리해 벽 근처 깜빡임을 막는다.
- 사격은 어깨 너머 3인칭을 유지하고 본인 날개를 접어 조준선 주변을 비운다. 벽 때문에 카메라가 가까워지면 본인 몸만 숨기며, 다른 사람의 외형은 유지한다.

- 실제로 나가는 무기는 `wpnEff`가 한 곳에서 정한다. 조준점 잠금과 발사가 같은 무기를 봐야 한다.
- 위치 통신 형식/빈도를 임의로 늘리지 않는다. 보스 체력·AI·보상·등장 규칙은 디자인 수정과 분리한다.
- 좀비의 먹이 발견 자세는 호스트의 실제 `shT`를 따르고, 손님은 기존 이동 데이터에서 추격 자세만 추정한다. 시각 상태가 이동 속도·공격 판정을 추가로 바꾸지 않게 한다.
- 좀비 전용 기하·재질을 공용 `RB`/`FM`과 분리한다. 옷·갑옷·등 장식의 위치는 `drawWolves`의 `TX`/`TY`/`TZ`를 통해 실제 몸통 회전·호흡에 붙인다.
- 좀비의 잔선은 최소화한다. 볼은 얕은 음영, 망토는 한 장의 곡면으로 두고 닫힌 모자 속 머리털을 숨긴다. 겹친 투구 챙·반복 자락·등 주름·작은 공통 패치를 다시 쌓지 않는다.
- 공포 좀비 눈동자는 흰자 안쪽, 짧고 뾰족한 이는 입 안쪽에 둔다. 붕대는 머리·몸통·팔을 한 바퀴 감싸는 얇은 천으로 붙이고 얼굴 앞에 천 조각을 늘어뜨리지 않는다.
- 좀비가 뻗는 손은 손바닥을 아래로 향하고 손끝도 아래로 구부린다. 어깨를 감싼 둥근 천 토시·망토 어깨 덮개는 쓰지 않는다.
- 좀비 길찾기는 `terrH`, 건물은 `bldH`를 사용한다. 높이 도달 제한과 PvP 벽 차폐를 유지한다.
- 테이블 종류는 `boss` 같은 속성으로 구분한다. 번호 범위로 단정하지 않는다. 삭제한 필드는 소비 지점까지 검색한다.
- `Object.assign(window, ...)` 검사 API 이름을 중복 선언하지 않는다.
- 데스크톱 커서 조작은 하지 않는다. 자동 pointer lock을 넣지 않고 초점/탭 이탈 시 입력과 잠금을 해제한다.
- 건설 설계도는 모둠당 12개, 동시 작업 속도는 3명에서 상한이다. 손을 떼어도 진행을 유지하고 90초 방치 시 해제한다.
- 건설 완료·강화·수리·철거·자원 보내기는 호스트에서 현재 자원으로 처리한다. 새 위치/분기/소유자 필드를 건물 저장 시 보존한다.
- 자동문·스프링 함정은 사용자 요청으로 추가하지 않는다. 새 포탑과 특화 공격이 기존 보스 AI·등장·보상을 바꾸지 않게 한다.
- 화살탑은 Lv1~2에서 활을 쓰고, Lv3의 연사 기관총/대형 저격총 선택부터 실제 무장이 바뀐다. `blocksOf` 행의 11번째 값 `gun`인 부품만 회전/반동을 적용한다.
- 충격파 포탑은 65차에 **대포탑**이 됐다. 저장·통신 열쇠는 `t:'pulse'` 그대로다(바꾸면 저장된 건물이 안 읽힌다). 피해·범위 판정(`range`·`area`·`dmg`·`rate`, 밀지 않음)은 쏘는 순간 호스트에서 하고, 포탄·폭발·숫자·흰 번쩍은 `towerFx…`가 착탄 때 보여 주기만 한다. 착탄 고리는 땅에 눕힌 어두운 주황 한 겹(끝 반지름 ≈ `area`)이다 — 카메라를 보는 세운 흰 고리는 화면을 가로질렀다.
- 탑 효과는 불투명 조각 풀(`tfxBallMesh`·`tfxChipMesh`·`tfxShellMesh`)과 기존 `burst`/`ring`만 쓰고, 초당 조각 예산(`TFX_RATE`)과 먼 곳 생략(`TFX_FAR`)을 지킨다. 새 투명 면·빛무리·점광원은 넣지 않는다.
- 3인칭 총은 `TPGUN` 표(무기 번호마다 12~14조각)대로 그린다. 원점은 오른손 손잡이 한가운데, f 총구 쪽·u 위·sd 몸 왼쪽(+). **[2]는 오른손 손잡이 (0,.03,0)·기울기 없음, [3]은 왼손이 받치는 몸통, [1] 개머리는 몸통 앞면까지** — `t61`·`t53`·`t54`가 이 약속을 본다. 총구는 표의 `mz`, 강화 빛은 `bar`를 감싼다. 정원은 `P_gun` = `MAXP×TPGUN_MAX`, `P_gunF` = `MAXP×(TPGUN_GLOW+2)`. 새 총을 더하면 표에 줄을 더하고 이 정원을 다시 본다.
- 어깨 너머 조준 카메라(`AIM_VIEW`)는 어깨 1.10·높이 1.58이다(65차 마감 — 가슴 앞 총이 머리·오른팔에 가려서 조금 오른쪽·위로). 조준선은 여전히 화면 중앙 ray이고 몸·날개가 조준선을 가리지 않아야 한다(`t57-character-view`).
- 성문(66차): 통로(|pp|<7)에는 몸·그림 조각을 두지 않는다(애들 벽 자리·좀비 길). 통로 위 성벽 길처럼 **아래가 비어 있는 발판**은 지형 격자에 못 담으므로 `GBOX` 상자로 두고, `groundUnder(x,z,R,y)` 는 사람 발 높이 `y` 를 넘겨받을 때만 상자를 본다(발+STEP 안이면 딛고, 몸에 걸리면 막고, 머리 위면 무시). 사람 몸을 옮기는 새 부름은 `y` 를 꼭 넘긴다. 계단 칸은 `bldH` 라 좀비 길찾기엔 평지로 보이므로 흐름장이 `RAMP_FLOW` 로 비싸게 매겨 돌아간다. 모둠 표시는 벽·기둥에 붙은 천 깃발·번호판만 쓴다 — 공중에 뜬 판·바닥 색 띠를 다시 두지 않는다.
- 성곽(67차): 치수는 `CW`·`CPLAN` 한 곳에만 둔다(몸·그림·좀비·보물이 모두 읽는다 — 64차 '끊어진 계단'). **모든 천장 밑면 ≥ 그 밑 딛는 면 + 2.2**, 바깥 울타리(`GK.FENCE`) 윗면 ≥ 아이가 설 수 있는 가장 높은 면 + 6.5. **지붕 밑(그 층 문턱 빼고) 아이는 어떤 좀비도 쫓지도 물지도 않는다**(`sheltered` 하나를 쫓기·`sheepHurt` 가 같이 부른다) — 대신 거기서 쏘면 성곽 벽이 막고 쏘기 틈(`CPLAN.apertures`)으로만 나간다(`castleOccluded`). 좀비의 땅↔성곽 층 전환은 **계단 칸 안(t 34.5)** 에서만, 높이는 `layerY`/`wolfY` 한 함수(칸 기준 — 호스트·손님 같은 x 에서 같은 y). 성벽 위 좀비 수는 계단당 3·전체 8·아이 한 명당 한 밤 4·12초(물려도 15초)·한 밤 한 번·새벽 귀환 예산(`BAL.climb`·`CLIMB_RET`). 둘레길·성곽은 `pathLines` 에 넣지 않는다(난수 순서가 흔들려 자원·꾸밈 자리가 통째로 바뀐다). 보물은 아이마다 로컬(`TRE`, `localStorage` 열쇠 = 방·판 번호 `sid`(+날), 늘 try/catch) — 하루 한 상자(80/15/5)·첫 발견 금화 더미·반짝 보물 하루 다섯 곳(방·날 씨앗, 통신 0)·🗝️(사람 칸 `ex` 하나). 들판 보물 상자(`CH_MAX`·`chestReward`)와 경제 규모를 맞춘다. meta 에는 판 `v`(손님 판이 다르면 새로고침 알림)·`sid`·위험 구간 `dg` 셋만 더했다.
- 성곽(69차 — 선생님이 67차를 교실에서 해 보고 고친 점):
  - **나선은 보통 땅처럼 걷는다.** 접선 레일·강제 시선 회전·8층 '층 멈춤'·달리기 끔을 없앴다. 몸은 디딤 높이(`spiralH`)·우물 벽·기둥(999)·머리 위 디딤(`spiralCeil`)만으로 오르내리고, 둥근 벽에 비비면 `spiralSlide` 가 호를 따라 미끄러뜨린다. **게임이 아이의 시선(yaw)을 돌리는 도우미는 두지 않는다** — 문 깔때기(`doorFunnel`)는 걸음 방향만 최대 20°(3칸 안) 휜다.
  - **자동 1인칭은 겹쳐 쓰기다.** 아이가 고른 시점(`camZoom`)을 절대 바꾸지 않는다 — 자동 1인칭 동안 휠은 무시하고 알림만(3초에 한 번). 덮임은 칸 비트 + 머리 위 실제 천장 상자(`camCov`)라 지붕 위는 밖이다.
  - **계단 카메라 보간**: 땅에 붙은 채 디딤 높이만큼 툭 오르내리면(`camStepAdd`) 카메라는 제자리 어긋남(`camStepY`)을 임계 감쇠(ω 14, 한도 ±0.8)로 되돌린다. 땅에 붙어 걷던 아이는 한 단(≤ STEP) 아래로 떨어지지 않고 붙는다(착지 먼지·툭·camDip 이 디딤마다 터지지 않게 — 미니게임 밖에서만). 3인칭 벽 검사는 몸의 실제 눈높이에서 시작한다.
  - **돌 질감은 셰이더로**: 결 셰이더(`addGrain`)의 `ASH_VERT`/`ASH_FRAG` 가 인스턴스 색 빨강에 +2t 를 얹은 조각(`bflag` → `bbuild`)만 무늬를 그린다 — 1 평면 마름돌(탑 안벽·나선 우물 판·쏘기 틈 볼·문 안감) · 2 원통 마름돌(나선 구석 메움, 가운데는 정수 칸) · 3 돌판 거칠기(디딤·바닥 판석·안쪽 돌). 조각·재질 0 추가. 결 투영 축은 꼭짓점 법선으로 고른다(45° 면 빗살 무늬 방지).
  - **쏘기 틈은 바깥 0.8 × 1.4 → 안 벽감 1.2~1.3**(`embrasure`·`slitFrame`·`slitHole`) — 복도 24 · 초소 16 · 회랑 20. 조준 가림 표(`CPLAN.apertures`)도 같은 치수, 몸 칸은 막힌 채(좀비 못 드나듦).
  - 망루 창은 트여 있다(덧창·창살·망원경 없음). 밤 '탑 창 불빛 줄'은 창 구멍 안쪽 빛 테(`cwinL` · `WINLG` · EMITC_F). 회랑 문은 곧은 문(탑 벽에 수직, x 36). 안내판은 문 옆 작은 나무 판(모둠 색 테·새긴 화살·숫자, 화살은 문 쪽).
  - 겉돌 면(`face`)은 구멍 가장자리 0.36 안에 떨어지는 이음매를 가장자리로 옮기고, 구멍에 잘린 돌은 세로·가로 두 가지 자르기 중 버리는 부스러기(0.28 × 0.1 미만)가 적은 쪽을 쓴다 — 버린 부스러기 자리는 짙은 속 몸이 검은 구멍으로 보인다.
  - '보통' 그림자도 PCFSoft(r160 표본 16 — PCF 17 보다 하나 적다). 같은 면 겹침은 `t67-castle-walk` G1 이 센다(넓이 ≥ 0.1 = 0).
- 숨김 브라우저는 `pw.mjs`로만 실행하고 `finally`에서 종료한다. GPU 속도와 21명 실접속 성능은 교실 기기에서 별도로 측정한다.

## 수정 후 검사

작업 트리 뿌리에서 `node 깃허브에올릴것/검사/check-current.mjs`로 현재 Node 검사를 한 번에 실행한다.
GitHub 에 올리면 `.github/workflows/checks.yml`이 같은 명령을 다시 돌리고, 원본과 배포용의
SHA-256 도 함께 본다. 손으로 돌리는 것을 대신하지는 않는다 — 올리기 전에 먼저 확인한다.
실제 화면까지 확인할 때만 `--render`를 붙인다. 브라우저는 한 개씩 실행하고 결과는 간단히 출력한다.
문법만 볼 때는 `node 깃허브에올릴것/검사/chk.mjs 클로드/index.html`을 사용한다.
수정 범위에 따라 아래 검사를 실행한다. 테스트 라이브러리는 검사 폴더에만 두고 게임 의존성으로 추가하지 않는다.
