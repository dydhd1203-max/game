# 캐릭터가 잔상처럼 깜빡이던 문제 — 원인은 그림자였다

증상(사용자 원문): **"움직일 때 캐릭터가 잔상처럼 깜빡여. 특히 옆으로 갈 때, 앞으로 갈 때는
다리 부분이. 그 장면을 스크린샷 찍어도 스크린샷에는 잔상이 안 나와."**

여러 번 고치려다 실패했다. 이 문서는 **왜 못 찾았는지**와 **어떻게 찾았는지**를 남긴다.
같은 종류의 증상을 만나면 4장의 방법부터 쓰면 된다.

---

## 1. 원인 — 그림자만 초당 15번 갱신됐다

```js
const SH_HZ = 15;
shAcc += dt; if(shAcc >= 1/SH_HZ){ renderer.shadowMap.needsUpdate = true; shAcc = 0; }
renderer.shadowMap.autoUpdate = false;
```

34차에 그림자 지도를 15Hz 로 줄였다. 그때 근거는 주석에 이렇게 적혀 있었다:

> "세계는 정지해 있고 해는 느리게 움직이니 15Hz 면 아무도 못 알아본다"

**세계는 맞지만 사람이 빠졌다.**

```
걷기 속도 SPD = 5.94칸/초
15Hz 지연  = 66ms
66ms 동안 이동 = 0.39칸
다리 두께      = 0.21칸      ← 지연이 다리보다 크다
```

캐릭터는 60fps 로 움직이는데 **그 그림자만 네 프레임에 한 번 뚝 따라붙는다.**
그게 초당 15번 반복되므로, 화면에서는 캐릭터가 잔상처럼 깜빡이는 것으로 보인다.

증상의 세부까지 다 맞는다:

| 사용자가 말한 것 | 그림자 15Hz |
|---|---|
| 특히 **옆으로** 갈 때 심함 | 그림자가 화면에서 가장 많이 밀리는 방향이다 |
| 앞으로 갈 때는 **다리** 쪽 | 다리 그림자가 발밑에 제일 가깝고 제일 빨리 움직인다 |
| **스크린샷에는 안 나온다** | 한 장에는 그림자가 조금 어긋난 정도라 음영으로 보인다. 깜빡임은 프레임 사이의 변화다 |
| 그래픽 설정을 바꿔도 그대로 | `high` 도 `mid` 도 `shadow:2048` 이라 똑같이 깜빡였다 |

---

## 2. 어떻게 찾았나 — 프리셋 대조

사용자가 그래픽을 **'부드럽게'** 로 바꿔 보고 증상이 사라지는 것을 발견했다.
그리고 휴대폰에서도 멀쩡했다. 프리셋을 나란히 놓으면 답이 바로 나온다.

```js
high: {shadow:2048, aa:4, pr:1.0 }   ← 깜빡임
mid:  {shadow:2048, aa:2, pr:0.85}   ← 깜빡임
low:  {shadow:0,    aa:0, pr:0.7 }   ← 멀쩡
if(isTouch){ GFX.shadow = 0; ... }   ← 휴대폰도 그림자 0 → 멀쩡
```

**멀쩡한 두 경우의 공통점이 `shadow:0` 하나뿐이다.** 이게 결정적 증거였다.

> **교훈: 증상이 사라지는 설정을 찾으면, 그 설정이 바꾸는 것만 비교하라.**
> 코드를 아무리 읽어도 안 나오던 답이 프리셋 표 세 줄로 나왔다.

---

## 3. 왜 그렇게 오래 걸렸나 — 측정이 엉뚱한 곳을 봤다

증상이 "스크린샷에 안 찍힌다" 였으므로 자세(포즈)가 아니라 프레임 사이의 문제로 좁혔다.
거기까지는 맞았다. 그런데 그 뒤로 **캐릭터가 그리는 값**만 팠다:

- 84개 인스턴스 메시 × 60~90프레임 × **행렬 16개 값 전부**(위치·회전·크기) → 이상 0건
- 인스턴스 개수 변동 0회, 보임/숨김 변동 0회
- 매 프레임 진동 0건, 걸음마다 튀는 것 0건
- 앞/옆/달리기/대각선/전직 상태까지 전부 → 전부 매끄러움
- 프레임 간격 60fps 에 편차 0.07ms, 끊김 0회

**전부 깨끗했다. 그런데 화면은 깜빡였다.**

이유는 간단하다. **그림자 지도는 완전히 별도의 렌더 패스다.**
`scene` 의 인스턴스 행렬에는 그 패스의 갱신 주기가 전혀 나타나지 않는다.
캐릭터 기하를 아무리 정밀하게 재도 그림자 지연은 절대 안 잡힌다.

> **교훈: "그리는 값이 매끄럽다" 는 "화면이 매끄럽다" 가 아니다.**
> 한 프레임을 만드는 데 관여하는 **패스가 여럿**이고, 서로 다른 주기로 돌 수 있다.
> 기하를 다 재고도 못 찾으면, **패스별 갱신 주기**를 의심하라.

### 이때 기각된 가설들 (다시 파지 마라)

| 가설 | 왜 아닌가 |
|---|---|
| 팔 IK 특이점 | 실제로 존재하는 문제였지만(별도 문서) 이 증상의 원인은 아니었다. 고쳐도 그대로였다 |
| 해상도 축소(pr 0.85) | `?gfx=high`(pr 1.0)로도 똑같았다 |
| 인스턴스 유령 행렬 | `count` 가 150프레임 내내 한 번도 안 변했다 |
| 프레임 끊김 | 60fps 에 놓친 프레임 0개, GPU 23% |
| 자기 그림자(receiveShadow) | 사람 부품은 이미 `receiveShadow=false` 다 |
| 모니터 주사율 | 60→75Hz 로 올려도 똑같았다 |

## 4. 같은 종류의 증상을 만나면 — 순서

1. **증상이 사라지는 설정을 먼저 찾아라.** 그래픽 프리셋(`?gfx=high/mid/low`), 다른 기기,
   다른 브라우저. 하나라도 멀쩡한 조건을 찾으면 범위가 단번에 줄어든다.
2. 그 조건이 **무엇을 바꾸는지**만 비교하라. `GFX_PRESET` 세 줄이면 끝난다.
3. 기하(행렬)를 재는 것은 그 다음이다. 그리고 **기하가 깨끗해도 끝이 아니다** —
   그림자·후처리·미니맵처럼 **주기가 다른 패스**가 있는지 본다.
4. 진단 화면 `?diag=1` 을 쓴다. `★프레임분포` 와 `★GPU실제` 가 보이고,
   숫자키 토글로 항목을 하나씩 꺼 가며 무엇이 원인인지 가를 수 있다.
   `'그림자 매 프레임'` 토글이 바로 이 문제를 재는 것이다.

---

## 5. 고친 방식

갱신 주기를 그래픽 프리셋의 손잡이(`shHz`)로 만들었다. `0` 이면 매 프레임이다.

```js
high: {shadow:2048, bloom:0, aa:4, pr:1.0,  shHz:0},
mid:  {shadow:2048, bloom:0, aa:2, pr:0.85, shHz:0},
low:  {shadow:0,    bloom:0, aa:0, pr:0.7,  shHz:0}
```

```js
renderer.shadowMap.autoUpdate = !GFX.shHz;                 // 0 이면 three.js 가 매 프레임 갱신
if(SH_HZ){ shAcc += dt; if(shAcc >= 1/SH_HZ){ ... } }      // 0 이 아닐 때만 손으로 조인다
```

### 성능 — 줄일 이유가 애초에 없었다

GTX 1660 · 걷는 중 · 각 70프레임씩:

| | 평균 | **최악** |
|---|---|---|
| 15Hz (전) | 13.55ms | **26.6ms** ← 네 프레임에 한 번 몰아 그려 프레임이 두 배로 튄다 |
| 매 프레임 (후) | **13.33ms** | **13.5ms** ← 고르게 펴져 턱이 사라진다 |

**매 프레임이 오히려 빠르다.** 15Hz 는 성능도 못 얻고 깜빡임만 만들고 있었다.
몰아 그리기가 프레임 예산 안에 들어가는 기기에서는, 나눠 그리는 쪽이 항상 낫다.

적용 뒤 기본값('보통')으로 다시 재니 **75fps · 평균 13.33ms · 최악 13.4ms · 20ms 넘김 0회.**

### 교실 기기에서 무거우면

`GFX_PRESET` 의 `shHz` 를 `15` 나 `30` 으로 되돌리면 된다. `mid` 만 되돌려도 좋다.
34차의 측정(그림자 패스가 본 패스와 맞먹는다)은 지금도 사실일 수 있다 — 다만 GPU 가
남는 기기에서는 그것이 프레임 예산을 넘지 않는다. **교실 노트북에서 `?diag=1` 로 재보고 정하라.**
