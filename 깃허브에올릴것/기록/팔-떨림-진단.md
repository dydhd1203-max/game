# 팔 떨림 — 왜 여러 번 고쳐도 계속 돌아왔나

증상: 움직일 때 팔이 떨리고 아바타가 어긋난다. **특히 옆으로 움직일 때** 심하다.

이 문서는 원인과 측정 방법을 남긴다. 다음에 같은 증상이 보이면 **먼저 아래 측정을 돌려라.**
눈으로 보고 상수를 바꾸는 방식으로는 이 버그를 못 잡는다 — 그래서 여러 번 실패했다.

---

## 1. 왜 계속 실패했나 — 검사가 이 버그를 볼 수 없다

검사가 120개 넘게 있는데 **팔 떨림을 잡을 수 있는 검사가 하나도 없다.**

| 검사 | 왜 못 잡나 |
|---|---|
| `t58-motion-static.mjs` 옆걸음 | **정지한 한 프레임**만 본다. 떨림은 프레임 사이에서 생기므로 원리상 불가능하다 |
| `t57-motion-static.mjs` 보행 | 매 프레임 배우를 **새로 만든다**. 떨림이 사는 프레임간 필터(`gs.arms`)를 통째로 건너뛴다 |
| 팔 부착 검사 | **Z축만** 읽는다. 팔이 양옆(X)으로 벌어지는 T 자세를 잡는 단언이 저장소 전체에 없다 |
| `t58` run 전환 | `s.gp` 를 `.8` 로 고정해서 **다리가 한 걸음도 안 돈 채** 통과한다 |
| `t57-character-view.mjs` | 단언이 **부품 수·삼각형 수**뿐이다. 완전한 T 자세도 통과한다 |

그래서 고칠 때마다 검사는 초록불인데 화면은 그대로였다.
`1155fb6 "관절 떨림을 해결한다"` 이후에도 아래 원인은 코드에 그대로 남아 있었다.

## 2. 진짜 원인 — 팔 IK 가 특이점(singularity) 위에 앉아 있다

관련 줄 (수정 전 기준):

```js
// 9854  팔 흔들림을 앞뒤 성분 dirF 로만 만든다
const swing=Math.cos(gait+(si>0?0:Math.PI)); armSwing[si>0?0:1]=swing*dirF;

// 9881  팔꿈치 굽힘
const bend=down?.12:.10-mvK*(.055+runK*.020)+mvK*Math.max(0,-armSwing[si>0?0:1])*(.12+runK*.17)
         +airK*(.18+rise*.20)+wind*(si<0?.65:.30)+strike*.12;

// 9885  굽힘각으로 팔꿈치·손 위치를 만든다
elbow=reach(shoulder,upper,aL*.50); hand=reach(elbow,fore,aL*.36);

// 9893  그 손을 다시 IK 로 푼다 — soft 인자가 없다(=하드 클램프)
const jointPose=sheepJoint(shoulder,hand,aL*.50,aL*(hasGun?.43:.36),elbow.map((v,i)=>v-shoulder[i]));
```

순서대로 보면:

1. **옆으로만 움직이면 `dirF ≈ 0`** 이다 → `armSwing ≈ 0`.
2. `armSwing` 이 0 이면 9881 의 `Math.max(0,-armSwing)*(.12+…)` 항이 사라져
   **`bend` 가 `.10 − .055 = .045` 에 고정**된다 (걸음 주기 내내. 앞으로 걸으면 `.045~.165` 로 변한다).
3. `bend` 가 `.045` 면 위팔과 아래팔이 거의 일직선이라, 9885 가 만든 손은 어깨에서
   **거의 정확히 `l1+l2` 만큼** 떨어진다.
4. 9893 이 그 손을 다시 IK 로 푸는데, `sheepJoint` 의 `soft` 기본값은 `0` 이라 **하드 클램프**다.
   `along ≈ l1` 이 되어 `side = √(l1² − along²) ≈ 0` — **√ 특이점**이다.
5. 9887~9891 의 저역통과 필터(`follow`, rate 26)가 만드는 아주 작은 길이 변동이
   이 특이점에서 **크게 증폭**되어 팔꿈치가 떤다.

숫자로:

```
aL = R6_ARM[1] * SHEEP_S = 0.60 * 0.70 = 0.42
l1 = aL*0.50 = 0.2100,  l2 = aL*0.36 = 0.1512,  l1+l2 = 0.3612
bend = 0.045 일 때 |어깨→손| = 0.361113   →  IK 여유 = -1.98e-5  (이미 한계를 넘었다)
side(팔꿈치가 옆으로 벌어진 양) = 4.19e-3  ≈ 0
```

## 3. 측정 — 증폭률

**증폭률** = 손이 아주 조금 움직일 때 팔꿈치가 몇 배로 움직이나.
`1.0` 이 정상이고, `5` 를 넘으면 눈에 보인다.

| `bend` | `soft` 없음 (수정 전) | `soft=aL*.05` |
|---|---|---|
| 0.045 ← **옆걸음이 여기 고정** | **15.7×** | 4.8× |
| 0.080 | 11.5× | 2.5× |
| **0.100** ← 수정 후 하한 | 9.5× | **1.9×** |
| 0.120 | 8.0× | 1.5× |
| 0.165 ← 앞걸음 최대 | 5.9× | 0.9× |

읽는 법:

- 옆으로 가면 `bend` 가 `0.045` 에 고정되어 **15.7×** — 확 떤다.
- 앞으로 가면 `bend` 가 `0.165` 까지 올라가 **5.9×** — 덜 보인다.
  **"특히 옆으로 움직이면 그렇다" 가 여기서 나온다.**

### 효과가 없는 수정 (측정으로 기각)

`9871` 의 `rl=si*Math.max(.045,si*rl)` 클램프는 걸음 주기의 52.5% 를 납작하게 만들어
그럴듯한 범인으로 보인다. 하지만 **제거해도 팔꿈치 도약이 `1.094e-3 → 1.099e-3` 으로 그대로다.**
`rl` 은 팔을 옆으로 굴릴 뿐 어깨-손 **거리**를 거의 바꾸지 않아서, 특이점과 무관하다.

→ **교훈: 그럴듯한 가설을 코드로 확인하지 말고 숫자로 확인하라.**

## 4. 적용한 수정

두 줄이다. 둘 다 있어야 한다 (하나만 하면 4.8× 또는 9.5× 에 머문다).

```js
// ① 9893 — IK 에 soft 여유를 준다. 한계 근처에서 갑자기 잠기지 않는다.
-const jointPose=sheepJoint(shoulder,hand,aL*.50,aL*(hasGun?.43:.36),elbow.map((v,i)=>v-shoulder[i]));
+const jointPose=sheepJoint(shoulder,hand,aL*.50,aL*(hasGun?.43:.36),elbow.map((v,i)=>v-shoulder[i]),aL*.05);

// ② 9881 — 이동 보정이 bend 를 기본값 .10 아래로 끌어내리지 못하게 한다.
-const bend=down?.12:.10-mvK*(.055+runK*.020)+mvK*Math.max(0,-armSwing[si>0?0:1])*(.12+runK*.17)
+const bend=down?.12:Math.max(.10,.10-mvK*(.055+runK*.020)+mvK*Math.max(0,-armSwing[si>0?0:1])*(.12+runK*.17))
```

`.10` 은 새로 만든 상수가 아니라 **식이 이미 쓰고 있는 기본값**이다. 이동 보정이 그 아래로
파고들지 못하게만 막는다. `aL*.05 = 0.021` 은 `sheepJoint` 이 이미 지원하는 `soft` 인자다.

**결과: 15.7× → 1.9×** (8.3배 개선). `soft` 는 다리 IK 에서 이미 쓰던 방식이라 새 개념이 아니다.

## 5. 다시 측정하는 법 (브라우저 콘솔에 붙여넣으면 된다)

게임을 띄우고 개발자도구 콘솔에 붙여넣으면 위 표가 다시 나온다.
상수와 `sheepJoint` 은 소스(7708~7714, 9662)에서 그대로 옮긴 것이다.

```js
(() => {
  const sc=0.70, aL=0.60*sc, L1=aL*0.50, L2=aL*0.36;
  function sheepJoint(a,b,l1,l2,pole,soft=0){
    const dx=b[0]-a[0],dy=b[1]-a[1],dz=b[2]-a[2],raw=Math.hypot(dx,dy,dz)||.0001;
    const ux=dx/raw,uy=dy/raw,uz=dz/raw,reach=l1+l2-.0001;
    const limited=soft>0&&raw>reach-soft?reach-soft*Math.exp(-(raw-reach+soft)/soft):Math.min(reach,raw);
    const d=Math.max(Math.abs(l1-l2)+.0001,limited);
    const dot=pole[0]*ux+pole[1]*uy+pole[2]*uz;
    let px=pole[0]-ux*dot,py=pole[1]-uy*dot,pz=pole[2]-uz*dot,pl=Math.hypot(px,py,pz);
    if(pl<.0001){px=uy;py=-ux;pz=0;pl=Math.hypot(px,py);if(pl<.0001){px=1;py=0;pl=1;}}
    const along=(l1*l1+d*d-l2*l2)/(2*d),side=Math.sqrt(Math.max(0,l1*l1-along*along))/pl;
    return {joint:[a[0]+ux*along+px*side,a[1]+uy*along+py*side,a[2]+uz*along+pz*side]};
  }
  const sh=[0,0,0];
  function amp(bend, soft){                       // 증폭률
    const rl=0.045, upper=-bend*.40, fore=bend*.60, sr=Math.sin(rl), cr=Math.cos(rl);
    const R=(o,a,len)=>[o[0]+cr*Math.sin(a)*len, o[1]-cr*Math.cos(a)*len, o[2]+sr*len];
    const e=R(sh,upper,L1), hand=R(e,fore,L2), eps=1e-4, out=[];
    for(const ax of [0,1,2]){
      const h2=hand.slice(); h2[ax]+=eps;
      const p=sheepJoint(sh,hand,L1,L2,e,soft).joint, q=sheepJoint(sh,h2,L1,L2,e,soft).joint;
      out.push(Math.hypot(q[0]-p[0],q[1]-p[1],q[2]-p[2])/eps);
    }
    return Math.max(...out);
  }
  const t={};
  for(const b of [0.045,0.08,0.10,0.12,0.165])
    t['bend='+b]={ 'soft없음':amp(b,0).toFixed(1), 'soft=aL*.05':amp(b,aL*0.05).toFixed(1) };
  return t;
})()
```

## 6. 아직 안 한 것 — 검사 추가

이 버그가 반복된 근본 이유는 **검사가 못 본다**는 것이다. 수정만으로는 또 돌아온다.

넣어야 할 검사 (`t61-arm-jitter-static.mjs` 같은 이름으로):

1. **같은 배우 객체를 유지한 채** 여러 프레임을 돌린다 — `gs.arms` 필터 상태가 살아 있어야 한다.
   (`t58` 의 날개 검사가 `const s=actor(...)` 를 재사용하는 방식이 올바른 본보기다.)
2. 이동 방향을 **옆으로** 준다 (`dirF≈0, dirS≈±1`).
3. 프레임 사이 **팔꿈치 위치 도약**을 재고 상한을 건다.
4. **X축(양옆) 팔 벌어짐**을 단언한다 — 지금은 이걸 보는 검사가 없어서 T 자세가 그냥 통과한다.
5. `bend` 가 주기 내내 한 값에 고정되지 않는지 본다.

이 문서를 쓴 시점에는 작업 컴퓨터에 Node 가 없어 `.mjs` 검사를 **실행해 볼 수 없었다.**
검증하지 못한 검사를 넣으면 CI 가 빨개져 오히려 막히므로 넣지 않았다.
Node 가 있는 곳에서 위 5가지를 구현하고 `check-current.mjs` 에 연결하는 것이 다음 할 일이다.

## 요약

- 원인은 상수 값이 아니라 **IK 특이점**이다. 팔이 거의 펴지면 팔꿈치 위치가 수치적으로 불안정해진다.
- 옆걸음은 `dirF≈0` 때문에 `bend` 가 최솟값에 **고정**되어 주기 내내 특이점에 머문다.
- 눈으로 보고 고치면 계속 빗나간다. **증폭률을 재라.** 1.0 에 가까우면 성공이다.
- 그럴듯한 범인(`9871` 클램프)은 측정해 보면 효과가 없었다. 추측을 측정으로 바꿔라.
