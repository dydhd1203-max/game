# 팔 떨림 — 왜 여러 번 고쳐도 계속 돌아왔나

증상: 움직일 때 팔이 떨리고 아바타가 어긋난다. **특히 옆으로 움직일 때** 심하다.

이 문서는 원인과 **측정 방법**을 남긴다. 다음에 같은 증상이 보이면 **먼저 아래 측정을 돌려라.**
눈으로 보고 상수를 바꾸는 방식으로는 이 버그를 못 잡는다 — 그래서 여러 번 실패했다.

---

## 1. 왜 계속 실패했나 — 검사가 떨림을 볼 수 없다

검사가 120개 넘게 있는데 **팔 떨림을 잡는 검사가 없다.**

| 검사 | 왜 못 잡나 |
|---|---|
| `t58-motion-static` 옆걸음 | **정지한 한 프레임**만 본다. 떨림은 프레임 사이에서 생긴다 |
| `t57-motion-static` 보행 | 매 프레임 배우를 **새로 만든다**. 떨림이 사는 `gs.arms` 필터를 건너뛴다 |
| 팔 부착 | **Z축만** 읽는다. 양옆(X) 벌어짐을 보는 단언이 없다 |
| `t58` run 전환 | `s.gp` 를 `.8` 로 고정해 **다리가 한 걸음도 안 돈 채** 통과한다 |
| `t57-character-view` | 단언이 **부품 수·삼각형 수**뿐이라 T 자세도 통과한다 |

그래서 고칠 때마다 검사는 초록불인데 화면은 그대로였다.
`1155fb6 "관절 떨림을 해결한다"` 이후에도 아래 원인은 코드에 그대로 남아 있었다.

**다만 검사가 전부 무력한 것은 아니다.** `t57-motion-static` 의 'Elbows keep breathing' 과
'gun remains supported by both hands' 는 **잘못된 수정을 실제로 잡아냈다**(4장 참고).
떨림 자체는 못 보지만, 떨림을 고치려다 망가뜨리는 것은 본다.

## 2. 원인 — 팔 IK 가 특이점(singularity) 위에 앉아 있다

```js
// 9854  팔 흔들림을 앞뒤 성분 dirF 로만 만든다
const swing=Math.cos(gait+(si>0?0:Math.PI)); armSwing[si>0?0:1]=swing*dirF;

// 9881  팔꿈치 굽힘 — armSwing 이 0 이면 뒤 항이 통째로 사라진다
const bend=down?.12:.10-mvK*(.055+runK*.020)+mvK*Math.max(0,-armSwing[si>0?0:1])*(.12+runK*.17) + …;

// 9885  굽힘각으로 팔꿈치·손 위치를 만든다
elbow=reach(shoulder,upper,aL*.50); hand=reach(elbow,fore,aL*.36);

// 9893  그 손을 다시 IK 로 푼다 — soft 인자가 없어 하드 클램프였다
const jointPose=sheepJoint(shoulder,hand,aL*.50,aL*(hasGun?.43:.36),elbow.map((v,i)=>v-shoulder[i]));
```

1. `bend` 가 작으면 위팔과 아래팔이 거의 일직선이라, 9885 가 만든 손이 어깨에서
   **거의 정확히 `l1+l2`** 만큼 떨어진다.
2. 9893 이 그 손을 다시 IK 로 푸는데 `soft` 기본값이 `0` 이라 **하드 클램프**다.
   `along ≈ l1` → `side = √(l1²−along²) ≈ 0` — **√ 특이점**.
3. 9887~9891 저역통과 필터(rate 26)의 아주 작은 길이 변동이 여기서 **크게 증폭**된다.

```
aL = R6_ARM[1]*SHEEP_S = 0.42,  l1 = 0.2100,  l2 = 0.1512,  l1+l2 = 0.3612
bend=.045 일 때 |어깨→손| = 0.361113  →  IK 여유 -1.98e-5 (이미 한계를 넘었다)
side = 4.19e-3 ≈ 0
```

**그리고 옆걸음이 특히 나쁜 이유:** 옆으로만 가면 `dirF≈0` → `armSwing≈0` → 9881 의
`max(0,-armSwing)` 항이 사라져 **`bend` 가 `.045` 에 걸음 주기 내내 고정**된다.
앞으로 걸으면 `bend` 가 `.045~.165` 를 오가며 특이점을 **스쳐 지나가는데**,
옆으로 가면 특이점에 **눌러앉는다.**

## 3. 측정

**증폭률** = 손이 아주 조금 움직일 때 팔꿈치가 몇 배로 움직이나. `1.0` 정상, `5` 이상이면 눈에 보인다.

### 걸음 주기 전체에 걸쳐

| | `bend` 범위 | 최악 | **평균** | 5× 넘는 시간 |
|---|---|---|---|---|
| 수정 전 · 옆걸음 | **0.045 고정** | 15.7× | 15.7× | **100%** |
| 수정 전 · 앞걸음 | 0.045~0.165 | 17.0× | **12.2×** | 100% |
| **수정 후 (양쪽 다)** | 0.045~0.165 | **4.8×** | **3.3×** | **0%** |

**앞걸음도 원래 나빴다.** 다만 옆걸음은 최솟값에 고정되어 내내 나쁘고, 앞걸음은 오르내려서
덜 보였을 뿐이다. `soft` 는 두 방향 모두를 고친다.

### `bend` 값별

| `bend` | `soft` 없음 | `soft=aL*.05` |
|---|---|---|
| 0.045 | 15.7× | 4.8× |
| 0.100 | 9.5× | 1.9× |
| 0.165 | 5.9× | 0.9× |

## 4. 고친 것

```js
// ① 9893 — 팔 IK 에 soft 여유. 단 총을 들 때는 주지 않는다.
-const jointPose=sheepJoint(shoulder,hand,aL*.50,aL*(hasGun?.43:.36),elbow.map((v,i)=>v-shoulder[i]));
+const jointPose=sheepJoint(shoulder,hand,aL*.50,aL*(hasGun?.43:.36),elbow.map((v,i)=>v-shoulder[i]),hasGun?0:aL*.05);

// ② 9854 — 옆으로 갈 때 armSwing 이 0 으로 죽지 않게 한다.
-else { const swing=Math.cos(gait+(si>0?0:Math.PI));armSwing[si>0?0:1]=swing*dirF;
+else { const swing=Math.cos(gait+(si>0?0:Math.PI));armSwing[si>0?0:1]=swing*(dirF<0?-1:1)*Math.hypot(dirF,dirS);
```

`moveFX/moveFZ` 는 정규화된 이동 방향이고 `fx,fz`·`rx,rz` 는 직교 몸 축이므로
움직이는 동안 `hypot(dirF,dirS) = 1` 이다. 따라서 ② 는

- 앞으로(`dirF=1,dirS=0`) → `swing*1` — **수정 전과 글자 그대로 같은 값**
- 뒤로(`dirF=-1`) → `-swing` — **같음**
- 옆으로(`dirF=0,dirS=±1`) → `swing` — **0 으로 죽던 것이 살아난다**

`armSwing` 은 9854 에서 만들어 9881 에서만 읽는다. 다른 소비처가 없어 부작용이 없다.

### ⚠️ 먼저 시도했다가 CI 에 걸린 방법 — 따라하지 마라

처음에는 `bend` 에 하한을 두었다: `Math.max(.10, .10-mvK*(.055+…)+…)`.
증폭률은 `1.9×` 로 좋아졌지만 **`t57-motion-static` 검사 두 개를 깼다.**

```
FAIL Elbows keep breathing through the gait instead of holding one folded angle
     walk:[0.4257, 0.4334]   기준: walk 폭 > .05, run 폭 > .12
FAIL Seven-part gun remains supported by both hands through recoil
     support:0.1042          기준: < .10
```

- **하한은 팔꿈치가 "숨쉬는" 폭을 절반으로 줄인다.** R6 리그가 지키려는 성질을 직접 깬다.
- **`soft` 를 총에도 주면 받침손이 총에 못 닿는다.** 그래서 `hasGun?0:` 으로 갈랐다.

교훈: 증폭률만 보고 고르면 다른 성질을 깬다. **`t57-motion-static` 을 같이 봐라.**

### 측정으로 기각한 가설

`9871` 의 `rl=si*Math.max(.045,si*rl)` 클램프는 걸음 주기의 52.5% 를 납작하게 만들어
그럴듯한 범인으로 보인다. 하지만 **제거해도 팔꿈치 도약이 `1.094e-3 → 1.099e-3` 으로 그대로였다.**
`rl` 은 팔을 옆으로 굴릴 뿐 어깨-손 **거리**를 거의 바꾸지 않아 특이점과 무관하다. 건드리지 않았다.

## 5. 다시 측정하는 법 (브라우저 콘솔에 붙여넣으면 된다)

상수와 `sheepJoint` 은 소스(7708~7714, 9662)에서 그대로 옮긴 것이다. 게임을 띄울 필요도 없다.

```js
(() => {
  const sc=0.70, aL=0.60*sc, L1=aL*0.50, L2=aL*0.36;
  function sheepJoint(a,b,l1,l2,pole,soft=0){
    const dx=b[0]-a[0],dy=b[1]-a[1],dz=b[2]-a[2],raw=Math.hypot(dx,dy,dz)||.0001;
    const ux=dx/raw,uy=dy/raw,uz=dz/raw,reach=l1+l2-.0001;
    const limited=soft>0&&raw>reach-soft?reach-soft*Math.exp(-(raw-reach+soft)/soft):Math.min(reach,raw);
    const d=Math.max(Math.abs(l1-l2)+.0001,limited);
    const dot=pole[0]*ux+pole[1]*uy+pole[2]*uz;
    let px=pole[0]-ux*dot,py=pole[1]-uy*dot,pz=pole[2]-uz*dot,pl=Math.hypot(px,py,pz);
    if(pl<.0001){px=uy;py=-ux;pz=0;pl=Math.hypot(px,py);if(pl<.0001){px=1;py=0;pl=1;}}
    const along=(l1*l1+d*d-l2*l2)/(2*d),side=Math.sqrt(Math.max(0,l1*l1-along*along))/pl;
    return {joint:[a[0]+ux*along+px*side,a[1]+uy*along+py*side,a[2]+uz*along+pz*side]};
  }
  const sh=[0,0,0];
  const amp=(bend,soft)=>{
    const rl=0.045, upper=-bend*.40, fore=bend*.60, sr=Math.sin(rl), cr=Math.cos(rl);
    const R=(o,a,len)=>[o[0]+cr*Math.sin(a)*len, o[1]-cr*Math.cos(a)*len, o[2]+sr*len];
    const e=R(sh,upper,L1), hand=R(e,fore,L2), eps=1e-4, out=[];
    for(const ax of [0,1,2]){ const h2=hand.slice(); h2[ax]+=eps;
      const p=sheepJoint(sh,hand,L1,L2,e,soft).joint, q=sheepJoint(sh,h2,L1,L2,e,soft).joint;
      out.push(Math.hypot(q[0]-p[0],q[1]-p[1],q[2]-p[2])/eps); }
    return Math.max(...out);
  };
  const cycle=(bendOf,soft)=>{ const a=[],b=[];
    for(let i=0;i<360;i++){ const s=Math.cos(i/360*Math.PI*2), bend=bendOf(s); b.push(bend); a.push(amp(bend,soft)); }
    return { 'bend': Math.min(...b).toFixed(3)+'~'+Math.max(...b).toFixed(3),
             '최악': Math.max(...a).toFixed(1)+'×',
             '평균': (a.reduce((x,v)=>x+v,0)/360).toFixed(1)+'×',
             '5×초과': (a.filter(v=>v>5).length/360*100).toFixed(0)+'%' }; };
  return {
    '수정전 옆걸음': cycle(()=>.045, 0),                        // armSwing 이 죽어 고정
    '수정전 앞걸음': cycle(s=>.045+Math.max(0,-s)*.12, 0),
    '수정후':        cycle(s=>.045+Math.max(0,-s)*.12, aL*0.05),
  };
})()
```

## 6. 아직 안 한 것 — 떨림 검사 추가

이 버그가 반복된 근본 이유는 **검사가 못 본다**는 것이다. 수정만으로는 또 돌아온다.

넣어야 할 검사 (`t62-arm-jitter-static.mjs` 같은 이름으로):

1. **같은 배우 객체를 유지한 채** 여러 프레임을 돌린다 — `gs.arms` 필터 상태가 살아 있어야 한다.
   (`t58` 의 날개 검사가 `const s=actor(...)` 를 재사용하는 방식이 올바른 본보기다.)
2. 이동 방향을 **옆으로** 준다 (`dirF≈0, dirS≈±1`).
3. 프레임 사이 **팔꿈치 위치 도약**을 재고 상한을 건다.
4. **X축(양옆) 팔 벌어짐**을 단언한다 — 지금은 T 자세가 그냥 통과한다.
5. `bend` 가 주기 내내 한 값에 고정되지 않는지 본다.

이 문서를 쓴 시점에는 작업 컴퓨터에 Node 가 없어 `.mjs` 검사를 **실행해 볼 수 없었다.**
검증하지 못한 검사를 넣으면 CI 가 빨개져 오히려 막히므로 넣지 않았다.

## 요약

- 원인은 상수 값이 아니라 **IK 특이점**이다. 팔이 거의 펴지면 팔꿈치 위치가 수치적으로 불안정해진다.
- 옆걸음은 `dirF≈0` 때문에 `bend` 가 최솟값에 **고정**되어 주기 내내 특이점에 머문다. 앞걸음은 스쳐 지나간다.
- 눈으로 보고 고치면 계속 빗나간다. **증폭률을 재라.** 주기 평균이 5× 아래면 성공이다.
- 그럴듯한 범인(`9871` 클램프)은 측정해 보면 효과가 없었다. **추측을 측정으로 바꿔라.**
- 증폭률만 보고 고르면 다른 성질을 깬다. **`t57-motion-static` 을 같이 봐라.**
