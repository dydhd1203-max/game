# 시즌1 코드를 재사용하는 개발 계획

2026-10-13 · 재사용 계획 및 s2-001 이식 기록

실제 첫 테스트판에서는 시즌1 사람 캐릭터의 모델·동작·꾸미기를 `src/avatar-season1.mjs`에 직접 이식했다. 재생성 도구는 `tools/extract-season1-avatar.mjs`다. 원본의 인스턴스 행렬·색·지오메트리·재질과 비교한다. 오디오는 `src/audio.mjs`로 이식하고, 월드는 기존 구역별 인스턴싱·공유 재질·업로드 범위 기법을 `src/scene.mjs`에 적용했다. 시즌1 타워 모델과 106차 압축기 전체를 그대로 가져왔다고 주장하지 않으며, 새 단순 원정 타워를 공유 인스턴스로 그린다. 실제 범위는 [구현·검수 기록](s2-001-구현검수.md)에 기록한다.

시즌1에서 검증한 조작·외형·렌더링·소리 기반을 활용하면 새로 만들고 검증할 양을 줄일 수 있다. 필요한 함수만 찾아 읽고 이식 위치를 기록하면 반복 분석에 쓰는 토큰도 줄일 수 있다. 다만 하나의 큰 HTML에 게임 상태 의존성이 섞여 있어, 파일 전체 복사만으로 독립적인 시즌2가 완성되지는 않는다. 절감률은 아직 산정하지 않는다.

## 기준과 보존

- 재사용 기준: 시즌1 **106차**, 커밋 `89da73bebdb360592a80bbc9be76612be6734b70`.
- 원본: [`클로드/index.html`](../클로드/index.html). 배포본: [`클로드/배포용/index.html`](../클로드/배포용/index.html).
- 두 파일의 SHA-256: `91c2c21654161390e37d84b70c96d5736f56f07de0add7fea950a0ab15d1173f`.
- 시즌1을 수정해 공통 라이브러리로 빼지 않는다. 선정한 코드와 필요한 자산을 시즌2 모듈로 가져오고 기준 커밋·원래 함수·수정 이유를 기록한다. 실행 중 시즌1 HTML을 불러오는 구조도 쓰지 않는다.
- 후속 시즌1 수정은 자동 반영하지 않고, 필요한 개선만 검토해 이식한다. 복사한 코드의 별도 유지보수 비용도 고려한다.

## 확인한 코드와 재사용 방식

아래 이름은 기준 버전의 검색 기준점이다. 모든 의존성을 이미 분리했거나 시즌2에서 동작 검증했다는 뜻은 아니다.

| 대상 | 원본 검색 기준점 | 가져올 것과 바꿀 것 |
|---|---|---|
| 캐릭터·이동·기본 전투 | `drawSheep`, `actorCullPrep`, `fireWeapon` | 익숙한 조작·외형·기본 공격을 출발점으로 사용. 게임 상태·충돌·피격 대상은 원정 상태에 연결 |
| 타워 외형·묶음 렌더링 | `blocksOf`, `rebuildStru`, `struRenderBuild`, `struRenderSync` | 모델·재질 공유, 구역별 시야 판정, 원래 부품 순서와 변경분 업로드 보존. 배치된 모듈만 현장 구조물로 연결 |
| 타워 조준·피해 표현 | `tickBuildingGuns`, `struGunBounds`, `tintStru` | 회전·반동 범위·피해 색 처리 재사용. 포장 중 사격 금지·재설치·파괴 상태에 맞춰 갱신 |
| 지형·장식·길찾기 | `genTerrain`, `castleTerrainAt` 및 104차 통행 마스크 | 재질·반복 모델·캐시 기법은 후보. 옛 성곽 지형·수정 중심 길찾기는 새 숲 배치·목표에 맞게 설계 |
| 마을·숲 환경 렌더링 | `bpush`, `bbuild`, `bankCull`, `bankLOD`, `geoMerge` | 공유 재질·구역별 묶음·거리별 세부 묘사 기법 활용. 새 지도에서 장식과 이동/설치 가능 공간을 구분 |
| 타워 발사 효과 | `towerAttack`, `towerAttackTick`, `towerFxShot`, `towerFxTick` | 기존 효과 풀과 표시를 활용. 호스트 피해 판정과 시각 효과를 분리하고 새 조합 규칙을 적중 시점에 연결 |
| 소리 재생 기반 | `busIn`, `sfxAt`, `voxOk`, `nodeEnd`, `bgmSwitch`, `sndGc` | 효과음·음악·환경음 분리, 거리 처리, 발음 상한, 부드러운 전환·정리 재사용. 곡·음색은 새 장면에서 듣고 결정 |
| 소리 장면 연결 | `bgmSceneNow`, `bgmLoop`, `sndLoad`, `sndSave` | 낮·밤·수정 위기를 마을·탐색·교전·보스·귀환으로 교체. `sndBgm` 등 저장 키도 `zns2:`로 분리 |
| UI·성능 기록 | `recTick`, `recText`, 105차 교사 표 갱신 캐시 | 동일한 UI 재생성 방지 기법과 JS/GPU·콜·삼각형 측정 활용. 밤 한정 기록은 임무·지역 단위로 바꾸고 전체 프레임 시간 수집 추가 |
| 방·재접속 | `DB_ROOT`, 기존 호스트/참가자 처리 | 검증한 연결 처리 패턴 참고. 별도 방·저장 경로와 모듈·보상 상태를 설계하고 늦은 입장·복구 재검증 |

특히 타워의 추가·삭제는 화면뿐 아니라 점유 칸·충돌·길찾기도 바꾼다. 포장 때 화면만 숨기거나 설치 때 새 ID를 발급하면 안 된다. 영구 모듈 상태와 현장 객체를 연결하는 계층을 새로 만든다. 실시간 그림자를 켠 경우의 화면 밖 그림자 보존도 이식 검수에 포함한다.

## 시즌2에서 새로 만드는 부분

1. 마을·사냥터·설치 지대의 배치와 장면별 연출. 우선순위는 [맵·소리·성능](맵-소리-성능.md)을 따른다.
2. 타워 모듈의 포장·운반·설치·회수, 고유 ID 보존과 동시 요청 처리.
3. 서리 표식→화살의 쇄빙 등 적중 순서 기반 조합, 재귀 발동 방지와 보스 제어 제한.
4. 원정 목표·봉화 개방·주민 구조·보스 예고/빈틈·마을 귀환.
5. 공동 경제·임무 체크포인트·실패 복구·시즌2 저장 및 통신 규약.

기존 거대 맵과 방어 게임 전체를 활성화한 채 새 콘텐츠만 덧붙이지 않는다. 첫 원정에 필요한 기능과 자산부터 가져와 성능과 의존성을 확인한다.

## 반복 작업을 줄이는 방법과 검증

- 위 함수 이름으로 필요한 구간만 검색한다. 전체 HTML·과거 작업 기록을 매번 다시 읽지 않는다.
- 구현 시 이 문서에 `원본 함수 → 시즌2 파일 → 변경점 → 검사` 표를 추가한다. 현재 적용 범위는 아래 s2-004 이식 표와 각 구현·검수 기록을 따른다.
- 공통 엔진을 크게 새로 만드는 작업보다 첫 마을·숲 원정에 필요한 작은 단위부터 이식한다. 원본 비교 장면과 같은 입력을 이용해 이식 자체의 변경을 찾는다.
- 타워는 [106차 구조물 검사](../깃허브에올릴것/검사/t106-structure-cull.mjs)와 [화면 비교](../깃허브에올릴것/검사/t106-structure-view.mjs)의 검증 항목을 옮긴다. 행렬·색·회전 경계·시야 제외·그리기 호출을 확인한다.
- 소리는 [66차 소리 검사](../깃허브에올릴것/검사/t66-sound-static.mjs)를 참고해 전환·음량·노드 정리를 검사하고 실제 샘플을 듣는다. 기존 검사의 원본 추출·전역 상태 가정은 시즌2에 맞게 바꿔야 한다.
- 이후 보완된 [79차 배경음 검사](../깃허브에올릴것/검사/t79-bgm-static.mjs)와 [타워 소리 검사](../깃허브에올릴것/검사/t79-tower-audio-static.mjs)도 확인해 이식 시 이전 개선을 누락하지 않는다.
- 기존 코드 재사용만으로 통신·저장·성능 검증을 생략하지 않는다. 시즌2의 포장/재설치·지역 이동·21명 전투에서 다시 확인한다.

위 표의 모든 후보를 이식한 것은 아니다. 첫 보스 테스트판의 코드·화면·오디오 검증과 실제 교실 FPS 검증을 구분한다. 실제 기기 FPS 개선은 아직 입증하지 않았다.


## s2-004 실제 조작·카메라 복원

기존 s2-001~003은 캐릭터 그리기 함수를 복사했지만 입력·이동 상태·카메라는 간소화한 시즌2 구현이었다. 이제 실제 플레이 상태를 원본 동작에 연결한다.

| 원본 | 시즌2 | 확인 |
|---|---|---|
| `updPlayer`, `sprintMul`, `lobbyMove78`, `sheepGaitStep` | `src/locomotion-season1.mjs`, `sim.mjs`, `app.mjs` | 원본 함수를 실행해 프레임별 위치·속도·점프·기력·착지 비교 |
| 일반 카메라 / `AIM_VIEW` / `fovTick` | `src/camera-season1.mjs`, `scene.mjs` | 원본 코드 260프레임의 위치·회전·FOV 비교 |
| `friendSeg`, `friendLerp` | `src/presentation-season1.mjs` | 원본 8점 버퍼를 그대로 추출, 지연된 원격 이동 재생 비교 |
| `drawSheep`와 모션 입력 | `src/avatar-season1.mjs` | 실제 시뮬레이션 240프레임을 렌더 API에 넣어 원본 행렬 비교 |

게스트 로컬 이동은 `prediction-season1.mjs`에서 같은 충돌·이동 함수로 예측하고 호스트 스냅샷과 보정한다. 공격·보상·타워·피해는 호스트만 판정한다. 입력 20Hz, 스냅샷 10Hz를 유지하며 짧은 Space 입력은 순번으로 전달한다.

원본의 성곽 계단·경주·비행·관전 및 총기 전투 전체는 이번 범위가 아니다. 건물 충돌은 시즌2 부지와 높이에 맞춘다. 상세 화면과 성능·미확인 범위는 [s2-004 검수](s2-004-모션카메라검수.md)에 기록한다.
