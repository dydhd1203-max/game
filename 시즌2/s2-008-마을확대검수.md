# s2-008 마을 확대·자연 조형물·공간 압축 검수

2026-10-14 · 시즌2 테스트판. 사용자 추가 요청에 따라 건물 주위의 원형 돌 테두리를 제거했으며, 마을 바깥 경계 바위와 건물 자체 기초·돌 화로는 유지한다. 아래 구현과 실제 검수 범위를 구분한다.

## 요구와 구현

| 요구 | 구현 |
| --- | --- |
| 작업장의 미술 수준을 나머지 마을로 확대 | 기존 작업장 GLB는 보존하고 수레·시장·집결소·정비소·보급소를 3D Jutsu/Blender GLB로 제작. 수레의 천 지붕·살대·적재함, 시장의 천막·진열, 집결소의 벤치·게시판, 정비소의 두꺼운 지붕·공구, 보급소의 선반·자루를 정적 마을 묶음에 포함 |

| 기존 진행 보존 | BUILD/RELEASE s2-008. 온라인은 서로 같은 지도 버전만 연결. 로컬 저장은 008→007→구 키 순으로 읽으며 복제본의 충돌 위치를 복구하고 원본 저장은 보존 |

`src/content.mjs`가 조형물과 충돌의 공통 좌표를 정의한다. `src/village-a.mjs`는 모델·포장·화단, `src/village-nature.mjs`는 자연 조형물, `src/scene.mjs`는 렌더링·카메라 연계를 담당한다. 새 모델의 GLB와 변환기는 `assets/`, `tools/village-jutsu/`, `tools/import-village-glb.mjs`에 보존한다.

현재 마을 구조물은 미술용이며 새 RPG 직업·상점 거래·층별 포탈·다섯 던전·합동 보스는 이번 구현 범위가 아니다. 공용 타워 기능을 되살리지 않았다. 기존 첫 보스 체험 진행은 유지한다.

## 검수 기록

- [3D Jutsu 원본 revision 5](https://higgsfield.ai/3d-jutsu/9874ebe5-dc9e-4c9c-b1dc-4ac21261971a), [제작·재현 절차](tools/village-jutsu/README.md), [GLB별 해시·치수](assets/village-buildings.manifest.json), [최종 모델 렌더 검수](검수/s2-008/village-assets/report.json). 다섯 모델 합계 84,406삼각형. 전체 및 다섯 근접 렌더를 직접 열어 천 두께·지붕·바퀴·간판·등걸이의 접촉을 확인했다. 원격 렌더 URL의 픽셀은 열지 못해 정확한 최종 GLB를 로컬 Blender로 렌더링해 검수했다.
- Node 테스트 파일 12개와 별도 네이티브 Web Audio 검사가 통과했다. 최초 `npm test` 중 오디오 파일만 샌드박스의 루프백 `listen EPERM`으로 실행되지 않아 네트워크가 허용된 루프백에서 다시 실행했다. 최종 GLB 교체 뒤 모델 변환·실제 정점·기존 작업장 보존 검사 8개를 다시 통과했다.
- 21명 출발열의 중앙 통행, 각 건물·줄어든 경계의 충돌, s2-007의 경계 밖/건물 안 21명 저장 복구와 원본 불변을 Node에서 확인했다. 숲 z < -18의 기존 자연물 904개 생성 인자와 최종 난수 상태는 변경 전과 동일하다.

### 실제 게임 화면·입력

[전체 실제 조작 보고서](검수/s2-008/village/current/report.json)는 9개 검수 항목·23장의 화면을 남긴다. 실제 WASD/Shift/Space/우클릭으로 여섯 시설의 측면·근접, 중앙 길, 북쪽 입구, 남쪽 경계를 이동했다. 달리기 기력 변화·공중제비·착지 자세와 먼지·카메라 반응을 직접 확인했다. 21명 생성 위치는 모두 걸을 수 있고 최소 간격은 1.6m다. 실제 불러오기/저장 버튼으로 007의 21명을 안전하게 복구하고 원본 바이트 보존·008 키 분리를 확인했다. 마을/숲/보스 5회 전환에서 GPU geometry 41→41, texture 6→6으로 누적되지 않았다. 커서 잠금과 브라우저 오류도 없었다.

전체 동선 검수 파일은 접촉부 보완 직전 HTML(`ce2c8757…55d3c84`)이다. 이후 간판·등걸이 연결 부위 168삼각형만 보강했으며 입력·카메라·충돌·저장 코드는 바꾸지 않았다. 접촉부 보완 HTML(`6421ffed…174f9aa2`)은 [추가 보고서](검수/s2-008/village/final-contact/report.json)의 4항목·12장으로 네 시설·출발·남쪽 풍경을 재검수했다. 이후 사용자 요청으로 여섯 시설의 돌 테두리만 제거했으며, 해당 판은 최종 출발·정비소/작업장 사진과 아래 성능 측정으로 확인한다. 충돌·입력·카메라 규칙은 동일하다.

[시각 검토 기록](검수/s2-008/village/visual-review.md)에 변경 전후 직접 연 화면과 판단을 남긴다. 후방 건물에 가까운 측면 시점에서는 원본 카메라가 벽을 피하며 몸을 숨길 수 있다. 기본 출발과 시설 근접 화면은 정상 3인칭으로 확인했고, 최종 추가 측면 검수는 중앙 길에서 걸어 접근한다.

### 최종 렌더링 성능

[성능 측정 원본](검수/s2-008/performance/performance.json)은 최종 HTML(`119c8742…38769d3`)로 통과했으며 예산 초과·브라우저 오류가 없다. 1366×768, DPR 1, 그리기 배율 .85(1161×652), MSAA 4, 시즌1 기본 카메라와 합성 캐릭터 21명을 동일하게 적용했다.

마을의 그리기 호출은 약 55%, 삼각형은 약 44% 감소했다. FPS 향상률을 뜻하지 않는다. 시즌2의 세 장면 모두 반복 측정 동안 geometry·texture 증가가 0이었다. 전투 비교의 타워 30개·적 40개는 성능 부하용 합성 상태이며 공용 타워 기능을 다시 넣은 것이 아니다. 고정 성능 배치와 실제 21명 출발 배치는 별도 검사다.

검사는 `PW_MODULE=/opt/codex/runtimes/cua/lib/node_modules/playwright/index.mjs PW_EXECUTABLE_PATH=/usr/bin/chromium S2_PERF_OUTPUT=검수/s2-008/performance node tests/performance.mjs`로 실행했다. 소프트웨어 WebGL과 3회×120프레임의 CPU 작업량 검사는 실제 노트북 FPS·다중 기기 통신 측정을 대체하지 않는다.

돌 테두리를 제거한 최종 판은 [실제 입력 재검수 4항목·2장](검수/s2-008/village/final-no-curbs/report.json)을 통과했다. [기본 출발 화면](검수/s2-008/village/final-no-curbs/02-village-default-spawn.png)과 [대장간·작업장 근접 화면](검수/s2-008/village/final-no-curbs/03-smith-workshop-no-stone-curbs.png)을 직접 열어 돌 테두리 제거와 건물·식재 유지, 기존 밝기·MSAA를 확인했다. 공통 식재 함수에서 여섯 곳의 돌 216개를 제거했다.

## 적용 범위와 남은 실제 기기 확인

브라우저 검사는 숨김 Chromium/SwiftShader에서 실행한다. 21명은 같은 화면에 배치한 합성 상태이며, 실제 노트북 FPS나 21대의 실시간 통신 성능 측정으로 해석하지 않는다. 기존 사용자 노트북에서의 시즌1 체감 성능을 최종 기준으로 삼는다.

새 파일은 저장·통신 버전이 s2-008이므로 교사와 학생 모두 같은 판을 사용해야 한다. 구 버전 온라인 방에는 새 방 코드가 필요하다. 다른 방 코드의 로컬 진행을 자동으로 가져오지는 않는다.

GitHub 작업 브랜치/PR은 배포 완료가 아니다. 시즌1과 배포 설정은 수정하지 않는다. 이 작업 환경에서는 Windows 바탕화면에 접근할 수 없어 해당 폴더 복사는 수행하지 않는다.
