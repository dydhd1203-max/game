# s2-009 자연 조형물 검수

2026-10-14 · PR #117의 s2-008을 기준으로 한 시즌2 미술 수정. 사용자가 지적한 공 모양 나무, 바위 위 초록색 판, 일정하게 줄지은 둥근 조약돌을 마을과 연결 숲에서 함께 수정한다.

## 구현

| 사용자 요구 | 실제 변경 |
| --- | --- |
| 나무가 동그란 덩어리로 보이지 않게 | 기울어진 줄기·갈라진 가지와 불규칙한 잎 덩어리. 잎의 높이·크기·회전을 달리하고 가지 사이에 하늘이 보이도록 배치 |
| 바위 위의 초록 판 제거 | 바위와 분리된 녹색 덮개를 삭제. 깨진 돌 표면의 정점 색으로 이끼를 표현하고 틈 주변에 낮은 고사리 배치 |
| 자연물을 자연스럽게 쌓고 배치 | 일부가 땅에 묻힌 큰 돌 옆에 크기가 다른 파편을 모으고, 각 군집의 깊이·간격·회전을 달리함. 일정한 조약돌·말뚝 줄 제거 |
| 시즌1 기준 성능 유지 | 불투명 정적 기하·공유 재질·공간별 묶음 사용. 추가 조명·그림자 패스·텍스처·프레임별 자연물 애니메이션 없음 |

`src/nature-geometry.mjs`는 잎·깨진 바위·줄기·고사리의 공유 기하다. `src/village-nature.mjs`는 마을과 남쪽 언덕을, `src/forest-nature.mjs`와 `src/scene.mjs`는 숲·보스 구역의 자연물 외형을 처리한다. 건물 모델, 마을 크기, 캐릭터, 조작, 밝기·그리기 배율·안티앨리어싱은 그대로다.

숲의 원래 나무 위치와 난수 소비 순서는 보존하며 외형만 바꾼다. 마을의 카메라 장애물 12개는 변경 전과 정확히 같다. 숲 바위 4개의 몸높이 외형은 기존 반경 3m의 충돌에 맞는지 확인했다. 남쪽 언덕의 나무 21개는 바위 표면과 연결된다.

## 버전·기존 기능 보존

실행판 표시는 `s2-009`, 저장·통신 규격 `BUILD`는 `s2-008`이다. 충돌·전투·진행 규칙을 바꾸지 않아 s2-008 방·저장을 계속 사용한다. 시즌1과 퀴즈나라·배포 설정은 수정하지 않는다.

[소스 확인](검수/s2-009/source-checks.json)에 시즌1 원본/배포본, 기존 작업장, 시뮬레이션·캐릭터·카메라·저장·통신 코드가 기준판과 동일함을 기록했다. 이동·저장·카메라·모션·모델 검사 파일 6개가 통과했다. [기하 확인](검수/s2-009/geometry-checks.json)은 유한 정점·단위 법선·퇴화 면 없음·고사리 앞면 방향과 전체 콘텐츠 상수/함수의 불변을 검사한다.

## 실제 화면 검토

`tests/nature-browser.mjs`는 실제 입장/시작 버튼과 WASD·우클릭으로 출발→마을 북쪽→숲 입구→왼쪽 경계→첫 바위에 접근한다. 조망 카메라·순간이동·캐릭터 상태 조작·숨긴 HUD를 사용하지 않는다. 숲의 전투도 정상 진행해 좀비가 일부 화면에 들어온다.

- [변경 전](검수/s2-009/nature/before/report.json): 기준 HTML `119c8742…38769d3`, 5항목·5장 통과. 둥근 수관·일렬 조약돌·초록 덮개를 직접 확인했다.
- [중간 시도](검수/s2-009/nature/after1/report.json): 조작 검사는 통과했지만 잎이 납작한 선반처럼 보여 미술 검수에서 보완했다. 이 화면을 최종 결과로 사용하지 않는다.
- [최종 화면](검수/s2-009/nature/after2/report.json): 최종 HTML `e1d7b012…2163753`, 4,653,314바이트, 5항목·5장 통과, 브라우저 오류 0. 잎은 삼각형 수를 늘리지 않고 하부를 좁히고 중심을 높여 두께를 보강했다. [마을 북쪽 나무·경계](검수/s2-009/nature/after2/02-village-north-trees.png)와 [첫 바위 표면](검수/s2-009/nature/after2/05-first-rock-surface.png)을 직접 열어 세 요구의 반영을 확인했다. 모든 사진에서 .85 배율·MSAA 4·AgX 1.28·기존 카메라를 검사했다. 04번은 카메라 앞 좀비가 일부 자연물을 가리므로 보조 사진이다.

[상세 시각 검토](검수/s2-009/nature/visual-review.md)에서 변경 전·거절한 중간 형태·최종 형태를 구분한다. 실제 노트북 화면에서의 최종 미술 선호와 FPS는 사용자의 테스트가 필요하다.

## 정적 기하와 전체 프레임 성능

마을 자연물은 이전과 같은 4개 정적 묶음+2개 인스턴스 묶음이며, 삼각형은 34,756→26,308개다. 이는 자연물만의 수치이며 전체 프레임·실제 FPS가 아니다. 숲은 여러 종류의 기하를 32m 공간별 정적 묶음으로 합친다. 숲 전체 자연물은 나무 82그루·바위 4곳·경계 군집 50곳, 101,996삼각형·20묶음·정점 버퍼 11,015,568바이트다. 합치면서 개별 그리기 호출을 줄이는 대신 정점 버퍼를 사용하는 방식이며, 프레임마다 재생성하지 않는다.

[최종 성능 보고서](검수/s2-009/performance/performance.json)는 시즌1·고정한 s2-008 원본·s2-009를 새로 측정했으며, 예산 초과와 브라우저 오류가 없다. 모두 1366×768·DPR1·그리기 배율 .85·MSAA4, 기본 FOV70·pitch -.22·zoom3.2 카메라와 같은 합성 캐릭터 21명을 사용한다.

| 장면 | 시즌1 호출 / 삼각형 | s2-008 호출 / 삼각형 | s2-009 호출 / 삼각형 |
| --- | ---: | ---: | ---: |
| 마을 | 246 / 824,608 | 110 / 459,962 | 83 / 417,934 |
| 숲 전투 | 330 / 1,126,903 | 87 / 374,768 | 70 / 355,078 |
| 첫 보스 | 직접 비교 장면 없음 | 72 / 352,310 | 63 / 342,160 |

세 장면 모두 이전판보다 제출 작업량이 줄었다. 마을은 호출 약 25%·삼각형 약 9% 감소이며 FPS 향상률은 아니다. 새 정적 공간 묶음 때문에 마을의 geometry 수는 36→55개지만 프레임 호출은 줄었다. 시즌2의 각 장면에서 반복 측정 후 geometry·texture 증가는 0이다.

CPU 표본은 혼재한다. 이전판→현재판의 평균은 마을 0.63→0.71ms, 숲 전투 1.17→1.48ms, 첫 보스 1.18→1.17ms였고, 숲 전투 p95는 2.0→4.6ms다. 이 3회×120프레임 검사는 WebGL 제출·시뮬레이션·통신을 제외한 CPU 작업량이며, 일부 상승이 있어 전체 FPS 개선으로 보고하지 않는다. 숨김 Chromium/SwiftShader 결과는 실제 노트북 FPS 또는 21대 실접속 통신 성능을 대신하지 않는다.

재현: `S2_PERF_VARIANTS=s1,previous,current S2_PERF_PREVIOUS_ROOT=<7174fc7 저장소 스냅샷> S2_PERF_OUTPUT=검수/s2-009/performance node tests/performance.mjs`에 기존 PW_MODULE/PW_EXECUTABLE_PATH 설정을 사용한다. 전투 부하의 타워 30개·적 40개는 비교용 합성 fixture이며 공용 타워 플레이 기능이 아니다. 고정 성능 배치는 실제 통행·출발열 검수와 구분한다.

## 적용

GitHub PR은 테스트판이며 머지·공개 배포 완료와 구분한다. 이 클라우드 환경에서는 사용자의 Windows 바탕화면에 접근할 수 없어 로컬 배포 폴더 복사는 수행하지 않는다.
