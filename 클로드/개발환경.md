마지막 갱신: 2026-09-11 (교실 기기가 크롬북 → 노트북으로 바뀜)

이 파일은 "다른 컴퓨터에서 이어서 하려면 뭘 해야 하나"만 다룬다.
작업 내용 자체는 `진행상황.md` 를 봐라.

## 1. 이 저장소는 GitHub 에 올라가 있다

주소: https://github.com/dydhd1203-max/game

전에는 학교 컴퓨터 한 대에만 있었다. 그 컴퓨터가 없으면 작업도 없었다.
이제는 GitHub 에 있으니 아무 컴퓨터에서나 받아서 이어 하면 된다.

**처음 쓰는 컴퓨터에서 (한 번만):**

    git clone https://github.com/dydhd1203-max/game.git
    cd game

**그 다음부터는 — 이 두 줄이 전부다:**

    git pull            <- 시작할 때. 다른 데서 한 작업을 받아온다
    git add -A && git commit -m "무엇을 고쳤는지" && git push
                        <- 끝낼 때. 지금 작업을 올린다

**컴퓨터를 옮기기 전에 `git push` 를 꼭 하고 자리를 떠라.**
안 하면 그 컴퓨터에만 남는다. 이번에 겪은 게 딱 그거였다.

## 2. 게임 실행하는 법

**`index.html` 을 그냥 더블클릭하면 된다.** 로컬 서버 필요 없다.

- 이건 실제로 확인한 사실이다. `type="module"` 스크립트가 있으면 보통
  `file://` 에서 막히는데, 그건 **모듈이 옆에 있는 로컬 파일을 부를 때** 얘기다.
  이 게임의 importmap 은 `three` 를 `https://unpkg.com/...` 이라는
  **절대 https 주소**로 넘긴다. https 는 `file://` 에서도 허용된 스킴이라 잘 불러온다.
- **대신 인터넷이 있어야 한다.** three.js 와 firebase 를 매번 인터넷에서 받아온다.
  인터넷 없는 자리에서는 안 열린다.

서버로 열고 싶으면 (주소창에 `?diag=1` 붙이기 편하다는 것 말고 이점은 없다):

    npx http-server . -p 8080     <- 그 뒤 http://localhost:8080

크롬북과 정반대다. **여기서는 GPU 가 병목이고 논리 쪽은 전부 잡음(±3) 안이다.**
값은 거의 다 픽셀 쪽에서 나온다 — 410만 픽셀마다 텍스처 읽기·블러·그림자 표본. 삼각형은 이 규모에선 공짜다.
전원은 충분하다고 했다(배터리 걱정 없음). 그래도 잴 때 충전기 여부는 같이 적어라 —
내장 GPU 는 배터리에서 클럭을 크게 내린다.

품질 손잡이(`gfx`)는 그 값을 보고 26차에 다시 짰다(로블록스 룩으로 가는 1단계):
`high` 그림자 2048 + MSAA 4, `mid` 그림자 1024, `low` 그림자 없음 · 해상도 0.75.

**33차** — 31차 판 교실 실측이 기준 40(화면 그리기 끔 +21 · 해상도 원본 −17)이라 가운데 칸을 내리고 **기본을 '보통' 으로** 바꿨다:
`high` 선명 = 2048 · MSAA 4 · 1.0, `mid` 보통 = 1024 · MSAA 2 · 0.85 ← 기본, `low` 부드럽게 = 0 · 0 · 0.7.
아이는 **시작 화면의 그래픽 단추**(선명/보통/부드럽게)로 바꾼다 — 고르면 그 기기에 저장되고 다시 열린다.
교실에서 견줄 땐 `?gfx=high` `?gfx=mid` 를 붙여 `?diag=1` + Shift+9 로 잰다(주소가 저장보다 이긴다). 33차부터 세계 면에 결(grain) 텍스처 한 장이 얹혀서 픽셀당 텍스처 읽기가 하나 늘었다 — 이것도 같이 잰다.
33차 교실 실측(보통): 기준 ≈46 · 화면 그리기 끔 +20.5 · **그림자 끔 +11** · 해상도 원본 −7.5 — 다음은 그림자를 싸게 하는 것이다.
33차 뒤: 총 타격감(섬광·시야 펀치·즉시 움찔·충격 고리·막타) · 세계 마무리(흙길·연못·개울·산마루·별·노을) · 무서움의 온도(울음 순서·좌우 팬·입구 쪽 붉은 하늘·보스 땅울림). 노을·붉은 하늘은 **하늘 돔 그림(DataTexture)** 에 칠한다 — 화면을 덮는 반투명 면은 검사기(swiftshader)에서 한 프레임이 초 단위가 된다.
33차 셋 다 머지된 뒤 교실 실측(보통): 기준 ≈40(첫 묶음 뒤 46 에서 −6) · 화면 그리기 끔 +19.5 · 그림자 끔 +2.5 · 해상도 원본 −8. 34차 ①(성능 3차) 후보는 진행상황 33차 끝에 — 해상도 0.75 · heldLight 끄기 · 먼 결 끄기 · 청크 반으로. 하나씩.
**셋 다 해상도 1.0(1707×1067, 픽셀 44%)** 이고 **빛 번짐은 프리셋에서 뺐다**(`?bloom=1` 로만 켜진다).
매끈한 면은 해상도를 내려도 티가 안 나고, MSAA 가 가장자리를 맡는다.
fps 가 60 에서 막히면 진단 화면의 `★GPU실제 ms` 줄로 여유를 본다.

**26차 판을 교실에서 잰 값** (high = 그림자 2048 + MSAA 4, 캔버스 1707×898 — 브라우저 안쪽 높이라 1067 이 아니다):

'해상도 원본' 이 제일 큰 손잡이다 — 픽셀 1M 당 7ms 꼴인데 Lambert+안개 치고 너무 비싸다.
용의자는 MSAA 4(표본 4배 대역폭)·바닥 anisotropy 8·하늘 돔+안개 겹그리기. **`?aa=2` / `?aa=0` 으로 열어 보면 첫째가 갈린다.**
GPU 가 빨라지자 CPU 가 드러났다: 게임 로직 +12, 이름표 +8.5, 캐릭터 갱신 +5.5 (25차c 판 28fps 에서는 잡음 안이었다 —
GPU 가 느리면 CPU 비용은 뒤에 겹쳐서 안 보인다). 그래픽 단계가 끝나면 여기가 다음 자리다.

**교실 견주기 손잡이(26차b)** — 파일을 안 바꾸고 주소 뒤에 붙인다: `?aa=0|2|4` `?pr=0.75|1|1.5` `?shadow=0|1024|2048` `?bloom=1`.
`?gfx=` 와 같이 써도 되고 이쪽이 이긴다. 진단 아랫줄(`AA x4 · 캔버스 1707×898`)로 먹었는지 확인한다.

### 그래도 집에서는 못 잰다

이유는 기계가 느려서가 아니라 **기계가 다르기** 때문이다.
개발 PC 에서 이방성 필터를 −7.7% 로 쟀다가 제대로 재니 −0.1% 였던 전례가 있다.

**그리고 검사기(`깃허브에올릴것/검사/`)로는 애초에 GPU 를 못 잰다.**
검사기는 소프트웨어 렌더링이라 FPS 가 **20에 붙어 있다** — 23차에 가방 성능을 FPS 로 재려다
15분 헛돌고 나서야 알았다. 드로우콜은 **세어서** 알 수 있었지만,
그림자·빛 번짐·채움률은 **세는 수가 없다. 재야만 안다.**

| 집에서 되는 것 | 교실 노트북이 있어야 되는 것 |
|---|---|
| 코드 고치기, 기능 추가 | 고친 게 실제로 빠른지 |
| 버그 잡기 | `?diag=1` + Shift+9 자동 측정 |
| 눈으로 보이는 것 다듬기 (스크린샷) | 그림자·빛 번짐을 켤 수 있는 여유가 얼마인지 |
| 검사 1010항목 (맞고 틀림) | **GPU 를 쓰는 것은 전부 여기서** |

집에서 성능 코드를 고쳐 놓는 건 되지만, **빨라졌다고 판단하지는 마라.**
학교 가서 재고 나서 판단해라. 특히 **GPU 를 쓰는 것은 "돌아간다"와 "쓸 만하다"가 다른 말이다.**

## 6. 아이콘 굽기 시간 — `window.__ICON_MS`

28차부터 3D 아이콘 165장을 페이지가 뜰 때 굽는다. 얼마나 걸렸는지 콘솔에서 `__ICON_MS` 를 치면 나온다
(`n` 장 수 · `make` 조각 만들기 · `render` 그리기 · `read` GPU 에서 한 번 읽기 · `png` 칸마다 PNG · `busy` 합 · `total` 시작부터 끝까지, ms).
검사 판(swiftshader, 한가할 때) 은 busy ≈ 1000ms 이고 그중 read 가 600 이다. **교실 기기에서 한 번 재서 여기에 적어 두자** —
GPU 가 있으면 read 가 몇 ms 일 것이고, 그러면 굽기 전체가 300ms 아래여야 한다. 그보다 훨씬 크면 그래픽 가속이 꺼진 기기다.
굽기는 제목 화면이 한 번 그려진 뒤에 한 덩어리로 돈다(그 사이 아이콘 자리는 빈 그림이었다가 채워진다).

**34차** — 성능 3차. 한 프레임을 뜯어보니(칸마다 그리기 가로채기) 그리기 384 · 삼각형 103만이었고 절반이 그림자 패스, 픽셀은 전부 PBR 이었다.
원색 재질을 **Lambert** 로(보석만 PBR), 그림자 지도는 **15Hz·PCF**, 잔 꾸밈은 그림자 없음, 손 조명(카메라 점광) 끔, 청크 32 → 64, 빈 늑대 조각은 안 그림.

'그림자 매 프레임 · 손 조명 켬 · 결 끔 · 작은 것 그림자 켬' 이 있어 교실에서 넷의 값을 따로 잰다.
