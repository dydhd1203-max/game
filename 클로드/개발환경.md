# 개발 환경 — 컴퓨터를 옮길 때

마지막 갱신: 2026-09-11 (교실 기기가 크롬북 → 노트북으로 바뀜)

이 파일은 "다른 컴퓨터에서 이어서 하려면 뭘 해야 하나"만 다룬다.
작업 내용 자체는 `진행상황.md` 를 봐라.

## 1. 이 저장소는 GitHub 에 올라가 있다

주소: https://github.com/dydhd1203-max/game

전에는 학교 컴퓨터 한 대에만 있었다. 그 컴퓨터가 없으면 작업도 없었다.
이제는 GitHub 에 있으니 아무 컴퓨터에서나 받아서 이어 하면 된다.

**처음 쓰는 컴퓨터에서 (한 번만):**

    git clone https://github.com/dydhd1203-max/game.git
    cd game

**그 다음부터는 — 이 두 줄이 전부다:**

    git pull            <- 시작할 때. 다른 데서 한 작업을 받아온다
    git add -A && git commit -m "무엇을 고쳤는지" && git push
                        <- 끝낼 때. 지금 작업을 올린다

**컴퓨터를 옮기기 전에 `git push` 를 꼭 하고 자리를 떠라.**
안 하면 그 컴퓨터에만 남는다. 이번에 겪은 게 딱 그거였다.

## 2. 게임 실행하는 법

**`index.html` 을 그냥 더블클릭하면 된다.** 로컬 서버 필요 없다.

- 이건 실제로 확인한 사실이다. `type="module"` 스크립트가 있으면 보통
  `file://` 에서 막히는데, 그건 **모듈이 옆에 있는 로컬 파일을 부를 때** 얘기다.
  이 게임의 importmap 은 `three` 를 `https://unpkg.com/...` 이라는
  **절대 https 주소**로 넘긴다. https 는 `file://` 에서도 허용된 스킴이라 잘 불러온다.
- **대신 인터넷이 있어야 한다.** three.js 와 firebase 를 매번 인터넷에서 받아온다.
  인터넷 없는 자리에서는 안 열린다.

서버로 열고 싶으면 (주소창에 `?diag=1` 붙이기 편하다는 것 말고 이점은 없다):

    npx http-server . -p 8080     <- 그 뒤 http://localhost:8080

## 3. 성능 측정은 교실 기기에서만 된다 ← 제일 중요

### ⚠️ 교실 기기가 바뀌었다 (25차)

크롬북이 아니라 **스물한 대가 다 같은 노트북**이다. 이게 무엇을 바꾸는지부터:

| | 크롬북 (1차~24차) | 지금 노트북 (LG gram · 내장그래픽) |
|---|---|---|
| 그림자 맵 | 안 건드렸다 (드로우콜 2배가 무서워서) | 가능 |
| 빛 번짐(후처리) | 안 건드렸다 (전체 화면 여러 패스) | 가능 |
| 화면 크기 | 1280×632 | **1920×1200 이상 — 픽셀이 2.2배** |
| 스물한 대가 제각각? | — | **아니다. 전부 같은 기종이다** |

**⚠️ 한 가지 바로잡을 것 — 크롬북에서도 GPU 는 범인이 아니었다.**
이 파일과 CLAUDE.md 가 오랫동안 "드로우콜이 족쇄" 라는 투로 쓰여 있었는데, 그건 계산이고
**교실에서 잰 값은 아래와 같다**(`진행상황.md` 맨 앞, 짝비교, 30fps → 33~35fps):

| 껐을 때 | 차이 |
|---|---|
| 해상도 0.55까지 내림 | +3 (0.85와 같다 → 픽셀 문제 아님) |
| 지형 전체 숨김 | 0 (→ 삼각형 문제 아님) |
| **화면 그리기 전체** | **+3** ← 아예 안 그려도 이것뿐 |
| **게임 로직 전체** | **+21** ← 여기 하나에 다 있었다 |

진짜 병목은 rAF 콜백 **바깥**의 약 10.4ms 였다(HUD 의 DOM 배치·그리기, GPU 업로드, 쓰레기 수거 의심).
**그러니 기기가 좋아졌을 때 조심할 자리도 GPU 가 아니라 CPU·DOM 쪽이다.**
다만 gram 은 화면이 훨씬 커서 **채움률이 처음으로 비용이 될 수 있다** — 빛 번짐을 넣으면 특히.
이건 아직 안 잰 것이니 교실에서 재고 나서 적어라.

**`진행상황.md` 의 옛 성능 표는 그때 기계의 기록이다.** 오늘 숫자와 비교하지 마라 —
16차에 옛 기록의 "2/5" 와 비교했다가 판단이 어긋날 뻔한 것과 같은 함정이다.

### 그래도 집에서는 못 잰다

이유는 기계가 느려서가 아니라 **기계가 다르기** 때문이다.
개발 PC 에서 이방성 필터를 −7.7% 로 쟀다가 제대로 재니 −0.1% 였던 전례가 있다.

**그리고 검사기(`깃허브에올릴것/검사/`)로는 애초에 GPU 를 못 잰다.**
검사기는 소프트웨어 렌더링이라 FPS 가 **20에 붙어 있다** — 23차에 가방 성능을 FPS 로 재려다
15분 헛돌고 나서야 알았다. 드로우콜은 **세어서** 알 수 있었지만,
그림자·빛 번짐·채움률은 **세는 수가 없다. 재야만 안다.**

| 집에서 되는 것 | 교실 노트북이 있어야 되는 것 |
|---|---|
| 코드 고치기, 기능 추가 | 고친 게 실제로 빠른지 |
| 버그 잡기 | `?diag=1` + Shift+9 자동 측정 |
| 눈으로 보이는 것 다듬기 (스크린샷) | 그림자·빛 번짐을 켤 수 있는 여유가 얼마인지 |
| 검사 1010항목 (맞고 틀림) | **GPU 를 쓰는 것은 전부 여기서** |

집에서 성능 코드를 고쳐 놓는 건 되지만, **빨라졌다고 판단하지는 마라.**
학교 가서 재고 나서 판단해라. 특히 **GPU 를 쓰는 것은 "돌아간다"와 "쓸 만하다"가 다른 말이다.**

## 3.5 이 저장소에는 게임이 둘 있다

| 폴더 | 게임 | 배포 |
|---|---|---|
| `index.html` + `배포용/` | 양들의 밤 (3D) | `배포용/` 폴더를 드래그 |
| `퀴즈게임/` | 퀴즈나라 (퀴즈 + 아바타 꾸미기) | `퀴즈게임/` 폴더를 **다른 넷리파이 사이트**에 드래그 |

퀴즈나라 쓰는 법은 `퀴즈나라-사용법.md` 에 따로 적어 뒀다.
파이어베이스는 같은 걸 써도 된다 — 양들의 밤은 `sheepnight` 아래, 퀴즈나라는 `quiz` 아래에 쓴다.

퀴즈나라는 **파일이 한 개다.** 아래 4번에서 말하는 "양쪽을 손으로 맞추는" 문제가 없다.

> ⚠️ **퀴즈나라 파일은 저장소에 딱 한 벌만 둔다 — `퀴즈게임/index.html`.**
> 전에 압축을 푼 사본이 `클로드/퀴즈나라/` 에 같이 올라가 있어서, 넷리파이에
> 옛 사본을 잘못 올릴 뻔했다. 사본은 지웠다.
> 새 버전을 받으면 **`퀴즈게임/` 안의 파일을 덮어쓰고**, 사본을 따로 만들지 마라.

## 4. 배포

`배포용/` 폴더를 Netlify Deploys 탭에 드래그앤드롭.

`배포용/index.html` 은 맨 위 `index.html` 과 **글자 하나까지 똑같다.**
지금은 고칠 때마다 손으로 양쪽을 맞추고 있다. 한쪽만 고치고 배포하면
고친 게 반영이 안 되니 조심해라. (언젠가 한 파일만 두도록 정리하면 좋다)

## 5. 알아 둘 것

- `index.html` 안에 `TEACHER_CODE` 와 Firebase 설정이 그대로 들어 있다.
  이 저장소는 공개(public)라서 누구나 볼 수 있고, 사실 Netlify 에 올린 게임에서
  소스 보기(Ctrl+U)를 눌러도 원래 다 보인다. 클라이언트 파일에 있는 값은
  비밀이 될 수 없다. 애들이 알면 곤란한 값이면 그 방식 자체를 바꿔야 한다.
  (Firebase `apiKey` 는 원래 공개되는 식별자라 노출돼도 정상이다)
- 백업 파일(`index.backup-*.html`)은 이제 git 이 안 올린다(`.gitignore`).
  옛날 버전은 `git log --oneline` 으로 찾아서
  `git show <번호>:index.html > 옛날.html` 로 꺼내면 된다.
